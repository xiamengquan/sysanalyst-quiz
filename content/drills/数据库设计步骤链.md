# 演练 · 数据库设计步骤链

> **域**：数据库
> **情境**：数据库设计是案例必考步骤链——「分几个阶段？每阶段产出什么？概念设计与逻辑设计的差异？」。练法：每格先默写「阶段名 + 产出物」，再对照范例句与辨析。

## 1 · 需求分析
- **问**：数据库设计第一步做什么？产出物是什么？
- **要点**：数据需求 / 处理需求 / 数据流图 / 数据字典 / 需求说明书
- **范例**：首先进行需求分析：调查清楚用户的数据需求与处理需求，用数据流图与数据字典加以描述，形成需求规格说明书，作为后续设计的基础。
- **作用**：一句话——确定「要存什么数据、数据怎么流动」，是全部设计阶段的输入。
- **辨析**：与概念设计——需求分析回答「用户要什么」，概念设计回答「数据本身长什么样」；产出物是数据字典而非 ER 图。
- **易错**：把 ER 图当作需求分析的产出——ER 图属于概念结构设计阶段。
- **溯源**：points/kp-3-4.md

## 2 · 概念结构设计
- **问**：概念结构设计的任务与产出是什么？常出现哪三类冲突？
- **要点**：ER 图 / 局部 / 集成 / 属性冲突 / 命名冲突 / 结构冲突
- **范例**：第二步进行概念结构设计：先分局部建立局部 ER 图，再集成全局 ER 图，消解属性冲突、命名冲突与结构冲突，形成与 DBMS 无关的全局概念模型。
- **作用**：一句话——把现实世界抽象成与数据库产品无关的 ER 模型，是需求到实现的桥梁。
- **辨析**：与逻辑设计——概念设计面向现实世界、与 DBMS 无关，产出 ER 图；逻辑设计面向 DBMS、产出关系模式。三类冲突：属性冲突（类型/取值单位不一致）、命名冲突（同名异义/异名同义）、结构冲突（实体抽象口径不一致）。
- **易错**：漏写「与 DBMS 无关」这一特征；三类冲突只答得出两类。
- **溯源**：points/kp-3-4.md

## 3 · 逻辑结构设计
- **问**：逻辑结构设计阶段做什么？范式检查在哪一步？
- **要点**：关系模式 / ER 转换 / 规范化 / 函数依赖 / 模式优化
- **范例**：第三步进行逻辑结构设计：按转换规则把全局 ER 图转换为关系模式，依据函数依赖做范式检查与分解（一般达到 3NF/BCNF），再结合处理需求对模式进行优化与外模式设计。
- **作用**：一句话——把 ER 图落成具体 DBMS 支持的关系模式，并消除冗余与异常。
- **辨析**：与概念设计——本阶段产物是关系模式而非 ER 图；规范化不是越高越好，要到 3NF/BCNF 后权衡查询性能（反规范化是有意为之的优化手段）。
- **易错**：只写「转关系模式」漏掉范式检查与优化；把反规范化当成错误答案——案例中考「适当冗余换性能」。
- **溯源**：points/kp-3-4.md

## 4 · 物理结构设计
- **问**：物理设计阶段解决什么问题？典型手段有哪些？
- **要点**：存取方法 / 存储结构 / 索引 / 聚簇 / 评价
- **范例**：第四步进行物理结构设计：为关系模式选择存取方法（建立索引、聚簇）与存储结构，估算存储空间，并对方案进行性能评价，满足吞吐与响应时间要求。
- **作用**：一句话——决定数据「怎么存、怎么取」，直接影响查询性能。
- **辨析**：与逻辑设计——逻辑设计关心「表结构对不对」，物理设计关心「存取快不快」；索引属于物理设计手段，不是模式修改。
- **易错**：把建立索引写到逻辑设计阶段；聚簇与索引的作用对象混淆。
- **溯源**：points/kp-3-4.md

## 5 · 数据库实施
- **问**：实施阶段包含哪些工作？
- **要点**：建库 / 数据装载 / 试运行 / 应用程序 / 调试
- **范例**：第五步进行数据库实施：依据物理设计建立数据库，编写应用程序，组织数据装载，进行联调与试运行，记录并解决暴露的性能与功能问题。
- **作用**：一句话——把设计蓝图变成可运行的系统，试运行暴露设计缺陷。
- **辨析**：与运行维护——实施阶段系统尚未正式交付，试运行发现问题可能回溯修改设计；运维阶段系统已交付，重点是保障与调优。
- **易错**：漏「试运行」；实施与运维阶段边界写混。
- **溯源**：points/kp-3-4.md

## 6 · 运行与维护
- **问**：数据库进入运行维护期，主要工作是什么？
- **要点**：备份恢复 / 安全性完整性 / 性能监控 / 重组 / 重构
- **范例**：最后进行运行与维护：定期备份与故障恢复，维护安全性与完整性控制，持续性能监控与调整，必要时对数据库进行重组或重构以适应需求变化。
- **作用**：一句话——保障系统长期稳定，重组保性能、重构应变更。
- **辨析**：重组 vs 重构——重组不改变逻辑结构（空间碎片整理、统计刷新），重构因需求变化改变模式。
- **易错**：重组与重构混淆；漏备份恢复这类保底项。
- **溯源**：points/kp-3-4.md
