# 案例081 · Web · 分析改进

> track: P0 · depth: deep

## 题干

某连锁零售企业拟建设/优化信息系统。背景：B2B订货门户对接多家供应商，要求接口可审计、可重试，库存变更需近实时可见。
**现状：**当前将计价、库存、促销规则分别硬编码在小程序与Web两套前端，促销时出现价格不一致；峰值时直接打满ERP连接池。业务方要求尽快止血，同时保留可演进空间，改进须可验证、可回滚。
你作为分析设计组核心成员参与方案论证。
补充约束：前端多端（Web/小程序）共用同一套计价与库存视图；大促出现缓存击穿与恶意穿透风险；不允许长时间停机；需可灰度回滚。

## 问题

**问题1** 指出当前方案存在的主要问题（不少于3点，须能从题干现状推出）。

**问题2** 提出改进措施，并说明每条措施对应解决上述哪个问题。

**问题3** 给出验证/测试或运维监控指标建议（不少于3个可观测指标）。

## 参考作答要点（非唯一答案）

**问题1要点：** 对比/分层须点名：接入层（CDN/网关限流）、BFF、缓存（击穿/穿透对策）、业务、ERP 适配；职责不重叠。

**问题2要点：** 措施具体：布隆过滤防穿透、互斥/逻辑过期防击穿、Write-Through/Behind 取舍、灰度回滚；每条对应题干痛点。

**问题3要点：** 风险：最终一致→对账幂等；缓存雪崩→限流降级；双端规则分裂→中台统一；给监控指标。

**领域提示：** Web · P0 加深：大促缓存与多端统一；答题回扣题干约束。
