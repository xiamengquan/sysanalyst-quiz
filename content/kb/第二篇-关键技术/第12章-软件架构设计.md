## 二、架构概述

**定义**：构件 + 连接件 + 集成模式及约束；指定组织结构与拓扑，显示需求与构件对应关系。

**架构九大意义**（常考）：
1. 干系人交流手段
2. 早期设计决策体现
3. 明确实现约束
4. 决定开发维护组织结构
5. **制约质量属性**
6. 使推理和控制更改更简单（局部/非局部/架构级变更）
7. 支持渐进原型
8. 培训基础
9. 可传递可复用模型

**架构发展史四阶段**：无架构 → 萌芽（DFD/控制流图）→ 初级（UML）→ 高级（4+1）。

## 三、架构建模

### 3.1 五种模型

结构模型、框架模型、动态模型、过程模型、功能模型。  
**最常用**：结构 + 动态。

### 3.2 4+1 视图

| 视图 | 关注 | 受众 |
|-----|------|------|
| **逻辑视图** | 功能需求 | 最终用户 |
| **开发视图**（实现/模块） | 软件组织管理 | 编程人员 |
| **进程视图** | 性能、并发、分布 | 系统集成人员 |
| **物理视图**（部署） | 拓扑、安装、通信 | 系统工程人员 |
| **场景**（用例） | 串联四视图 | 所有人 |

**静态**：逻辑 + 开发；**动态**：进程 + 物理。  
MIS 侧重逻辑/开发；实时系统侧重进程/物理。

## 四、软件架构风格（核心）

**定义**：特定领域系统组织方式的惯用模式 = 词汇表 + 约束。

### 4.1 数据流风格

| 风格 | 特点 | 典型 |
|-----|------|------|
| **批处理** | 成批处理，顺序执行，无交互 | 传统文件批处理 |
| **管道-过滤器** | 过滤器 + 管道；数据流驱动 | Unix 管道、编译器 |

### 4.2 调用/返回风格

| 风格 | 特点 |
|-----|------|
| **主程序/子程序** | 单线程控制 |
| **面向对象** | 对象 + 方法调用 |
| **层次结构** | 层间调用，上层依赖下层 |
| **C/S** | 资源不对等、共享；二层或三层 |
| **B/S** | 三层 C/S 的实现，浏览器客户端 |

**二层 C/S 缺点**：开发成本高、客户端复杂、界面不一、移植难、维护升级难、扩展性差、安全性难保证。

**三层 C/S 优点**：
- 逻辑相对独立
- 灵活选平台
- 并行开发、多语言
- 功能层隔离表示与数据

**B/S 不足**：动态页面支持弱、安全性较 C/S 低、交互性不强。

### 4.3 以数据为中心

| 风格 | 特点 |
|-----|------|
| **仓库（数据库）** | 中央数据存储，独立构件通过仓库交互 |
| **黑板** | 知识源 + 黑板 + 控制；适合复杂非结构化问题（信号处理、AI） |

### 4.4 虚拟机风格

| 风格 | 特点 |
|-----|------|
| **解释器** | 内置虚拟机，弥合语义差异 |
| **规则系统** | 规则引擎驱动 |
| **复用系统** | 程序指令级复用 |

### 4.5 独立构件风格

| 风格 | 特点 |
|-----|------|
| **进程通信** | 构件独立，显式消息传递 |
| **事件系统** | 隐式事件通知，松耦合 |

### 4.6 面向服务 SOA

**要点**：功能定义为独立服务；松散耦合；三角色=提供者/请求者/注册中心。

**关键技术**：UDDI（注册）、SOAP（消息：Envelope/Header/Body）、WSDL（描述）、REST（无状态资源操作）。

**ESB**：标准化通信总线；非侵入集成遗留系统；消息转换与路由。

## 五、架构实现与质量属性

**ABSD 六子过程**：需求 → 设计 → 文档化 → 复审 → 实现 → 演化。

**变更三类**：局部 / 非局部 / **架构级**（改部分关系或整个系统）。

**质量属性场景六要素**：刺激源→刺激→环境→制品→响应→响应度量。

**开发期属性**：易理解、可扩展、可重用、可测试、可维护、可移植。  
**运行期属性**：性能、安全、可伸缩、互操作、可靠、可用、健壮。

**可修改性** vs **可变性**：快速高性价比变更 vs 扩充成为新架构的能力。

## 六、第12章易混对比

| 对比 | 要点 |
|-----|------|
| 批处理 vs 管道-过滤器 | 整体成批 vs 流式逐段处理 |
| 仓库 vs 黑板 | 共享数据 vs 知识源协作求解 |
| 二层 vs 三层 C/S | 表示+数据 vs 表示+功能+数据 |
| C/S vs B/S | 胖客户端 vs 浏览器 |
| 解释器 vs 规则系统 | 虚拟机解析 vs 规则匹配 |
| 进程通信 vs 事件系统 | 显式消息 vs 隐式事件 |
| SOA vs 微服务 | 服务粒度、治理方式不同（微服务见第20章） |
| 可修改性 vs 可变性 | 改现有 vs 变成新架构 |

## 应试钩子

**案例可能怎么问**：给定场景选架构风格（管道-过滤器/仓库/黑板/C-S/B-S/SOA 等）并说明权衡；ESB 集成遗留系统时答「非侵入、消息转换、服务注册」；质量属性场景六要素填空或补响应度量。

**论文怎么用**：ABSD、面向服务/SOA（20下、24上）——写「需求→架构风格选型→4+1 视图/关键决策→质量属性场景验证→演化」；与微服务对比时强调粒度、治理与集成方式差异。
