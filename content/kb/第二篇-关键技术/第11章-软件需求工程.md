## 二、核心知识点

### 2.1 需求定义与层次

**软件需求**：用户对新系统在功能、行为、性能、设计约束等方面的期望。

**三层需求**：

| 层次 | 来源/内容 | 作用 |
|-----|----------|------|
| **业务需求** | 投资人、客户、管理层 | 项目视图与范围 |
| **用户需求** | 用户具体目标与任务 | 用户能做什么 |
| **系统需求** | 功能 + 非功能 + 设计约束 | 开发人员实现依据 |

### 2.2 质量功能部署 QFD

| 类型 | 含义 | 未满足后果 |
|-----|------|-----------|
| **常规需求** | 用户明确期望的功能/性能 | 实现越多越满意 |
| **期望需求** | 用户认为理所当然但未说清 | 未实现 → 不满意 |
| **意外需求（兴奋需求）** | 范围外但开发者可赋予的特性 | 未实现不影响购买；实现则更高兴 |

### 2.3 FURPS+ 分类

| FURPS | 内容 |
|-------|------|
| F 功能性 | 特性、功能、安全性 |
| U 可用性 | 人性化、帮助、文档 |
| R 可靠性 | 故障频率、可恢复性、可预测性 |
| P 性能 | 响应时间、吞吐量、准确性、资源利用率 |
| S 可支持性 | 适应性、可维护性、国际化、可配置性 |

**“+”辅助因素**：实现、接口、操作、包装、授权。

### 2.4 好需求特性（IEEE）

- **单条需求**：正确、无歧义、可检验、可跟踪
- **需求集合**：完整、一致、可修改
- **高品质**：正确性、完整性、一致性、明确性、可验证性、优先级排序、可修改性、可追溯性、可理解性

### 2.5 需求工程

**两大工作**：需求开发 + 需求管理。

**需求开发四阶段**：
1. 需求获取
2. 需求分析
3. 需求定义（文档化）→ 用户原始需求说明书 + 软件需求规格说明
4. 需求验证

**需求管理**：需求基线、变更控制、**需求跟踪**。

**需求工程五活动**（含管理）：获取 → 分析 → 规格 → 确认验证 → 管理。

**需求基线**：评审批准后的需求约定，是开发与管理的桥梁。

## 三、需求获取方法（要点）

| 方法 | 要点 |
|-----|------|
| 用户访谈 | 结构化/非结构化结合；准备→主持→后续 |

| JRP/JAD | 短期达成一致；严格议程、避免术语 |

## 四、结构化分析（DFD / STD / 数据字典）

> **由简入深**：`速查/结构化与面向对象分析-体系化学习路径.md`（L0–L2）；刷题路径选「结构化与OO分析（L0→L4）」。

### 5.1 DFD 在需求阶段的三作用

1. 理解表达用户需求
2. 概括内部逻辑，是设计基础
3. 存档材料，修改开发计划依据

### 5.2 DFD 绘制步骤

1. 画系统输入输出（边缘标出）
2. 画内部，从输入连接处理
3. 为每个数据流命名（避免空洞词）
4. 为加工命名（**动宾短语**）
5. 逐层分解

### 5.3 状态转换图 STD

- 描述系统状态及状态间转换
- **初态**：实心圆；**终态**：双同心圆（内实心）
- 可表示循环过程或单程生命期

### 5.4 数据字典六类条目

| 条目 | 要点 |
|-----|------|
| 数据元素 | 最小单位，类型/长度/取值 |
| 数据结构 | 组合关系；[] 任选、{} 必选、* 重复 |
| 数据流 | 来源、去处、组成、流通量 |
| 数据存储 | 结构、数据流、查询要求 |
| 加工逻辑 | 编号、名称、I/O；可用判定树/表/结构化语言 |
| 外部实体 | 名称、I/O 数据流、数量 |

**四作用**：列表、相互参照、内容检索、一致性检验。专人（数据管理员）维护。

## 五、面向对象需求与需求管理

> **由简入深**：`速查/结构化与面向对象分析-体系化学习路径.md`（L3–L4）；用例符号见 `速查/UML-体系化学习指南.md`。

### 6.1 用例模型

> 用例图符号、include/extend、案例填空见：`速查/UML-体系化学习指南.md` · L2.1。

**元素**：参与者、用例、通信关联（箭头表示主动方）。

**构建四阶段**：识别参与者 → 合并需求获用例 → 细化描述 → 调整模型。

**参与者类型**：人、其他系统、硬件设备、时钟。

**用例命名**：动词(短语)+名词(短语)；宜编号便于**需求跟踪**。

**注意**：
- 不混淆用例与用例内步骤
- 区分**业务用例** vs **系统用例**

**用例规约**：名称、说明、主/备选事件流、非功能需求、前置/后置条件。

**需求管理**：变更控制（CCB 审批）+ **需求跟踪矩阵**（需求↔设计↔代码↔测试；正向/反向跟踪）。
