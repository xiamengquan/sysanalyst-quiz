## 要点

### 一、场景特征

**定义**：用户界面驻留于 Web 浏览器（或支持 Web 技术的可视化界面）的应用程序，基于 Web 技术与 W3C 标准，通过 HTTP 等协议提供内容与服务。

**典型场景**：
- 电子商务（购物车、支付、供应链集成）
- 企业门户、SaaS 服务、社交网络
- 从小规模工具到 Internet/Intranet/Extranet 大规模分布式应用

**Web 应用核心优势**（案例可列举）：
| 特征 | 说明 |
|------|------|
| 易于访问 | 任意浏览器、多设备，无需安装客户端 |
| 开发高效 | 单代码库多平台，开发周期短 |
| 使用简单 | 自动更新，用户无维护负担 |
| 扩展性强 | 按需增用户，数据多存云端 |

**新式 Web 应用特征**（与案例架构选型相关）：
1. **云托管与可扩展性**：低内存、高吞吐，容器/微服务友好
2. **跨平台**：Linux/macOS/Windows，Docker 部署
3. **自动化测试**：脚本模拟用户操作，可重复、可回归
4. **传统应用 + SPA 并存**：服务端渲染 MVC vs 客户端 SPA（Blazor WebAssembly 等）
5. **CI/CD 友好**：Azure DevOps、GitHub Actions 等持续交付

**两种构建方式**：
- **传统 Web 应用**：大部分逻辑在服务器，每次操作完整页面重载
- **SPA**：静态 HTML 初始化 + JavaScript + Web API，极少服务端页面加载

## 易混辨析

| 对比 | 区别 |
|-----|------|
| **传统 Web vs SPA** | 传统 Web 每次操作多完整页面重载、逻辑主要在服务端；SPA 初始化后由 JavaScript 调用 API、极少整页刷新，交互更流畅。 |
