## 概述

**系统维护**：关系： - MTBF ↑ → 可靠性 ↑ - MTTR ↓ → 修复能力 ↑ - MTBF 不含计划内维护停机。

## 定义

- **系统维护**是软件上线后为修正缺陷、适应环境、完善功能与预防问题而修改软件的过程；**用于**全生命周期价值（四类维护）。
- 评价流程：确定对象→收集资料→实施评价→复核报送。指标驱动：效率/能力/效果/效益。

## 二、运维技术指标

| 指标 | 全称 | 含义 | 公式 |
|-----|------|------|------|
| **MTTR** | 平均故障修复/恢复时间 | 故障到恢复正常平均时间 | 修复总时间/故障次数 |
| **MTBF** | 平均故障间隔时间 | 两次故障间平均运行时间；**越大越可靠** | 总运行时间/故障总数 |
| **MTTF** | 平均无故障时间 | 不可修复部件从开始到失效；衡量寿命 | 正常运行总时间/故障总数 |
| **MTTA** | 平均应答时间 | 告警到确认的平均时间 | 应答累计时间/事件总数 |

**关系**：
- MTBF ↑ → 可靠性 ↑
- MTTR ↓ → 修复能力 ↑
- MTBF 不含计划内维护停机

**系统运行管理**：用户管理、网络资源管理、软件资源管理。

**网络管理五功能**：性能、故障、配置、计费、安全。

**身份认证四种**：用户名密码、IC 卡、动态密码、USB Key。

## 三、系统故障管理

**故障类型**：计划维护、应用性、人为操作、系统软件、硬件、相关设备、灾难灾害。

**故障处理流程**：监视 → 调查 → 排查恢复 → 收尾。

## 四、软件维护（重点）

### 4.1 维护占比

运行维护占生命周期 **60%–80%**。

### 4.2 维护四类（必背）

| 类型 | 触发原因 | 示例 |
|-----|---------|------|
| **改正性维护** | 识别纠正错误、缺陷、误用 | Bug 修复 |
| **适应性维护** | 外部环境变化（软硬件、数据环境） | 换操作系统、数据库升级 |
| **完善性维护** | 用户新功能与性能要求 | 新增报表、优化功能 |
| **预防性维护** | 提高可维护性、可靠性 | “用今天方法改昨天系统满足明天需要” |

**统计**：完善性维护通常占比最大。

### 4.3 维护管理

维护申请→审批→计划→实施→验收→更新配置库。完善性维护通常占比最大。

## 六、遗留系统处置（重点）

### 6.1 遗留系统特征

- 不能满足全部要求
- 性能落后、技术过时
- 大型、难维护
- 缺乏文档

### 6.2 评价活动

启动评价 → 业务价值评价 → 外部环境评价（硬件/支撑软件/IT 基础设施）→ 应用软件评价 → 分析结果。

**综合技术水平**：
```
OR = (P₁×ORH + P₂×ORS + P₃×OAF + P₄×ORA) / 4
```

### 6.3 四象限演化策略（必考）

```
        高业务价值
            │
  改造      │      集成
 (高技高值) │ (高技低值)
────────────┼──────────── 高技术水平
  淘汰      │      继承
 (低技低值) │ (低技高值)
            │
        低业务价值
```

| 象限 | 策略 | 说明 |
|-----|------|------|
| 第一象限 高技高值 | **改造** | 功能增强 + 数据模型改造 |
| 第二象限 高技低值 | **集成** | 企业应用集成，消除孤岛 |
| 第三象限 低技低值 | **淘汰** | 全面重新开发；可借鉴旧系统降风险 |
| 第四象限 低技高值 | **继承** | 新系统兼容旧功能/数据模型；需并行运行 |

## 七、新旧系统转换（重点）

### 7.1 转换前准备

数据准备、文档准备、人员培训、设备安装、**系统试运行**。

### 7.2 三种转换策略

| 策略 | 做法 | 优点 | 缺点 | 适用 |
|-----|------|------|------|------|
| **直接转换** | 旧停新立，无过渡 | 人力费用最省 | 风险高，无回退 | 新系统简单或旧系统完全不可用 |
| **并行转换** | 新旧同时运行，结果核对 | 风险小，可培训比较 | 双套班子，周期长，数据难控 | 大型、复杂、数据重要系统（最常用） |
| **分段转换** | 分期分批逐步切换 | 震动小，费用适中 | 周期长，需新旧接口 | 大系统、风险大（订票、银行） |

**分段转换三种方式**：
1. 按**功能**分阶段
2. 按**部门**分阶段
3. 按**机器设备**分阶段

**并行转换实施**：以旧系统为正式作业，新系统结果作核对；验证后旧系统退出。

### 7.3 数据转换与迁移

**原则**：**数据不丢失**。

**三种方法**：
1. **切换前工具迁移**（ETL，最主要）：一次迁移 vs 分次迁移
2. **切换前手工录入**：新旧结构差异大、期初数据无法从历史获得
3. **切换后新系统生成**：根据已迁移数据生成结果数据

**迁移三阶段**：准备→抽取/转换/装载→校验（完整性、一致性、总分平衡）。

## 八、第15章易混对比

| 对比 | 区别 |
|-----|------|
| 改正 vs 完善性维护 | 修错 vs 增功能 |
| 适应 vs 预防性维护 | 适应环境 vs 主动改进可维护性 |
| 改造 vs 继承 | 高技术可改 vs 低技术但高价值需兼容 |
| 淘汰 vs 集成 | 低价值重建 vs 高技低值互联 |
| 直接 vs 并行转换 | 一刀切 vs 双轨核对 |
| 并行 vs 分段 | 全系统双轨 vs 子集渐进 |
| MTBF vs MTTR | 间隔越长越好 vs 修复越短越好 |
| 一次 vs 分次数据迁移 | 短、风险低 vs 解决数据量大与宕机矛盾 |
