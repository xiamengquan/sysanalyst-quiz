# 架构（原则、模式）

> **大纲**：20.2 · **教程**：第20章 · **分组**：科目2 · 5. 微服务系统分析与设计 · **状态**：工坊精修 v1.2.8 · 审计通过

## 概述

**架构（原则、模式）** 属本科目大纲考点。常考：**定义**  ·  全部功能集中于单一部署单元  ·  以独立服务为单位、通过标准接口实现跨系统集成的架构思想  ·  SOA 的细粒度实现，强调小服务、独立 DB、去中心化集成。

## 定义

- **单一职责原则（答卷）**：单一职责原则是指每个微服务只围绕一项明确的业务能力构建；**用于**控制服务边界，避免「大而全」服务带来的耦合与发布风险。
- **隔离性原则（答卷）**：隔离性原则是指各服务以独立进程运行并拥有自己的数据存储，常用容器封装；**用于**故障隔离，防止单服务异常拖垮整个系统。
- **自治性原则（答卷）**：自治性原则是指每个服务拥有独立的生命周期，可独立开发、测试、部署与演化；**用于**提升团队并行效率与发布频率。
- **弹性原则（答卷）**：弹性原则是指系统具备自动扩缩容与故障转移能力；**用于**应对流量波动，保障高可用。
- **可观察性原则（答卷）**：可观察性原则是指通过日志、指标与分布式链路追踪等手段掌握系统运行状态；**用于**快速定位分布式环境下的故障与性能瓶颈。
- **可测试性原则（答卷）**：可测试性原则是指各服务须支持单元测试、集成测试与契约测试，并纳入 CI/CD 流水线；**用于**在频繁独立发布下仍保障质量。
- **可维护性原则（答卷）**：可维护性原则是指服务对外暴露标准 API（如 REST/OpenAPI）并实施版本控制；**用于**降低服务间协作成本，支持平滑升级。
- **安全性原则（答卷）**：安全性原则是指服务间通信加密（TLS）、身份认证（OAuth2/JWT）与访问控制（RBAC）；**用于**保障分布式环境下的数据与接口安全。
- **智能端点 + 简单消息原则（答卷）**：智能端点 + 简单消息原则是指业务逻辑放在服务端点、消息通道保持轻量简单，以去中心化方式集成；**用于**替代 ESB 重度编排，降低集成中间件单点风险。

## 要点

### 2.1 九大架构原则

| 原则 | 要点 |
|------|------|
| 单一职责 | 一服务一业务域 |
| 隔离性 | 独立进程+独立 DB，容器封装 |
| 自治性 | 独立生命周期，组件化 |
| 弹性 | 自动扩缩容、容错转移 |
| 可观察性 | 日志、指标、链路追踪 |
| 可测试性 | 单元/集成/契约测试、CI/CD |
| 可维护性 | 标准 API（REST/OpenAPI）、版本控制 |
| 安全性 | TLS、OAuth2、JWT、RBAC |
| 智能端点+简单消息 | 去中心化集成，异步消息 |

## 易混辨析

| 对比 | 区别 |
|-----|------|
| **SOA vs ESB** | SOA 是架构思想（服务化、松耦合）；ESB 是实现 SOA 的集成中间件，提供路由、转换与编排，但可能成为性能瓶颈与单点。 |

- 「说明从单体迁移微服务的理由与拆分原则」→ 写单体痛点 + 单一职责/隔离性/有界上下文等原则答卷句。

- 「跨服务下单如何保证一致性？」→ Saga + 最终一致性，说明补偿机制；避免简单写 2PC。
- 「如何保障微服务可观测与容错？」→ 日志/指标/链路追踪 + 熔断/限流/降级。
- 背景：电商/金融后台单体瓶颈（发布慢、扩展难、技术栈锁定）。
- 方案：按业务能力拆分 + 容器编排 + API 网关 + 注册发现 + 消息队列；一致性写 Saga。
- 成效：独立发布频率、故障隔离、弹性伸缩、团队并行度等可量化指标。
