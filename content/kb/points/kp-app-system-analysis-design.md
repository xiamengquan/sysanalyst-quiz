**应用系统分析与设计**：论述题建议：项目背景 → 与本专题相关的分析与设计决策 → 效果与不足（对齐第22章三问式结构）。

## 速懂

- **一句话**：应用系统分析与设计是在业务需求基础上完成逻辑建模、架构与详细设计以指导实现的活动。
- **考什么**：概念辨析、场景决策与案例回扣。
- **具体理解**：
  - 「请说明 Web 应用架构设计应遵循的核心原则（至少 2 个）」→ 直接誊写 §2.1 八大原则答卷句。
  - 「对比 MVC 与 MVP / 传统 Web 与 SPA / 整体式与微服务」→ 用 §五 易混对比表展开。
  - 「如何提升 Web 应用性能？」→ 负载均衡 + 连接池 + 缓存（含 CDN）三板斧，各写定义+作用。
  - 「多端（Web/小程序）如何统一业务规则？」→ 前后端分离 + BFF 或统一领域服务，避免双端两套逻辑。
- **别搞混**：题干锚词：**应用系统分析与设计**。

## 定义

- **应用系统分析与设计**：是在业务需求基础上完成逻辑建模、架构与详细设计以指导实现的活动。**作用**：用于衔接需求工程与编码测试（结构化/OO 双路线）。
- **结构化分析设计**：是以 DFD/数据字典/SC 图为主。**作用**：用于数据流驱动、过程型系统。
- **面向对象分析设计**：是以用例、类图、交互图为主。**作用**：用于复杂业务对象建模与复用。
- **设计评审**：是对架构与详细设计进行同行审查。**作用**：用于缺陷早移与变更控制。
