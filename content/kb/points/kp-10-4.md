# 架构标准

> **大纲**：12.4 · **教程**：第12章 · **分组**：科目1 · 10. 软件架构设计 · **状态**：工坊精修 v1.3.1 · 审计通过

## 概述

**架构标准**：二层 C/S 缺点：开发成本高、客户端复杂、界面不一、移植难、维护升级难、扩展性差、安全性难保证。

## 定义

- **C/S 架构**：是客户端与服务器分工协作的应用架构。**作用**：用于局域网内功能较强客户端场景。
- **B/S 架构**：是浏览器作为统一客户端、业务逻辑与数据集中在服务器端的架构。**作用**：用于跨平台访问与集中升级。
- **三层架构**：是将表示层、业务逻辑层与数据访问层分离的结构。**作用**：用于降低耦合、支持伸缩与团队分工。
- C/S、B/S、三层架构（答卷·必背）：
- **软件架构**：软件架构是软件系统的构件、连接件、集成模式及其约束的集合，规定了系统的组织结构与拓扑关系。**作用**：用于主要作用是体现早期设计决策、明确实现约束、制约并权衡质量属性，并为干系人沟通、开发组织划分与系统演化提供依据。
- **架构风格**：架构风格是特定应用领域内反复使用的系统组织方式的惯用模式，由构件类型、连接件类型及其组合约束（词汇表 + 约束）构成。**作用**：用于主要作用是为架构设计提供可复用的组织模板，简化设计决策并影响系统的质量属性与演化能力。
- **SOA**：SOA（面向服务架构）是将系统功能封装为可独立发布、发现与调用的松散耦合服务的架构风格。**作用**：用于主要作用是实现跨系统、跨平台的业务集成与复用，三角色为服务提供者、服务请求者与注册中心。
- **ESB**：ESB（企业服务总线）是 SOA 中连接各服务与遗留系统的标准化通信与集成中间件。**作用**：用于主要作用是以非侵入方式集成异构系统，提供消息转换、路由、协议适配与服务编排能力。
- **质量属性**：质量属性是描述系统在运行期或开发期非功能需求满足程度的可度量特征（如性能、安全、可用性等）。**作用**：用于主要作用是作为架构设计与评估的核心依据，架构风格与关键决策直接制约并权衡各类质量属性。
- **质量属性场景**：质量属性场景是用结构化方式描述特定质量属性需求的情境化实例，六要素为：刺激源→刺激→环境→制品→响应→响应度量。**作用**：主要用于架构评估（如 ATAM）中明确「在什么条件下系统应如何响应」，使非功能需求可验证、可量化。

## 要点

### 返回风格

| 风格 | 特点 |
|-----|------|
| **主程序/子程序** | 单线程控制 |
| **面向对象** | 对象 + 方法调用 |
| **层次结构** | 层间调用，上层依赖下层 |
| **C/S** | 资源不对等、共享；二层或三层 |
| **B/S** | 三层 C/S 的实现，浏览器客户端 |

| 架构 | 定义（是……） | 作用 / 适用（用于……） |
|-----|-------------|---------------------|
| **C/S 架构** | C/S 架构是客户端与服务器资源不对等、通过网络共享数据的调用/返回式架构，常见二层或三层划分。 | 适用于需丰富客户端交互、局部高性能处理的场景；主要作用是集中管理核心数据与业务逻辑。 |
| **B/S 架构** | B/S 架构是以浏览器为客户端的三层 C/S 实现，表示层由 Web 浏览器承担。 | 适用于广域网部署、免客户端安装与易维护升级的场景；主要作用是降低客户端部署与维护成本。 |
| **三层架构** | 三层架构是将系统划分为表示层、功能（业务逻辑）层与数据层的 C/S 组织方式。 | 适用于需逻辑独立、并行开发与跨平台选型的中大型系统；主要作用是隔离界面、业务与数据，提升可维护性与可扩展性。 |

**二层 C/S 缺点**：开发成本高、客户端复杂、界面不一、移植难、维护升级难、扩展性差、安全性难保证。

**三层 C/S 优点**：
- 逻辑相对独立
- 灵活选平台
- 并行开发、多语言
- 功能层隔离表示与数据

**B/S 不足**：动态页面支持弱、安全性较 C/S 低、交互性不强。
