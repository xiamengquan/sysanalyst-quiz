# 第20章 微服务系统分析与设计

## 一、场景特征

**定义**：将大型应用拆分为**小型、自治、独立部署**的服务，每个服务围绕特定业务能力，通过轻量通信（HTTP/REST、gRPC、消息）协作。

**典型场景**：电商、金融、流媒体（Netflix）、大型互联网后台

**核心特征**：
1. 服务粒度小、职责单一
2. 独立部署与演化
3. 松耦合
4. 分布式部署（跨数据中心）
5. 技术异构（Java/Python/Go 混用）
6. 弹性伸缩
7. 独立演化和部署

**与 SOA 关系**：微服务是 SOA 的细粒度实现；强调去 ESB 中心化、去共享 DB、智能端点+简单消息

## 二、架构原则与模式

### 2.1 九大架构原则

| 原则 | 要点 |
|------|------|
| 单一职责 | 一服务一业务域 |
| 隔离性 | 独立进程+独立 DB，容器封装 |
| 自治性 | 独立生命周期，组件化 |
| 弹性 | 自动扩缩容、容错转移 |
| 可观察性 | 日志、指标、链路追踪 |
| 可测试性 | 单元/集成/契约测试、CI/CD |
| 可维护性 | 标准 API（REST/OpenAPI）、版本控制 |
| 安全性 | TLS、OAuth2、JWT、RBAC |
| 智能端点+简单消息 | 去中心化集成，异步消息 |

### 2.2 六种架构模式（案例对比高频）

| 模式 | 机制 | 优点 | 注意 |
|------|------|------|------|
| **聚合器** | 收集多服务数据聚合返回 | 减延迟、减依赖、提高可靠 | 聚合器成为瓶颈 |
| **代理** | 网关转发+治理（LB/熔断/限流） | 解耦客户端与后端 | 不做数据聚合 |
| **链式** | 请求顺序经过多服务 | 流程清晰 | 客户端阻塞等待 |
| **分支** | 链式扩展，条件分支 | 灵活业务路径 | 复杂度上升 |
| **数据共享** | 共享 DB 或数据代理(Kafka) | 数据一致 | 并发与一致性风险 |
| **异步消息** | 消息队列+EDA | 高吞吐、松耦合 | 最终一致性 |

### 2.3 开发与运维组件

| 组件 | 代表技术 | 作用 |
|------|----------|------|
| 容器化 | Docker、Kubernetes | 隔离、编排、自动部署 |
| 服务注册发现 | Consul、Eureka、Nacos | 动态地址 |
| 服务通信 | REST、gRPC、Kafka | 同步/异步 |
| API 网关 | Zuul、Kong | 路由、鉴权、限流 |
| 安全 | OAuth2（4 模式）、JWT、TLS | 认证授权 |
| 监控 | ELK（Logstash→ES→Kibana）、Prometheus+Grafana、APM | 日志/指标/告警 |

**OAuth2 四种模式**：授权码、密码、客户端、隐式

**gRPC 四种 RPC**：Unary、Server Streaming、Client Streaming、Bidirectional Streaming

**Kafka 核心概念**：Broker、Topic、Partition、Producer、Consumer、Consumer Group

## 三、开发与测试要点

### 3.1 测试特点

- 服务多、依赖链长
- 需契约测试（Consumer-Driven Contract）
- 需测试替身（Mock/Stub）与测试容器
- 分布式环境搭建复杂

### 3.2 测试过程与类型

**过程**：单元（单服务）→ 集成（服务间）→ 端到端 → 性能 → 容错 → 安全

| 类型 | 要点 |
|------|------|
| 功能 | API 正确性、业务规则 |
| 性能 | 单服务与链路延迟、吞吐 |
| 容错 | 熔断、降级、故障注入 |
| 安全 | 认证授权、传输加密、漏洞扫描 |
