系统分析师 · 案例分析答题教程

面向软考高级科目2 案例分析（机考，通常 3 道大题）。
2026 起：与综合知识在上午同场连续机考——选择题交卷后（最长 150 分钟，满 120 分钟可提前交卷）立即进入本科目，请预留案例作答体力与时间。
目标：把「会知识点」变成「会按题型得分」；可与教程第16—21章、你的全渠道定制商城项目对照练习。

0. 先建立正确预期

案例分析不是写论文，也不是默写教材。

维度 论文 案例分析
篇幅 摘要+2500字长文 每问几十到三四百字 / 填空 / 填表
素材 必须像你的真实项目 以题干场景为准，可少量迁移经验
得分点 切题+实践+文笔 踩采分点：对比、选型理由、步骤、风险
失败主因 走题、空洞 漏约束、只写概念不写「为什么选」、字数不够或散

阅卷逻辑很简单：题干给了什么约束 → 你有没有用到 → 结论是否落在采分点上。

2. 考场时间与读题流程（强烈建议固定）

总时长按当次安排（常见约 90 分钟量级，以准考证为准），3 题建议均分，难题可略倾斜。

2.1 单题 7 步法（约 25–30 分钟/题）

① 先看问题（30秒）——知道要答什么，再读案例
② 通读案例，圈约束（3–5分钟）
③ 判断领域与题型（1分钟）
④ 列提纲/表格骨架（2分钟）
⑤ 按问作答，先写采分点（15–18分钟）
⑥ 回扣题干关键词检查（2分钟）
⑦ 字数与卷面：填空写满，简答分段（1分钟）

为什么先看问题？
避免读案例时平均用力；有目的地找「性能、遗留系统、安全、实时」等词。

2.2 读案例时必圈的「约束清单」

用笔或记号标出（机考可用草稿纸）：

类型 例子
业务目标 促销高峰、定制履约、多渠统一
质量属性 性能、可用、安全、可改、一致
技术现状 遗留 J2EE/.NET、单体、已有 ERP
组织约束 工期紧、团队技能、不能停机
明确要求 「对比两种方案」「200字以内」「填表」

答每一问前，扫一眼这张清单：你的理由里至少用到 2 个题干词。

3. 题型识别与答题模板（核心）

2026 考纲四类题型（站点筛选与 案例四类题型导航 已对齐）：

考纲类型 本教程子模板 速查
需求识别与确认 类型 C（需求侧）+ 获取方法表 需求获取五法对比卡
建模与设计 类型 B 填空补图 + 类型 D 设计 系统设计类 Checklist
问题诊断与改进 类型 D 改进 问题诊断模板
技术方案论证 类型 A 方案对比/选型 技术方案论证模板

下面 A–E 为答题手法（可与上表四类交叉组合）。题型对了，模板就对了。

类型 A：方案对比 / 选型（→ 技术方案论证）

题面特征： 张工/李工两种方案；传统集成 vs SOA；单体 vs 微服务；MySQL vs NoSQL…

标准答法：

  1. 用表格（若题目是填表，严格按表头）
  2. 对比维度从题干来：耦合、扩展、复用、复杂度、性能、成本、对遗留系统友好度…
  3. 最后一问若问「为何选王工」：写 「更符合题干的××需求」，不要只写「更先进」。

万能对比维度（按需选用 4–6 个）：

集成复杂度 | 系统耦合度 | 可扩展性 | 对遗留包装能力
开发/改造成本 | 性能与实时性 | 运维复杂度 | 团队技能匹配
一致性保障 | 安全性 | 上线风险 | 是否便于提供增值服务

句式：

方案A优点是…，不足是…；方案B优点是…，不足是…。结合题干「需要××、存在××遗留」，宜选方案B，因为…。

类型 B：填空 / 补全图表 / 补步骤

特征： 架构图缺框、流程缺步、表中空格、括号填技术名。

策略：

  1. 先看已有格子的命名风格（全称还是缩写、中文还是英文）
  2. 空格前后是「输入/输出/上一层/下一层」→ 用数据流或调用关系推理
  3. 拿不准时优先填教材标准词：ESB、API 网关、服务注册中心、熔断、缓存、CDN、消息队列、BFF、防腐层

忌： 自造英文、写太长句子塞进空格。

类型 C：简答「请说明…」「请分析…」（限字）

特征： 100/200/300 字以内；说明层次、功能、步骤、风险。

结构（推荐三段，不要散文）：

（1）结论/分层名（先给答案）
（2）每层/每步：做什么 + 用什么（标准/技术）
（3）回扣题干一句（为何这样划分）

字数控制：
200 字 ≈ 4–6 个短句；宁可少修饰，不要缺层次。

类型 D：设计 / 改进建议（→ 建模与设计 或 问题诊断与改进）

特征： 如何保证性能、如何做安全、如何测、如何拆服务…；或「指出问题 + 改进措施」

结构：

目标（对应题干质量属性）
→ 措施1（机制 + 落点）
→ 措施2
→ 措施3
→ （可选）验证方式 / 风险

每条措施尽量：技术名 + 用在哪一层/哪个链路 + 解决什么问题。

坏例子：「加强缓存和优化。」
好例子：「商品详情与定制模板走 CDN/本地缓存，降低源站压力；下单热点接口网关限流，保护库存与支付下游。」

类型 E：计算 / 指标（较少但要会）

如可用性、缓存命中、进度网络图、规范化等——公式先行，代入题干数字，单位写清。

4. 分析师思维：比「会技术」更重要的三问

每道大题在心中过一遍：

  1. 要解决的业务问题是什么？（超卖、集成烟囱、高峰、实时控制…）
  2. 关键质量属性排序？（题干通常已暗示）
  3. 约束下最优，而不是理论上最优？

案例分析的高分句，往往是：

虽然微服务更灵活，但题干要求「工期紧、团队小、核心交易强一致」，更宜先模块化单体/适度拆分，待流量与组织成熟再演进。

这叫权衡（trade-off），系分案例极爱考。

5. 高频场景「条件反射」清单

看到关键词，立刻想到标准对策（写答案时往上靠）：

题干信号 优先联想
多种遗留、协议杂、要增值组合 SOA / 服务封装 / ESB 或 API 网关
大促、高并发读 缓存、CDN、读写分离、限流降级
下单库存正确 预占、幂等、事务消息、防超卖
多端（Web/小程序） BFF/统一领域服务，避免双端两套规则
外部平台订单 适配器归一、状态映射、幂等
与 ERP/MES 防腐层、异步回传、监控对接成功率
拆微服务 按业务能力拆、数据库独立、分布式事务难点
安全 认证鉴权、HTTPS、最小权限、审计、防注入
可测性 分层测、契约测、性能专项、故障注入
实时/嵌入式 最坏执行时间、优先级、优先级反转、看门狗

把你公司的系统也映射进去练习（考试仍以题干为准）：

你的现实 案例可迁移点
自营/分销/小程序 多入口、统一订单模型
外平台接入 适配器、归一、售后映射
自研编辑器 异步导出、对象存储、一致性
ERP/MES 集成、最终一致、进度展示

6. 答案「长什么样」才像得分卷

6.1 推荐版式

  • 有对比 → 先表后文（表内短词，表下 2–4 句结论）
  • 有步骤 → （1）（2）（3） 编号
  • 有层次 → 层名：职责；关键技术/标准
  • 简答 → 短句，一段一个点

6.2 采分点密度自检

写完问自己：

  • 题干专有名词出现了吗？（遗留系统、ESB、峰值…）
  • 每个空/每条建议是否可能对应一个采分点？
  • 有没有只写形容词（「更好、更强」）却没有机制？
  • 限字题是否超了？（超了砍修饰，留结构）

6.3 常见失分

失分 表现 改法
空对空 大段定义，不碰案例 每段至少一句题干事实
单边吹 只夸所选方案 承认另一方案适用点
技术堆砌 列 10 个中间件 3 条措施写透
忽略约束 无视「不能停机」 方案加灰度/双写/并行切换
填空风格乱 中英混、过长 对齐已有格

7. 用一道「缩微例题」练手（集成类）

案例缩微：
企业有多套遗留系统（不同技术、不同协议），要做功能整合并提供组合增值服务。刘工主张分层传统集成+消息中间件；王工主张 Web Service 包装 + ESB。最终选王工。

问题1（表）： 比集成方法、需求符合度、耦合与扩展。
问题2： ESB 基本功能（≤200字）。
问题3： 基于 Web Service 的层次与标准（≤300字）。

你应按：

  1. 表：传统=层次多、方法杂 / 对遗留友好但耦合高；SOA=服务暴露与组合 / 总线低耦合易扩展
  2. ESB：路由、协议转换、消息转换、编排、监控与治理（用题干「异构、增值组合」串起来）
  3. 层次示例：表现/接入 → 组合编排 → 服务 → 遗留适配；点名 SOAP/WSDL 或 REST、或登记发现等（按当纲用语）

练完对照：你是否每空都在对比维度上说话，而不是默写 SOA 定义。

8. 复习计划（案例专项）

8.1 知识准备（按领域）

  • 每周 1 个领域：读精炼笔记第16—21章对应节 + 画一张「架构草图」
  • 准备 10 张对比卡（SOA vs 传统 EAI、单体 vs 微服、直连 vs 总线、强一致 vs 最终一致…）

8.2 真题训练法

  1. 限时：按考试单题时间做
  2. 先自己写再看解析
  3. 用红笔标：题干哪句对应解析哪句采分点
  4. 沉淀到自己的「信号→对策」表（第5节）

8.3 每周最少量

  • 1 道完整案例（3 问）限时
  • 3 张对比表默写
  • 1 次：把某问压缩到 200 字内仍含 4 个采分点

9. 考场当天检查单

开始答卷前：

  1. 先扫三道题题型（对比 / 填空 / 简答 / 设计）
  2. 先做擅长领域（Web/移动/集成），再啃嵌入式/CPS（若都不熟则均分时间）
  3. 填表题优先保证「表填满」
  4. 简答先写编号结构，再填肉
  5. 交卷前：每问是否出现题干关键词

10. 一句话总纲

圈约束 → 认题型 → 套模板 → 表/编号呈现 → 每句挂钩题干与质量属性。

案例分析考的是「在约束下做系统分析师的判断」，不是考谁背的名词更多。

附录：与你项目相关的练习方向（自愿）

用自家系统出假题自测（答案仍按教材术语写）：

  1. 自营/分销/外平台如何统一订单模型？（适配器 + 统一状态机）
  2. 大促时编辑器导出与下单如何互不影响？（异步队列、限流、降级）
