何时写

论文题出现 企业架构、信息化规划、顶层设计、业务与 IT 对齐、EA 治理 等，且要求写 规划过程 + 架构制品 + 实施路线。

Zachman 框架（「什么×谁」矩阵）

维度 典型列（简化） 论文可写
视角 规划者/所有者/设计者/建造者/子系统/用户 本人角色落在「设计者/建造者」
抽象 What/How/Where/Who/When/Why 用 What=数据、How=功能、Where=网络 对齐项目

一句话：Zachman 强调 分类完备；论文写「按单元格补齐制品，避免只写技术架构」。

TOGAF ADM（架构开发方法，简记）

  1. 架构愿景 → 2. 业务架构 → 3. 信息系统架构（数据+应用）→ 4. 技术架构 → 5. 机会与迁移 → 6. 实施治理 → 7. 变更管理（循环）

论文段落模板：现状痛点 → ADM 裁剪（说明跳过/合并阶段的理由）→ 关键制品（业务架构图/应用分层/技术选型）→ 迁移路线图与治理委员会。
