概述

Web 应用及特征：Web 应用系统（答卷·定义）：Web 应用系统是以 Web 浏览器（或支持 Web 技术的可视化界面）为用户入口、基于 Web 技术与 W3C 标准、通过 HTTP/HTTPS 等协议向用户提供内容与服务的应用程序。

速懂

  • 一句话：Web 应用系统是以 Web 浏览器（或支持 Web 技术的可视化界面）为用户入口、基于 Web 技术与 W3C 标准、通过 HTTP/HTTPS 等协议向用户提供内容与服务的应用程序。
  • 考什么：Web 峰值、缓存限流、B/S 与 MVC（教程第 16 章）。
  • 具体理解：
    • 传统应用 + SPA 并存：服务端渲染 MVC vs 客户端 SPA（Blazor WebAssembly 等）
    • 传统 Web 应用：大部分逻辑在服务器，每次操作完整页面重载
    • SPA：静态 HTML 初始化 + JavaScript + Web API，极少服务端页面加载

定义

  • Web 应用系统：Web 应用系统是以 Web 浏览器（或支持 Web 技术的可视化界面）为用户入口、基于 Web 技术与 W3C 标准、通过 HTTP/HTTPS 等协议向用户提供内容与服务的应用程序。作用：主要用于降低客户端安装与维护成本，实现跨平台、易访问的信息交互与业务处理；典型场景包括电子商务、企业门户、SaaS 与社交网络等。

步骤与流程

Web 测试特点

  1. 用户量大，需跨平台全局访问与并发事务处理
  2. 超文本链接关系须人工校验
  3. 多层架构，需综合分析各层结果
  4. 集成 Web 服务器、DB、中间件、第三方组件
  5. 浏览器导航（back/forward/refresh）影响状态
  6. 技术种类多，测试模型粒度难定义
  7. 分布式、动态、多平台、交互、超文本

场景特征

  1. 云托管与可扩展性：低内存、高吞吐，容器/微服务友好
  2. 跨平台：Linux/macOS/Windows，Docker 部署
  3. 自动化测试：脚本模拟用户操作，可重复、可回归
  4. 传统应用 + SPA 并存：服务端渲染 MVC vs 客户端 SPA（Blazor WebAssembly 等）
  5. CI/CD 友好：Azure DevOps、GitHub Actions 等持续交付

开发框架（案例技术选型）

  1. 浏览器
  2. Struts(Controller)
  3. Spring(Business)
  4. Hibernate(DAO)
  5. 数据库

要点

场景特征

定义：用户界面驻留于 Web 浏览器（或支持 Web 技术的可视化界面）的应用程序，基于 Web 技术与 W3C 标准，通过 HTTP 等协议提供内容与服务。

典型场景：

  • 电子商务（购物车、支付、供应链集成）
  • 企业门户、SaaS 服务、社交网络
  • 从小规模工具到 Internet/Intranet/Extranet 大规模分布式应用

Web 应用核心优势（案例可列举）：

特征 说明
易于访问 任意浏览器、多设备，无需安装客户端
开发高效 单代码库多平台，开发周期短
使用简单 自动更新，用户无维护负担
扩展性强 按需增用户，数据多存云端

新式 Web 应用特征（与案例架构选型相关）：

两种构建方式：

  • 传统 Web 应用：大部分逻辑在服务器，每次操作完整页面重载
  • SPA：静态 HTML 初始化 + JavaScript + Web API，极少服务端页面加载

易混辨析

对比 区别
传统 Web vs SPA 传统 Web 每次操作多完整页面重载、逻辑主要在服务端；SPA 初始化后由 JavaScript 调用 API、极少整页刷新，交互更流畅。
