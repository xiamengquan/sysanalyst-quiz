1. L0 · 入门：先立坐标系

1.1 UML 是什么（答卷·定义 / 作用）

UML（答卷·定义）
UML（统一建模语言）是一套用标准图形符号描述软件系统静态结构与动态行为的可视化建模语言；它不是编程语言，也不是软件开发过程本身。

UML 的作用（答卷）
UML 用于在分析、设计与沟通中统一表达系统模型，帮助干系人就「系统长什么样、如何运作」达成一致，并为需求分析、架构设计、实现与测试提供可共享的图示依据。

类别 答卷·定义 答卷·作用 考试关键词
结构图 结构图是描述系统静态构成与元素间连接关系的 UML 图。 用于说明系统由哪些构件组成、如何组织与部署。 类、包、组件、部署

2.2.1 六种关系 · 答卷定义与作用

关系（答卷·定义）：关系是 UML 模型元素之间具有语义的连接。类图中最常考查；用例图中另有通信关联以及 «include» / «extend»（见 §3.1）。
关系的作用（答卷）：关系用于标明模型元素之间如何联系与协作，使静态结构与动态交互可被准确表达和阅读。

关系 答卷·定义 答卷·作用 符号要点
关联 Association 表示分类器之间的结构关系，其实例之间通过链接相连；可标注角色名、多重性、导航性、可见性、限定符和约束，也可附带关联类；聚合与组合是关联的两种特殊形式。 用于在类图中表达实例间的结构连接及端点语义。 实线；单向导航：开放箭头指向可导航目标端
依赖 Dependency 表示客户端元素对供应者元素的依赖，供应者的变更可能影响客户端；通常是非结构性的、较弱的语义关系，常用于使用、创建、调用、导入等。 用于表示较弱的使用/创建/调用等语义，而不强调长期结构持有。 虚线开放箭头：客户端 → 供应者
泛化 Generalization 表示一般分类器与特殊分类器之间的 is-a 关系；特殊分类器继承一般分类器的特征，并可增加、覆盖或特化其行为，支持子类型可替换父类型。 用于建立类型层次与多态。 实线空心三角，三角在一般分类器端
实现 Realization 表示实现元素与规约元素之间的契约兑现关系，实现端承诺满足规约端声明的契约（典型如类实现接口）。 用于表示实现与规约在操作与责任上的对应。 虚线空心三角，三角在被实现的规约端
聚合 Aggregation 是具有共享整—部分语义的关联；整体与部分是弱拥有关系，整体不负责部分的生命周期，部分可独立存在，并可能被多个整体共享。 用于表示可分离的整—部分包含及共享归属。 实线空心菱形在整体（whole）端
组合 Composition 是具有组合整—部分语义的关联；整体负责部分的存在与存储，部分生命周期通常与整体绑定；整体销毁时部分通常失去独立存在意义。 用于表示强拥有与构成，部分不能独立于整体存在。 实线实心菱形在整体（whole）端

强度（答卷可写）：在整—部分与使用联系上，依赖弱于关联，关联弱于聚合，聚合弱于组合。泛化与实现属于类型/契约关系，不参与菱形强弱排序。

选型依据（答卷）：部分生命周期是否从属整体 → 组合/聚合；是否为结构连接 → 关联/依赖；继承还是兑现契约 → 泛化/实现（看实线/虚线三角）。

flowchart TB Dep[依赖 · 临时使用] --> Assoc[关联 · 稳定往来] Assoc --> Agg[聚合 · 可拆的整体部分] Agg --> Comp[组合 · 同生共死] Gen[泛化 · 是一种] -.->|类型层次| Class[类] Real[实现 · 兑现接口] -.->|契约| IF[«接口»]

易混（答卷对比句）

对比 可直接写的区别
关联 vs 依赖 关联是结构性联系，实例经链接相连；依赖较弱，常用于使用/创建/调用/导入，供应者变更可能影响客户端。
聚合 vs 组合 聚合：弱拥有，整体不负责部分生命周期，部分可独立、可被共享；组合：整体负责部分存在与存储，生命周期通常绑定。
泛化 vs 实现 二者均为空心三角；实线表示继承父类，虚线表示实现接口。
菱形方向 菱形始终画在整体一端。

多重性（答卷）：多重性（Multiplicity）标注在关联端点，表示该端一个实例可与另一端实例集合的基数约束（如 1、0..1、、1.. 等）。

口诀（助记，勿当答卷）：关联「认识」· 依赖「用一下」· 泛化「是一种」· 实现「兑现契约」· 聚合「有一些」· 组合「长在身上」。

前端类比（勿写进答案）：关联≈模块间稳定引用；依赖≈临时 import；泛化≈继承；实现≈兑现接口约定；聚合≈可挪走的子项；组合≈随父卸载的子项。

3. L2 · 必考五图（精读 · 带图）

3.1 用例图 Use Case

答卷·定义：用例图是描述系统边界外参与者与系统内用例及其关系的行为图。
答卷·作用：用于界定系统功能范围，说明谁与系统交互、系统为参与者完成哪些有价值目标。

include vs extend（答卷）

答卷·定义 答卷·作用 箭头
«include» include 是基用例必然包含另一用例行为的关系。 用于抽取每次都必须执行的公共子流程。 基用例 → 被包含用例
«extend» extend 是在特定条件下由扩展用例为基用例增加行为的关系。 用于表示可选增值功能或条件触发的扩展行为。 扩展用例 → 基用例
flowchart LR Base[基用例：查询联系人] Inc[被包含：身份认证] Ext[扩展：发送短信] Base -->|«include» 必做| Inc Ext -->|«extend» 可选| Base
include extend
时机 每次都执行 条件满足才执行
话术 抽公共子流程 可选增值/异常

案例填空看哪里

  1. 边界外空白 → 参与者
  2. 椭圆空白 → 用例名（动宾）
  3. 虚线旁 → 先判必经/可选，再写 include 或 extend

3.2 类图 Class

答卷·定义：类图是描述类、接口及其属性、操作与静态关系的结构图。
答卷·作用：用于展示问题域或设计中的概念结构，说明有哪些类以及类之间如何关联。

三格：类名 / 属性 / 操作()。可见性：+ public · - private · # protected。

分析类三角色 BCE（答卷·定义 / 作用）

角色 答卷·定义 答卷·作用
边界 Boundary 边界类是系统与参与者（或其他外部系统、设备）之间的交互接口类。 用于接收外部输入、返回处理结果并完成交互适配，隔离系统内外；不承担核心业务数据的持久保存。
控制 Control 控制类是协调完成某一用例（或其中控制流程）的编排类。 用于按规定顺序调用相关对象、处理分支与异常，实现用例处理流程；不长期保存业务数据。
实体 Entity 实体类是问题域中具有持久业务意义的信息及其业务规则的载体类。 用于表达并保存业务对象的状态与约束，供控制类在用例执行中读写。

采用 BCE 的作用（答卷）：按职责分离界面交互、流程编排与业务数据，避免职责混杂，便于建立分析模型并衔接到序列图与设计。
口诀（助记）：界面收发、控制编排、实体存业务。
协作（答卷）：参与者通过边界类交互，边界类将请求交控制类，控制类再调用实体类。一条用例常对应 1 边界 + 1 控制 + 若干实体。详解见 速查/结构化与面向对象分析-体系化学习路径.md · §4.4。

多重性读法：靠近对端的数字 = 「一个本端对应几个对端」。

3.3 序列图 Sequence

答卷·定义：序列图是按时间顺序描述对象之间消息交互的行为图。
答卷·作用：用于说明某一场景下对象如何依次发送消息、协作完成一次交互。

口径对照（必记）：

题型 数量 元素 依据
选择题 / 综合知识 三大 对象、生命线、消息 2014 上午第 2 题

选择题里参与者通常并入「对象」（顶框 + 生命线）；案例简答要求单独列出参与者，写作用「界定系统边界、作为消息发起/接收源头」。

四大核心元素（案例简答 · 2026 上）：

元素 作用（答卷句）
参与者 Actor 与系统交互的外部实体（用户、外部设备/系统）；作为消息发起或接收源头，界定系统边界
对象 Object 系统内部执行业务的实例（常写 对象名:类名）；消息传递的核心载体
生命线 Lifeline 参与者/对象在时间上的存在；纵向体现交互先后顺序（上早下晚）
消息 Message 参与者↔对象、对象↔对象间传递的交互指令；带箭头与消息名，串联流程节点

3.3b 通信图 Communication（旧称：协作图）

答卷·定义：通信图（Communication Diagram）是按对象之间的链接（Link）结构描述消息交互的行为图；在 UML 1.x 中称为协作图（Collaboration Diagram）。
答卷·作用：用于说明某一协作场景中「哪些对象彼此相连、在链路上交换了哪些消息」；消息旁用序号表达先后，强调对象拓扑与协作关系，而非垂直时间轴。

与序列图的关系（答卷）：通信图与序列图同属交互图（Interaction），语义等价、视角不同——同一场景可互相转换；序列图突出时间顺序，通信图突出对象间链接结构。

元素 含义
对象 / 角色 矩形框，常写作 名称:类名 或仅类名
链接 Link 对象间实线，表示二者存在可发消息的连接
消息 链路上的箭头；标注 序号:消息()（如 1.2:校验()）
序号 表达消息先后；可用嵌套序号（1、1.1、1.2）表示调用层次
对比项 序列图 通信图（协作图）
答卷·侧重点 按时间轴看「先发谁、后发谁」 按链接看「谁连着谁、链路上有哪些消息」
时间表达 生命线自上而下 消息序号（可嵌套）
结构表达 较弱（对象横排） 较强（对象自由排布 + 链接）
旧称 / 现称 顺序图 ≈ 序列图 协作图 ≈ 通信图（UML 2）
题干信号 「调用顺序」「时序」「生命线」 「协作关系」「对象链接」「带序号消息」；题干写「协作图」亦指本图

易混（答卷）：

  • 通信图 ≠ 类图：类图是静态结构（类与关系）；通信图是某次协作中的对象实例与消息。
  • 通信图 ≠ 活动图：活动图描述流程步骤/并行；通信图描述对象间消息协作。
  • 软考材料若写「协作图」，按 UML 2 答「通信图」即可，二者概念等价。

何时优先画通信图：题干强调参与对象有哪些、彼此如何连接、消息挂在哪条链上；或要求与序列图对照转换时。

3.4 状态机图 State Machine

答卷·定义：状态机图是描述某一个对象在其生命周期中所处状态及状态迁移的行为图。
答卷·作用：用于说明该对象在何种事件（及条件）下从一种状态转到另一种状态。

何时用状态图 何时用活动图
焦点是一个对象的状态 焦点是业务流程步骤/并行
「处于什么状态」 「下一步做什么」

迁移标注格式：事件[条件]/动作

3.5 活动图 Activity

4. L3 · 加深：易混与次高频

4.1 聚合 vs 组合（答卷再钉死）

聚合（答卷·定义）：聚合是具有共享整—部分语义的关联；整体与部分是弱拥有关系，整体不负责部分的生命周期，部分可独立存在，并可能被多个整体共享。符号为实线空心菱形，菱形位于整体端。
聚合的作用（答卷）：用于表示可分离的整—部分包含及共享归属。

组合（答卷·定义）：组合是具有组合整—部分语义的关联；整体负责部分的存在与存储，部分生命周期通常与整体绑定；整体销毁时，部分通常失去独立存在意义。符号为实线实心菱形，菱形位于整体端。
组合的作用（答卷）：用于表示强拥有与构成，部分不能独立于整体存在。

flowchart LR W1[Whole] --o P1[Part] W2[Whole] --* P2[Part]
聚合 ○ 组合 ●
生命周期 部分可独立于整体 部分随整体消亡
符号 空心菱形在 whole 端 实心菱形在 whole 端
语义判据 部分可脱离整体仍具独立存在意义 整体销毁时部分通常失去独立存在意义

答卷补充：聚合与组合都是带整体—部分语义的特殊关联；题干出现删除级联、同生共死信号时，优先判为组合。
