数据与数据流程分析（DFD）

大纲：10.6 · 教程：第10章 · 分组：科目1 · 8. 系统规划与分析 · 状态：结构式重写 v2.0 · 审计通过

概述

数据与数据流程分析（DFD） 属本科目大纲考点。常考：数据流图 DFD（0层图、分层、守恒） · 案例大题高频。

速懂

  • 一句话：系统规划是信息系统生命周期第一阶段，在既定约束下分析系统建设的必要性与可能性的工作。
  • 考什么：可行性四维、DFD、规划方法 BSP/CSF（教程第 10 章）。
  • 别搞混：| 对比 | 区别 |

定义

  • 系统规划：系统规划是信息系统生命周期第一阶段，在既定约束下分析系统建设的必要性与可能性的工作。作用：用于主要作用是输出可行性研究报告与系统设计任务书，为后续系统分析、设计与实施确立目标与边界。
  • 系统分析：系统分析是在系统规划基础上，与用户配合对现行系统进行全面调查与分析，确定新系统逻辑需求的工作。作用：用于主要作用是找出业务瓶颈、明确新系统应实现的逻辑功能，并输出系统需求规格说明书。
  • 数据流图 DFD：数据流图是用外部实体、加工、数据流、数据存储四种基本元素描述系统中数据流动与处理过程的图形化模型。作用：主要用于在系统分析阶段表达系统的逻辑功能与数据加工路径，为分层分解、需求确认与后续设计提供依据。
  • 上下文图 / 0 层图：上下文图（即 0 层图）是数据流图的最顶层，仅含一个代表整个系统的加工及其与外部实体之间的数据流。作用：用于界定系统边界、明确系统与外部环境的信息交换关系，是 DFD 自顶向下分解的起点。
  • 可行性分析：可行性分析是对拟建信息系统从必要性与可能性两方面进行论证与评价的工作。作用：用于主要作用是为项目立项、方案选择与投资决策提供依据，避免盲目建设或技术不可行。

步骤与流程

DFD 绘制规则（必背）

  1. 仅 4 种基本元素，每个元素必须有名字
  2. 每个加工至少一个输入、一个输出；保持数据守恒
  3. 按层给加工编号
  4. 子图与上一层一个加工对应，输入输出数据流一致
  5. 每个数据存储必须有读和写的数据流
  6. 可加入物质流，不可夹带控制流

数据流内涵五要素

  1. 数据源
  2. 数据传输
  3. 数据转换
  4. 数据存储
  5. 数据输出

逻辑数据流与数据流守恒

  1. 输入 = 输出（无增删时）
  2. 输出 = 输入 + 增量（更新/修改）
  3. 处理前 = 处理后 + 丢失量（删除/移除）

要点

四种基本符号

符号 图形 含义
外部实体 矩形 系统外人员、设备、其他系统
进程/加工 圆角矩形 功能模块或处理过程
数据存储 开口矩形（长方形） 文件、数据库等
数据流 带箭头实线 数据流动方向与内容
要素 定义（是……） 作用（用于……）
外部实体 外部实体是系统边界之外、与系统发生信息交换的人员、设备或其他系统。 用于表示系统与外部环境的交互端点，界定系统范围。
加工（进程） 加工是对输入数据进行处理并产生输出数据的功能模块或处理过程。 用于描述系统的逻辑功能单元及数据变换环节。
数据流 数据流是携带特定含义的数据在加工、外部实体与数据存储之间的有向流动。 用于表达数据的传递方向、来源与去向。
数据存储 数据存储是系统内以文件、数据库等形式持久保存数据的逻辑容器。 用于表示数据的暂存或持久化位置，支撑读/写数据流。

禁止：DFD 中不可夹带控制流（可加入物质流辅助理解）。

物理数据流图（第2版）：在逻辑 DFD 基础上标注具体实现（程序、文件、DB 表、通信协议、设备）；用于设计/实现衔接。案例改错题：逻辑阶段勿过早写表名/中间件名；物理阶段须与部署一致。

易混辨析

对比项 TFD DFD
TFD vs DFD 业务“流水账”，6种符号 系统功能，4种符号，分层分解
对比项 逻辑 DFD 物理 DFD
逻辑 DFD vs 物理 DFD 描述系统应做什么的抽象功能模型，不含实现细节 描述系统如何实现，含技术、设备与存储细节；前者用于需求分析，后者衔接设计与实现

应试

案例可能怎么问：TFD/DFD 符号识别与分层改错（守恒、外部实体、数据存储）；四维可行性缺项补全；NPV/回收期/盈亏平衡计算与方案比选结论。

论文怎么用：可行性分析、业务流程、成本效益（23上/24下/25下）——用「现状痛点→候选方案→经济/技术/管理可行性→NPV 或 ROI 结论」结构；BPR/流程再造可写 AS-IS/TO-BE 与 KPI 改进。
