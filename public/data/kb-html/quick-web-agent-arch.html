Web 与 AI 智能体 · 架构选型四维度卡

对齐真题：2026 上案例分析 · 试题五（Web + AI 智能体服务平台）
关联章节：第16章 Web · 第20章 微服务 · 第9章 安全 · 第4章 分布式
用途：案例「填表对比两种后端架构」、简答负载均衡与中间件

一、场景特征（读题信号）

题干常见表述：

  • Web 端提供：智能对话、任务自动执行、多智能体协同、知识库检索、API 调用
  • 三类终端：用户端、AI 智能体、管理后台
  • 质量要求：高并发、低延迟、数据安全、高可用；智能体 动态扩缩容 与 行为安全管控

答题第一步：确认是在比 两种后端架构（如 Spring Cloud 微服务 vs FastAPI+Node 轻量栈），按题干给的 四个维度 分别填各自优势/短板，勿混写成一个方案。

二、四维度对比（案例填表 · 2026 上口径）

维度 考查什么 轻量快速栈（FastAPI + Node.js 等） 微服务栈（Spring Cloud 等）
① 并发适配 / 实时性 峰值吞吐、响应时延、稳定性 开发快、轻量高效；异步 I/O 适合 I/O 密集；但 高并发下稳定性较弱（进程模型、治理组件少） 线程池/连接池与 服务治理 成熟；网关限流熔断；更适合 ** sustained 高并发** 与 SLA
② 智能体调度能力 多 Agent 接入、任务分发、扩缩容 需 自建 任务队列、Worker 池、路由；多 Agent 协同逻辑多在应用层实现 服务注册发现（Nacos/Eureka）+ 客户端/网关负载均衡；配合 K8s 做 Agent 实例 动态扩缩容；适合 分布式调度、多智能体协同
③ 安全与权限管控 鉴权、审计、风控、行为管控 基础安全（HTTPS、JWT 等）具备；企业级风控（细粒度 RBAC、行为审计、合规策略）常需 额外开发 Spring Security / Gateway 生态；统一 OAuth2、RBAC、API 权限；网关层 限流、黑白名单；更适合 企业级安全管控
④ 扩展性与分布式 服务拆分、横向扩展、大型平台 适合 原型验证、中小规模；横向扩展需手动拆服务或上容器 服务拆分、弹性扩缩容；配置中心、链路追踪齐全；适合 大型分布式 AI 平台

2026 上 · 问题 1 参考填空（四格）

题干要求从 并发适配、智能体调度、安全管控、扩展性 四维度对比两种架构，官方参考答案要点可概括为：

序号 填入内容（对应维度） 通常归属栈
（1） 开发快、轻量高效，但 高并发稳定性较弱 轻量快速栈
（2） 支持 分布式调度、多智能体协同与动态扩缩容 微服务栈
（3） 基础安全能力具备，企业级风控需额外开发 轻量快速栈
（4） 支持 服务拆分、弹性扩缩容，适合大型分布式平台 微服务栈

选型结论（案例写法）：若题干强调 高并发 + 多 Agent + 企业安全 + 大规模扩展 → 倾向 Spring Cloud + K8s；若强调 快速上线、团队小、流量可控 → 可先用轻量栈，并说明后续演进路径。

三、AI 智能体（Agent）要点（综合知识 + 案例背景）

答卷·定义：智能体是可以 感知环境、自主决策并执行动作 的计算实体，具有 自主性、反应性 等特征。

大模型时代 Agent（2026 上选择题口径）：不仅能对话，还可 规划任务、调用工具/API（如检索知识库、触发工作流），并非「只能对话生成」。

平台架构中与 Agent 相关的构件：

构件 作用
接入层（Nginx / API Gateway） 用户与 Agent 的 HTTP/WebSocket 接入、SSL、限流
调度/编排层 任务队列、Agent 路由、多 Agent 协同（Orchestrator）
推理/工具层 LLM 调用、RAG 检索、外部 API 执行
注册发现 Agent 实例上下线、健康检查、负载分配
安全审计 行为日志、权限策略、敏感操作拦截

四、负载均衡（2026 上 · 问题 2 要点）

面向 大量 Agent 并发接入与高吞吐推理，常见技术对比如下（300 字内简答可直接选用）：

类型 代表 优势 劣势
七层反向代理 Nginx、OpenResty 七层路由、限流、熔断、SSL 卸载；适合 Agent HTTP/WebSocket 接入 长连接密集时转发压力较大
四层负载均衡 LVS、HAProxy（四层模式） 性能极高、抗并发；适合大量连接与推理流量转发 缺乏应用层感知，无法按 Agent ID/任务类型调度
API 网关 Spring Cloud Gateway、Kong 可感知 用户/Agent 身份与接口权限；支持灰度、限流 部署复杂，网关集群本身需高可用
服务发现 + 客户端 LB Nacos + Ribbon/自研 去中心化、调度灵活；适合微服务下 Agent 实例调度 客户端逻辑复杂，统一管控难度高

答题提示：写 2～3 种 即可，每种 优势 + 劣势 成对出现；点明 Agent 场景多为 长连接 + 推理耗时，四层偏吞吐、七层偏治理。

五、常用中间件（2026 上 · 问题 3 要点）

类别 典型产品 在 AI Agent 平台中的作用
Web / 接入 Nginx、Apache 静态资源、反向代理
API 网关 Spring Cloud Gateway、Kong 路由、鉴权、限流
分布式缓存 Redis 会话、向量/热点缓存、限流计数
消息队列 Kafka、RabbitMQ 异步任务、Agent 事件通知、解耦
服务注册发现 Nacos、Eureka Agent/微服务实例注册与发现
搜索引擎 Elasticsearch 知识库、对话记录检索
配置 / 限流 Sentinel、Apollo 动态配置、熔断限流
容器编排 Kubernetes Agent 容器化调度与扩缩容

六、与「并发 vs 实时性」的辨析（易混）

概念 含义 案例怎么写
高并发 单位时间大量请求/连接 网关限流、连接池、水平扩展、缓存
低延迟 / 实时性 单次交互响应快（如对话首 token、排队 ≤1s） 边缘缓存、异步化非关键路径、推理队列优先级、WebSocket 推送
二者冲突时 峰值并发可能拉高延迟 写 削峰（队列）、读写分离、热点缓存、降级

七、30 秒默写清单

  • 四维度：并发、Agent 调度、安全、扩展
  • 轻量栈：快、轻、高并发稳性弱、基础安全
  • 微服务栈：调度扩缩、企业安全、分布式扩展
  • Agent：感知+决策+执行；可 规划任务、调工具
  • LB：七层（路由权限）vs 四层（性能）vs 网关 vs 客户端
  • 中间件：Redis / MQ / Nacos / ES / K8s
