分值与题型

  • 综合 5–8 分；案例 10–15 分；论文常涉及 Web/高并发/架构选型（章节权重约 15%–20%）
  • 题干信号：浏览器入口、HTTP/HTTPS、B/S、MVC/SPA、高并发、会话、REST

Web 应用概念与特征

  • 定义：以浏览器（或 Web 界面）为入口，基于 W3C 标准，经 HTTP/HTTPS 提供内容与服务的应用
  • 优势（案例可列）：易访问、免安装、易更新、易扩展、跨平台
  • 构建方式：传统服务端渲染 vs SPA（静态壳 + API）；新式特征含云托管、CI/CD、自动化测试

架构设计原则（8 条 · 案例高频）

# 原则 答题一句
1 分离关注点 UI / 业务 / 基础设施分开
2 封装 稳定接口、隐藏实现
3 依赖反转 依赖抽象，便于替换与测试
4 显式依赖 构造注入，避免隐式全局
5 单一责任 一服务一职责，微服务拆分依据
6 DRY 逻辑单点维护
7 持久性无知 领域模型不绑死 ORM
8 有界上下文 独立持久化边界，跨上下文用 API

架构分类与模式

分类 适用 案例对比点
整体式 低流量、小团队 部署简单 vs 扩展难
微服务 高并发、复杂域 独立扩展 vs 分布式复杂度
Serverless 事件驱动、短时任务 按量计费 vs 冷启动
B/S 三层 表现 / 逻辑 / 数据 职责分离
MVC / MVP Web 页面组织 Presenter 更利单测
前后端分离 SPA、多端复用后端 REST/BFF

REST：资源 URI + HTTP 动词 + 无状态 → 详见 REST 学习卡
Web + AI 智能体：四维度选型 → Web与AI智能体-架构选型四维度卡

开发框架（选型题）

栈 代表 角色
Java EE Spring + Struts + Hibernate（SSH） MVC + IoC + ORM
Java EE JSF 标准 Web 框架
.NET ASP.NET + ADO.NET 微软全栈
Web 层 jQuery / AJAX 等 异步交互

通信 · 存储 · 客户端/服务端

  • HTTP/HTTPS：无状态；Session/Cookie 维护登录态
  • 缓存四级：应用缓存 → 全局 → 分布式（一致性哈希）→ CDN
  • 性能三板斧：负载均衡、连接池、缓存
  • 客户端/服务端：浏览器 + Web 服务器 + 应用服务器 + DB/中间件

部署

版本与变更管理、交付前测试、支持制度、可回滚；容器/K8s 与 CI/CD 在案例中与「灰度/蓝绿」同写。

测试过程（功能 / 性能 / 安全 / Web 服务）

类型 要点
功能 表单校验、异常、浏览器后退不破坏数据
性能 超正常点击率、递增负载、极限/崩溃
安全 认证、会话、注入/XSS、事务与审计
可靠性 数据准确、高影响缺陷
Web 服务 WSDL、SOAP/REST 互操作

流程：需求 → 策略 → 环境/用例/工具 → 执行与报告。

高并发（≈65% 案例信号）

CDN、读写分离、缓存（穿透/击穿/雪崩）、消息队列、限流降级、异步化。
