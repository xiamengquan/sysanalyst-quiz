可检索摘要：需求分析常用工具包括加工逻辑三件套（结构化语言、判定表、判定树）、功能建模（数据流图 DFD、数据字典 DD）、数据建模（E-R 图、层次方框图、Warnier 图、IPO 图）、行为建模（状态转换图 STD、Petri 网）、面向对象建模（用例图、类图、顺序图、状态图、活动图）与辅助工具（因果图）。判定表适合条件组合复杂的逻辑，判定树直观但组合多时易爆炸，结构化语言适合含顺序/判断/循环的加工。

一、加工逻辑描述三件套（数据字典「加工逻辑」条目）⭐ 必考

DFD 中每个「加工」的内部逻辑，可用以下三种工具之一描述（写在数据字典的加工逻辑条目中，常考「该用哪种、为什么」）。

1. 结构化语言

  • 定义：介于自然语言与程序设计语言之间的伪码，只用**顺序、判断（IF-THEN-ELSE）、循环（WHILE）**三种基本结构表达加工逻辑，避免纯自然语言的二义性。
  • 用法：按执行顺序书写处理步骤，判断用 IF-THEN-ELSE，重复用 WHILE；动词要明确，避免「处理」「做」等空洞词。
  • 适用：逻辑不太复杂、含顺序步骤或判断循环的加工。

2. 判定表

  • 定义：用表格列出所有条件组合与对应动作的决策工具，由四部分组成：条件桩（列条件）、动作桩（列动作）、条件项（条件取值组合）、动作项（各组合下的动作）。
  • 用法：n 个条件最多 2ⁿ 种组合，须逐一填写动作、消除重复列、合并等价列；保证不遗漏、不重复。
  • 适用：条件多且组合关系复杂的决策逻辑，表达最严谨。
  • 示例（取号资格判定）：
条件桩 取值1 取值2 取值3 取值4
已实名认证？ Y Y N N
号源余量>0？ Y N Y N
动作 允许取号 提示无号 提示先认证 提示先认证

3. 判定树

  • 定义：用树形分支图表达判断逻辑，从树根到树叶的一次路径对应一条决策规则。
  • 用法：树根为初始判断，逐层分支，叶结点为动作；分支自左至右/自上而下按条件优先级排列。
  • 适用：判断层次清晰的逻辑，比判定表直观易画易交流；但条件组合多时树会迅速膨胀。

三件套选型口诀（答卷）

  • 条件组合多 → 判定表（严谨无遗漏）；分支层次清 → 判定树（直观好交流）；含顺序/循环 → 结构化语言。
  • 易错：三者描述的是同一加工逻辑，可互相转换，不是并列的独立机制。

二、功能建模工具（结构化分析核心）

4. 数据流图 DFD

  • 定义：用外部实体、加工、数据流、数据存储四种元素描述系统逻辑的数据流模型。
  • 用法（绘制四步）：①画系统输入输出（边缘标出）→ ②画内部，从输入连到处理 → ③为每个数据流命名（避免空洞词）→ ④为加工命名（动宾短语）。
  • 分层：顶层图定边界与外部实体 → 0 层图分解主要加工 → 逐层细化；父图与子图的数据流必须平衡。
  • 纠错四类：不平衡、黑洞（只有输入）、奇迹（只有输出）、多余连线（外部实体与数据存储直接连线）。
  • 需求阶段三作用：理解表达用户需求；概括内部逻辑作为设计基础；存档与修改开发计划的依据。

5. 数据字典 DD

  • 定义：对 DFD 中数据流、数据存储、加工与数据项的精确定义集合，用于消除二义性。
  • 用法：六类条目——数据元素（最小单位）、数据结构（[] 任选、{} 必选、* 重复）、数据流（来源/去处/组成/流通量）、数据存储、加工逻辑（可用判定树/表/结构化语言）、外部实体；专人（数据管理员）维护。
  • 四作用：列表、相互参照、内容检索、一致性检验。

三、数据建模工具

6. E-R 图（实体—联系图）

  • 定义：用实体、属性、联系描述静态数据结构的概念模型。
  • 用法：矩形画实体、椭圆画属性、菱形画联系并标 1:1 / 1:n / m:n；常与 DFD 配合（DFD 管加工与流动，E-R 管数据结构）。

7. 层次方框图

  • 定义：用方框嵌套表示数据结构的层次分解图。
  • 用法：自顶向下把数据逐层分解为组成部分，适合表达数据的组成层次。

8. Warnier 图（Warnier-Orr 图）

  • 定义：用花括号嵌套表示数据层次结构的图示工具。
  • 用法：花括号自左向右展开层次，符号标注出现次数（如 ±1、n）；功能与层次方框图类似。

9. IPO 图（输入—处理—输出图）

  • 定义：以输入、处理、输出三栏描述加工基本信息的简单工具。
  • 用法：逐条列出输入数据、处理步骤要点、输出结果；适合粗粒度描述加工，配合 HIPO（层次图+IPO）使用。

四、行为建模工具

10. 状态转换图 STD

  • 定义：描述单个对象或控制逻辑状态迁移的模型（状态=圆角框，迁移=箭头，事件触发迁移）。
  • 用法：先列状态与事件，再画迁移弧并标注触发事件/条件/动作；适合行为复杂、事件驱动的控制逻辑分析。
  • 易混：DFD 描述「数据怎么流」，STD 描述「状态怎么变」；OO 侧对应 UML 状态图。

11. Petri 网

  • 定义：用库所（圆）、变迁（矩形）、有向弧、令牌描述并发、异步、资源竞争系统的模型。
  • 用法：变迁满足触发条件时点火，令牌流动表示系统状态推进；用于分析并发冲突、死锁与资源竞争。

五、面向对象建模工具（UML · 详见 quick-uml-learn）

工具 定义（一句话） 用法要点
用例图 参与者、用例、通信关联描述系统功能视图 四阶段：识别参与者→合并需求获用例→细化描述→调整模型；用例命名「动词短语+名词短语」
类图 类、属性、操作及类间关系（关联/泛化/聚合/依赖）的静态结构模型 适合表达静态结构；OO 建模四步中「定义概念类、确定类关系、添加职责」
顺序图 按时间顺序描述对象间消息交互 适合按时序推进的交互场景
状态图 单个对象状态随事件的迁移 对应 STD 的 OO 表达
活动图 工作流/业务流程的活动与分支汇合 适合流程编排与并行活动

配套：BCE 分析类（边界/控制/实体）划分职责；CRC（类–责任–协作者）卡片厘清职责与协作。

六、辅助分析工具

12. 因果图

  • 定义：分析原因（输入条件）与结果（输出动作）组合关系的图示工具，可机械地导出判定表。
  • 用法：先列原因与结果，用恒等/与/或/非等约束符号连接，转换为判定表后生成测试用例；与判定表是「推导关系」——因果图在先，判定表在后。

七、选型速记表

问什么 用什么
条件组合决策怎么定 判定表（组合多）/ 判定树（层次清）/ 结构化语言（含循环）
数据怎么流 DFD + 数据字典
数据长什么样 E-R 图（也可层次方框图 / Warnier 图）
加工粗略描述 IPO 图
状态怎么变 STD / UML 状态图
并发与竞争 Petri 网
谁用系统做什么 用例图 + 用例规约
原因结果组合 因果图 → 判定表

总口诀：流看 DFD、字看 DD、据看 E-R、态看 STD、并看 Petri、决策三件套（语言/表/树）、对象 UML 一套齐。
