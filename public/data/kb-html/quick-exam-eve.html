二、试题一必答 · 两手准备

A. 需求获取五法 × 四维（默写用）

方法 广度 深度 信息集成 用户参与 一句用途
访谈 中 高 中 中高 深挖特定角色任务与痛点
JRP/JAD 中高 高 高（当场冲突） 高 当场对齐、消冲突、快共识
问卷 高 低 低 中（间接） 扩样本、看共性倾向

观察 低中 高 中 中 发现「说不清」的真实做法

答卷套路：先问卷（+采样）扩面 → 访谈/观察加深 → 情节串联板或原型对齐界面 → JAD 收敛冲突；每点回扣题干约束（工期/成本/地理分布/说法冲突）。

需求管理三件（问到就写）：评审批准后建立需求基线；CCB 变更控制（影响分析+审批）；需求跟踪矩阵（需求↔设计↔实现↔测试，正向+反向）。

B. 加工逻辑三件套（判表/判树/结构化语言）

工具 适用 口诀
判定表 条件多、组合复杂 表达最严谨、不遗漏不重复
判定树 分支层次清晰 直观易画好交流；组合多会爆炸
结构化语言 含顺序/判断/循环 伪码只写 IF-ELSE 与 WHILE

三者描述同一加工逻辑，可互相转换；写在数据字典「加工逻辑」条目。

C. DFD 纠错四类（案例填空常客）

  1. 父子图不平衡——子图输入输出与父图对不上
  2. 黑洞——加工只有输入无输出
  3. 奇迹——加工只有输出无输入
  4. 多余连线——外部实体与数据存储直接连线（必须经加工）

绘制四步：画系统输入输出（边缘标出）→ 画内部连处理 → 数据流命名（避免空洞词）→ 加工命名（动宾短语）。

三、Web 高并发 · 四段骨架（过 3 遍）

① 架构填空链（从外到内）

CDN（静态）→ 负载均衡 LB → API 网关（鉴权/路由/限流）→ 应用集群（注册中心）→ Redis 缓存 → MQ 削峰 → 分库分表

⚠️ 动态实时数据不放 CDN，CDN 只放静态资源。

② 负载均衡

  • 四算法：加权轮询（性能差异大）、最少连接（长短混杂）、源地址哈希（会话粘滞）、一致性哈希（扩缩容迁移少）
  • 四层（IP/端口，LVS）vs 七层（HTTP 内容，Nginx）；经典组合 LVS + Nginx

③ 缓存三问题（技术方案论证高频）

问题 场景 对策
穿透 查不存在的 key 布隆过滤器 / 空值缓存
击穿 热点 key 过期瞬间 互斥锁 / 逻辑过期
雪崩 大量 key 同时过期 过期时间加随机抖动 / 多级缓存

④ 业务一致性三连（10 分大题）

  • 防超卖：Redis 原子扣减（Lua/DECR）+ DB 剩余>0 条件更新 + MQ 异步落库削峰
  • 防重复：前端防连点 + 幂等令牌（SETNX）/ 唯一索引（至少写两种）
  • 超时释放（15 分钟未支付）：延迟队列或 Redis ZSet 到期检查 + 支付/取消条件更新 + 对账兜底

四、微服务 · 骨架

① 拆分策略（诊断/建模必写）

按业务能力拆 / 按 DDD 限界上下文拆 / 按变更频率与团队拓扑拆（康威定律）

⚠️ 反面素材：按 UI/API/DB 技术层拆 = 分布式单体，诊断题见此必写。

② 治理五件套（缺一扣分）

  1. 注册发现：实例上下线、健康检查
  2. API 网关：统一鉴权、路由、限流、协议转换
  3. 配置中心：动态配置、灰度发布
  4. 熔断/降级：超时→熔断→降级→限流，依赖故障不拖垮全链路
  5. Service Mesh：流量/安全/可观测下沉 Sidecar

③ 单体 vs 微服务对比五维（论证题万能表）

耦合度 · 独立部署 · 数据一致性 · 运维复杂度 · 团队自治 —— 结论必须回扣题干（工期/遗留系统/峰值流量）

④ 典型诊断句式

  • 拆分过细、链路雪崩 → 熔断+降级+限流+超时重试（幂等前提）
  • 数据不一致 → 最终一致性：本地消息表 / MQ 事务消息 + 对账补偿

五、数据库 · 一条龙套路（选答必拿）

  1. 规范化：找候选键 → 判部分依赖（1NF→2NF）→ 判传递依赖（→3NF）；各举插入/删除/修改异常一例
  2. SQL 填空：DDL 三件 CHECK / PRIMARY KEY / REFERENCES；统计三件 JOIN / GROUP BY / HAVING / ORDER BY
  3. 性能：反规范化三手段（冗余列、派生列、汇总表）+ 一致性保障三句（同一事务更新、触发器、定期对账，缺一扣分）+ 联合索引最左前缀（如 (会员号,预约时间)、(课程号,签到状态)）

六、规划计算 · 公式保底（10 分钟）

公式 写法
静态回收期 累计净现金流由负转正之年：整数年 + 上年缺口/当年净流（如 3 + 30/150 = 3.2 年）
动态回收期 同上但用现值累计（折现后），结果 ≥ 静态回收期
NPV 各年净现金流折现求和 − 初始投资；NPV > 0 → 经济可行
可行性分类 技术 / 经济 / 法律社会 / 操作（用户使用）/ 组织政策
