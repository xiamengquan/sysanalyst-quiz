定义

  • 移动应用系统：是面向智能手机、平板等移动终端、强调弱网络、小屏幕与触控交互的信息系统。作用：用于移动场景下的跨平台交付、应用商店分发与离线/同步等设计决策。
  • MVC（Model-View-Controller）：是将数据模型、界面展示与用户交互控制分离的架构模式。作用：用于降低界面与业务耦合、便于移动端多视图复用同一模型。
  • MVP/MVVM：是 MVC 演进，Presenter/ViewModel 进一步解耦视图与逻辑。作用：用于 Android/iOS 与数据绑定框架选型。
  • 移动 UX 约束：是含触控目标、弱网降级、电量与通知策略。作用：用于案例写非功能需求与架构权衡。

要点

一、场景特征

定义：面向智能手机、平板等移动终端的应用系统，强调跨平台、弱网络、小屏幕、触控交互、应用商店分发。

典型场景：消费类 App、企业移动办公、小程序、H5 轻应用、超级 App（多业务模块聚合）

主流移动研发平台（了解名称与定位即可）：

平台 背景 特点
EMAS / mPaaS 阿里巴巴 全生命周期 DevOps、「双十一」级基础设施
TMF 腾讯 小程序、热修复、移动网关
FinClip 第三方 小程序容器、跨端、灰度发布
APICloud 第三方 跨平台引擎、统一编译、一套代码多端
EMOP 京东 原生/跨端/H5/小程序四框架、组件化

部署平台：App Store、Google Play、企业内部分发、小程序平台、H5 托管

二、架构原则与模式

架构演进阶段

单体应用 → MVC → MVP → MVVM → 微服务
架构 核心思想 适用
MVC Model-View-Controller 分离 传统移动/Web
MVP Presenter 中转，View 被动 可测试性更好
MVVM ViewModel + 数据绑定（Vue/小程序/Angular） 响应式 UI
微服务 独立服务、独立部署（Netflix 案例） 大规模、高可用

Spring MVC 请求流程（Web 移动后端常考）：DispatcherServlet → HandlerMapping → HandlerAdapter → Handler → ViewResolver → 渲染响应

Netflix 微服务模块：用户管理、视频流、推荐、支付、配置管理；Eureka 注册发现、Ribbon 负载、Hystrix 熔断、Zuul 网关

开发方式对比（案例必选考点）

方式 技术 优点 缺点
原生 Native Swift/ObjC(iOS)、Kotlin/Java(Android) 性能最佳、完整硬件 API 双端开发、成本高
Web App HTML5/CSS/JS 跨平台、开发快 性能弱、离线差
混合 Hybrid WebView + 原生桥接 平衡性能与效率 体验略逊原生
小程序 平台 DSL（微信/支付宝等） 免安装、流量入口 平台依赖
Flutter Dart + 自绘引擎 跨端一致 UI 生态较新
桥接 App JS 与原生通信 复用 Web 技能 调试复杂

无代码开发

阶段：表单驱动 → 模型驱动 → 集成自动化

优劣：降低门槛、加速交付 vs 复杂逻辑受限、 vendor 锁定

代表平台：Airtable、Bubble、PowerApps、Zapier（触发器-动作-映射-激活）

流程：需求 → 界面 → 逻辑 → 数据 → 测试调优 → 发布维护

三、开发与测试要点

开发环境

  • App：Xcode(Apple)、Android Studio；Cocoa Touch、CoreData、WebKit
  • 小程序：各平台 IDE（FIDE 等）
  • 网页：DevExtreme 等 HTML5 工具

开发关注点

  • 安全（认证、存储、传输）
  • 性能（启动、内存、网络）
  • 可维护性（模块化、组件化）
  • 测试（单元、UI 自动化、兼容性）
  • 发布与版本更新（灰度、热修复）

测试要点

  • 多设备、多 OS 版本兼容
  • 弱网/断网场景
  • 触控手势、屏幕适配
  • 应用商店审核规则
  • 性能（启动时间、内存、电量）
  • 安全（本地存储、通信加密）
