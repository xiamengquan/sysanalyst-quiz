概述

数据库控制（并发、完整性、安全、备份恢复、优化）：三级模式、关系代数/规范化、事务ACID与并发控制、数据库安全（标识鉴别/授权粒度/视图/审计vs跟踪/备份分类）、ER模型、分布式分片/分片键与跨站点数据共享·持久化、数据仓库/OLAP/挖掘、NoSQL。综合题与选择题均高频。

定义

  • 作用 / 答卷展开：是用于避免出现热点节点（某节点数据量或访问量过大导致瓶颈）与空闲节点（资源浪费），保证整体吞吐与响应稳定。
  • 数据均衡性原则：数据均衡性原则是指分片后各节点的数据量与访问压力应尽可能均匀。作用：用于题干场景下的概念识别、对比选型与案例/论文回扣。
  • 业务相关性原则：业务相关性原则是指分片键与分片边界应紧贴核心业务场景与高频访问路径来设计。作用：用于题干场景下的概念识别、对比选型与案例/论文回扣。
  • 数据分片：数据分片是把逻辑上统一的数据集合按既定规则划分到多个物理节点存储与访问的技术。作用：用于提升容量与并发扩展能力，并支撑故障隔离与按片备份恢复。
  • 分片键：分片键是用于决定一条（或一组）数据路由到哪一个分片的属性或属性组合。作用：用于实现数据定位、均衡分布，并尽量保证主查询路径与事务可在单分片内完成。
  • 跨厅（跨站点）数据共享：跨厅数据共享是指不同业务网点之间能够按统一规则访问与使用同一业务域下的共享数据（如 A 厅取号、B 厅办理时读取原取号记录）。作用：用于支撑跨网点连续办理与实时协同，避免各厅数据孤岛。
  • 数据持久化：数据持久化是将业务数据可靠写入可长期保存的存储介质，并在进程重启、节点故障后仍可恢复访问的能力。作用：用于满足长期保存、审计统计与故障后数据不丢等需求（如排队记录保存 ≥5 年）。

核心知识点/概念

DBMS与三级模式

外模式(用户视图/子模式) ←→ 模式(逻辑/概念模式) ←→ 内模式(存储模式)
         ↑ 外/模式映像              ↑ 模式/内映像
  • 两级独立性：逻辑独立性（模式改变不影响外模式）、物理独立性（内模式改变不影响模式）。
  • 数据模型：概念(ER)、逻辑(关系/网状/层次)、物理。

关系数据库

基本概念：关系、元组、属性、域、码(候选码/主码/外码)、主属性/非主属性。

完整性：

类型 含义
实体完整性 主码非空且唯一
参照完整性 外码要么为空，要么引用存在的主码
用户定义完整性 业务规则约束

关系运算：并、差、交、笛卡儿积、选择(σ)、投影(π)、连接(⋈)、除。

规范化：

范式 要求
1NF 属性不可再分
2NF 1NF + 消除非主属性对码的部分函数依赖
3NF 2NF + 消除非主属性对码的传递函数依赖
BCNF 每个决定因素都是候选码
4NF 消除多值依赖

异常：数据冗余、修改异常、插入异常、删除异常。

并发控制

事务ACID：

特性 含义
Atomicity 原子性，全做或全不做
Consistency 一致性
Isolation 隔离性
Durability 持久性

并发问题：丢失修改、读脏数据、不可重复读。

封锁：X锁(排他)、S锁(共享)；两段锁协议(2PL) 保证可串行化。

封锁协议：一级(改X锁)、二级(读S锁+改X锁，避免脏读)、三级(读S锁到结束，避免不可重复读)。

隔离级别：读未提交、读已提交、可重复读、串行化。

数据库安全性 ★必考

两层实现：DBMS自身措施 + 应用程序控制。

措施 说明
用户标识和鉴别 最外层保护；口令认证、强身份认证(数字证书/智能卡/指纹等)
存取控制(数据授权) 按角色授权；操作类型+数据对象
密码存储和传输 远程终端加密传输
视图保护 通过视图授权，隐藏敏感数据
审计 事后监督，日志长期保存作证据

权限角色三类：数据库登录权限类、资源管理权限类、DBA权限类。

授权粒度（由大到小4级）：数据库级 → 关系级(表) → 元组级(行) → 属性级(列)。

视图：

  • 虚拟关系，存储SELECT语句而非数据本身。
  • 作用：简化查询、逻辑独立、安全控制(限制用户可见列/行)。

审计 vs 跟踪：

对比项 审计 跟踪
目的 安全检查、稽查证据 系统调试分析
保存 长期保存日志 通常不长久保存
时机 事后监督 开发/调试阶段
与认证关系 认证=事前防范 —

备份与恢复 ★必考

按实现方式：

类型 子类 说明
物理备份 冷备份(静态) 关闭DB，复制文件；最快最安全，备份期间不可用
热备份(动态) 运行中备份；可用但需日志配合
逻辑备份 — exp/imp等工具；适合小库，大库慢

按数据量：

类型 备份内容
完全备份 整个数据库
增量备份 上次任意备份后变化的数据
差异备份 上次完全备份后变化的所有数据

组合策略：通常1次完全 + 多次增量/差异。

日志文件：记录每次更新；热备份必须配合日志；恢复时 Redo(重做已提交) + Undo(撤销未完成)。

故障恢复：

故障类型 恢复方法
事务故障 撤销(Rollback)
系统故障 日志Redo/Undo
介质故障 后援副本+日志

数据库设计

6阶段：需求分析 → 概念设计(ER) → 逻辑设计 → 物理设计 → 实现 → 运行维护。

ER模型：实体、属性、联系(1:1/1:n/m:n)；冲突(属性/命名/结构)；集成(一次/逐步)。

ER转关系规则：

  • 实体→关系；1:1可合并；1:n合并到n端或独立；m:n→独立关系+两端主码。

分布式数据库

  • 分片：水平(行)、垂直(列)；完备性、重构性、不相交性（见下「分片正确性」）。
  • 复制：提高可用性和性能。
  • 透明性：分片、位置、局部、重复、事务。

分布式数据库分片设计的核心原则（答卷·必背）

案例常问「说明分片设计的核心原则（至少 2 个）」——优先答下面三条设计原则；勿与「完备性 / 重构性 / 不相交性」混淆（后者是分片结果正确性准则）。

原则（答卷写全名） 一句话抓手
数据均衡性原则 量与压均匀，防热点/空闲
业务相关性原则 键贴业务与主查询，少跨片
可扩展性原则 能加节点横向扩，少重构少停机

分片正确性准则（易混·教程原文，非上述三条的替身）

准则 含义
完备性 全局关系的每个数据项必属于某个分片
重构性 各分片可重构回原全局关系
不相交性 水平分片时各片数据一般不重叠（复制策略除外）

分片键与跨厅共享 / 数据持久化（答卷·案例高频）

写法：定义用「X 是……」，作用用「用于……」。政务多网点「跨厅办理」属跨站点业务共享场景，答卷扣题干用「跨厅」，概念表述可用「跨站点 / 跨分片可定位」。

水平分片 / 垂直分片（答卷）
水平分片是按行（元组）划分，使同一表的不同行落到不同节点；垂直分片是按列（属性）划分，使同一表的不同列组落到不同节点。

选分片键时首要考虑（答卷）
数据均匀度、与主查询模式匹配、事务尽量单分片、以及后续扩容 / 再分片能力。（勿只选“更新最少的列”或忽略跨分片事务。）

组合分片键（答卷·场景例）
当存在多网点（如多政务分厅）且按业务类型办理时，可采用业务类型 + 分厅 ID 组合分片键：以业务类型作为主维度形成逻辑组，以分厅 ID 作为副维度分散存储，便于同业务跨厅定位原记录。

应试

案例可能怎么问：给定业务表与函数依赖，要求判断范式级别并分解至 3NF/BCNF；或给出并发/死锁场景，选隔离级别与加锁策略；备份恢复题常考「完全+增量/差异」组合与 RPO 对应关系；分布式库案例常考「分片设计核心原则（至少 2 个）」——答数据均衡性、业务相关性、可扩展性并稍作展开；再问分片键选型，回扣「跨厅/跨站点共享」与「长期持久化/审计保存」。

论文怎么用：数据迁移/多源集成类（23上、24上）可写「源库→中间层→目标库」割接步骤、一致性校验与回滚；OLTP/OLAP 分离、读写分离、缓存与索引优化可作为性能段落素材；多网点政务/连锁类可写分片键与故障隔离。

常考结论

  • 授权粒度：库→表→行→列（4级，由大到小）。

  • 审计=事后；标识鉴别=事前。

  • ACID：原一隔持。

  • 范式递进：1→2→3→BCNF→4NF。

  • 备份口诀：物逻分，冷热全增异。

  • 增量备份基于"上次任意备份"，差异备份基于"上次完全备份"（易混！）。

  • 分片设计原则口诀：均衡、相关、可扩展（写全名：数据均衡性 / 业务相关性 / 可扩展性）。

  • 分片正确性准则：完备、重构、不相交（勿与上条混答）。
