概述

开发框架（Java EE、.NET、Web 层）：HTTP 无状态（答卷·定义）：HTTP 是无连接、无状态的请求-响应协议，服务器默认不保留客户端历史请求上下文；用于简化服务器设计，但跨请求的用户状态须借助 Session/Cookie 等机制维护。

速懂

  • 一句话：数据库连接池是复用连接以降低建立开销的机制。
  • 考什么：Web 峰值、缓存限流、B/S 与 MVC（教程第 16 章）。
  • 具体理解：
    • 先背定义节「是什么 + 作用」，再展开要点中的表格或口诀。
  • 别搞混：题干锚词：开发框架 / EE / NET。

定义

  • 数据库连接池：是复用连接以降低建立开销的机制。作用：用于 Web 高并发访问性能。
  • ORM 框架：是用对象映射关系表，简化 CRUD。作用：用于开发效率与 SQL 注入防护（参数化）。
  • 读写分离：是主库写、从库读的水平扩展模式。作用：用于提升读性能与可用性。
  • 缓存（Redis 等）：是热点数据内存加速层。作用：用于降低 DB 压力与会话管理。

Session（答卷·定义）：Session 是服务器端为识别同一用户会话而维护的状态存储机制，通常通过 Session ID（常存于 Cookie）关联；用于在无状态 HTTP 之上跟踪登录态、购物车等跨请求业务状态。

案例三件套（审计通过 v0.19 · 依据 case-map 真题蒸馏）

  • 怎么考：技术选型题给出候选框架组合（Struts/Spring/Hibernate 或 Spring Boot + 前后端分离），问选型理由与各层职责。
  • 怎么答：分层职责按链路誊写——浏览器（表现交互）→ Controller 层（请求调度与输入校验）→ Business 层（业务逻辑）→ DAO 层（数据访问）→ 数据库（持久化）；选型理由写「与团队技能和现有系统兼容、生态成熟、文档与社区支持完善、可平滑扩展」，并逐条回扣题干约束（如与 ERP 兼容、团队熟悉度）。
  • 易错与扣分：分层职责张冠李戴（把业务逻辑写进 DAO、把持久化写进 Controller）；只报框架名不写分层对应关系；忽略题干明示的兼容性与团队约束。
