速懂

  • 一句话：系统规划是信息系统生命周期第一阶段，在既定约束下分析系统建设的必要性与可能性的工作。
  • 考什么：可行性四维、DFD、规划方法 BSP/CSF（教程第 10 章）。
  • 具体理解：
    • 制定系统建设方案 → 系统设计任务书
    • 平衡选择——“合适”优于“最好”，超出目标的“好”往往意味着更高成本或风险
    • 按实际处理步骤绘制，“流水账”式
    • 行为符号：圆圈表示工作步骤；达到职能分解层时圆圈外加方框
  • 别搞混：题干锚词：系统规划概述。

定义

  • 系统规划：系统规划是信息系统生命周期第一阶段，在既定约束下分析系统建设的必要性与可能性的工作。作用：用于主要作用是输出可行性研究报告与系统设计任务书，为后续系统分析、设计与实施确立目标与边界。
  • 系统分析：系统分析是在系统规划基础上，与用户配合对现行系统进行全面调查与分析，确定新系统逻辑需求的工作。作用：用于主要作用是找出业务瓶颈、明确新系统应实现的逻辑功能，并输出系统需求规格说明书。
  • 数据流图 DFD：数据流图是用外部实体、加工、数据流、数据存储四种基本元素描述系统中数据流动与处理过程的图形化模型。作用：主要用于在系统分析阶段表达系统的逻辑功能与数据加工路径，为分层分解、需求确认与后续设计提供依据。
  • 上下文图 / 0 层图：上下文图（即 0 层图）是数据流图的最顶层，仅含一个代表整个系统的加工及其与外部实体之间的数据流。作用：用于界定系统边界、明确系统与外部环境的信息交换关系，是 DFD 自顶向下分解的起点。

步骤与流程

项目整体管理步骤（案例常写）

  1. 章程/启动：明确目标、干系人、授权。
  2. 规划：范围、WBS、进度、成本、质量、风险、沟通。
  3. 执行：按计划交付，协调资源。
  4. 监控：挣值、变更控制、风险跟踪。
  5. 收尾：验收、文档归档、经验教训。

要点

二、核心知识点

系统规划

定位：信息系统生命周期第一阶段；在约束下分析建设必要性与可能性，输出可行性研究报告与系统设计任务书。

系统规划六步骤：

  1. 对现有系统进行初步调查
  2. 分析和确定系统目标
  3. 分析子系统的组成和基本功能
  4. 拟定系统的实施方案（含优先级）
  5. 进行系统的可行性研究
  6. 制定系统建设方案 → 系统设计任务书

项目提出与选择

立项动机四类：

类型 目标 特点
基础研究 开拓未来市场、建立竞争优势 长期战略、探索性、无严格产品目标
应用研发 占有市场、获取利润 有明确研发目标、严格时间与预算
提供技术服务 咨询、集成、定制、升级 面向特定行业、综合解决方案
产品使用者 通过采购获得使用价值 采购或定制，关注使用、影响与代价

项目选择五原则：

  1. 选择有核心价值的项目（与核心业务相关）
  2. 评估约束、风险、成本与效益
  3. 项目优先级排序（净现值、投资回收期等指标）
  4. 评估多种实施方式（自建/承包/购买/外包）
  5. 平衡选择——“合适”优于“最好”，超出目标的“好”往往意味着更高成本或风险

项目约束：开发过程中“不能做什么”的原则（客户/企业/环境/用户约束）。

方案权衡常见矛盾：技术风险、用户锁定性、扩展性、目标偏离。

系统分析

任务：在规划基础上与用户配合，全面调查分析，找出瓶颈，确定新系统逻辑功能，输出系统需求规格说明书。

三大难点：

  1. 分析师与用户理解不同（业务 vs IT）
  2. 沟通困难导致遗漏与误解
  3. 环境不断变化，边界锁定困难

问题分析

研究问题领域：了解当前系统；项目经理领导，资深系统分析师主持。

上下文图（环境图/系统图）绘制五步骤：

  1. 确定系统边界
  2. 识别外部实体
  3. 识别过程
  4. 绘制上下文图
  5. 验证上下文图

因果分析要点：先分析原因和结果，再陈述问题；避免直接说“我们需要……”而把方案当问题。

系统改进目标约束四类：进度、成本、技术、政策。

业务流程分析

目的：明确职能在各部门如何完成、信息处理细节，为流程改造与数据流程分析提供依据。

分析步骤：调查 → 描述现有流程 → 确认 → 分析 → 提出方案 → 优化流程。

五种分析方法：

方法 核心视角
价值链分析法 基本活动 vs 辅助活动，找核心竞争力
客户关系分析法 CRA 以客户与企业的关系、客户行为为依据
供应链分析法 SCM 内外部供应链，找核心环节
基于 ERP 的分析法 供应链一体化、资源集成优化
业务流程重组 BPR 以顾客满意为出发点，价值链分解整合

三、业务流程图 TFD（重点）

基本符号（6种）

符号 含义
圆圈 业务处理单位
矩形框 对业务处理的描述
报表符号 输出信息（报表、报告、文件、图形）
不封口方框 存储文件
卡片符号 收集资料
矢量连线 业务过程联系（物流或信息流）

TFD 特点

  • 按实际处理步骤绘制，“流水账”式
  • 符号简单，易读；对专业细节表现力弱
  • 适用于事务处理型业务
  • 内部实体参与信息处理；外部实体仅传递/接收信息（如供货单位、有关部门）

BAM 业务活动图

  • 行为符号：圆圈表示工作步骤；达到职能分解层时圆圈外加方框
  • 决策符号：圆圈边上加菱形
  • 编号：分层编号（如 1.0、1.1、1.2）
  • 应用：流程识别、描述新流程、实施优化

BPM 与建模语言（了解）

BPM 三要素：实体、对象、活动。建模语言分文本类（BPEL/XPDL，可执行）和图元类（BPMN/UML 活动图，直观；BPMN 可生成 BPEL）。

四、数据流图 DFD（超高频考点）

四种基本符号

| 符号 | 图形 | 含义 | | 外部实体 | 矩形 | 系统外人员、设备、其他系统 | | 进程/加工 | 圆角矩形 | 功能模块或处理过程 | | 数据存储 | 开口矩形（长方形） | 文件、数据库等 | | 数据流 | 带箭头实线 | 数据流动方向与内容 |

要素 定义（是……） 作用（用于……）
外部实体 外部实体是系统边界之外、与系统发生信息交换的人员、设备或其他系统。 用于表示系统与外部环境的交互端点，界定系统范围。
加工（进程） 加工是对输入数据进行处理并产生输出数据的功能模块或处理过程。 用于描述系统的逻辑功能单元及数据变换环节。
数据流 数据流是携带特定含义的数据在加工、外部实体与数据存储之间的有向流动。 用于表达数据的传递方向、来源与去向。
数据存储 数据存储是系统内以文件、数据库等形式持久保存数据的逻辑容器。 用于表示数据的暂存或持久化位置，支撑读/写数据流。

禁止：DFD 中不可夹带控制流（可加入物质流辅助理解）。

数据流内涵五要素

数据源 → 数据传输 → 数据转换 → 数据存储 → 数据输出

逻辑数据流与数据流守恒

逻辑数据流：数据在逻辑上的流动路径与处理方式。

守恒原则（考试判断题）：

  1. 输入 = 输出（无增删时）
  2. 输出 = 输入 + 增量（更新/修改）
  3. 处理前 = 处理后 + 丢失量（删除/移除）

DFD 绘制规则（必背）

  1. 仅 4 种基本元素，每个元素必须有名字
  2. 每个加工至少一个输入、一个输出；保持数据守恒
  3. 按层给加工编号
  4. 子图与上一层一个加工对应，输入输出数据流一致
  5. 每个数据存储必须有读和写的数据流
  6. 可加入物质流，不可夹带控制流

上下文图与分层

  • 0 层图（上下文图）：系统与外部实体的关系，界定系统范围
  • 自顶向下逐层分解，平衡原则：子图与父图加工对应
  • 物理 DFD：含具体实现细节；逻辑 DFD：抽象功能，不含实现

SA 方法与 DFD 的关系

  1. 建立当前系统具体模型（现状 DFD）
  2. 抽象出逻辑模型
  3. 建立目标系统逻辑模型（修改后的 DFD）
