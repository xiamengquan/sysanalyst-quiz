二、核心知识点

2.1 系统规划

系统规划（答卷·定义）：系统规划是信息系统生命周期第一阶段，在既定约束下分析系统建设的必要性与可能性的工作。

系统规划（答卷·作用）：主要作用是输出可行性研究报告与系统设计任务书，为后续系统分析、设计与实施确立目标与边界。

定位：信息系统生命周期第一阶段；在约束下分析建设必要性与可能性，输出可行性研究报告与系统设计任务书。

系统规划六步骤：

  1. 对现有系统进行初步调查
  2. 分析和确定系统目标
  3. 分析子系统的组成和基本功能
  4. 拟定系统的实施方案（含优先级）
  5. 进行系统的可行性研究
  6. 制定系统建设方案 → 系统设计任务书

2.2 项目提出与选择

立项动机四类：

类型 目标 特点
基础研究 开拓未来市场、建立竞争优势 长期战略、探索性、无严格产品目标
应用研发 占有市场、获取利润 有明确研发目标、严格时间与预算
提供技术服务 咨询、集成、定制、升级 面向特定行业、综合解决方案
产品使用者 通过采购获得使用价值 采购或定制，关注使用、影响与代价

项目选择五原则：

  1. 选择有核心价值的项目（与核心业务相关）
  2. 评估约束、风险、成本与效益
  3. 项目优先级排序（净现值、投资回收期等指标）
  4. 评估多种实施方式（自建/承包/购买/外包）
  5. 平衡选择——“合适”优于“最好”，超出目标的“好”往往意味着更高成本或风险

项目约束：开发过程中“不能做什么”的原则（客户/企业/环境/用户约束）。

方案权衡常见矛盾：技术风险、用户锁定性、扩展性、目标偏离。

2.3 系统分析

系统分析（答卷·定义）：系统分析是在系统规划基础上，与用户配合对现行系统进行全面调查与分析，确定新系统逻辑需求的工作。

系统分析（答卷·作用）：主要作用是找出业务瓶颈、明确新系统应实现的逻辑功能，并输出系统需求规格说明书。

任务：在规划基础上与用户配合，全面调查分析，找出瓶颈，确定新系统逻辑功能，输出系统需求规格说明书。

三大难点：

  1. 分析师与用户理解不同（业务 vs IT）
  2. 沟通困难导致遗漏与误解
  3. 环境不断变化，边界锁定困难

2.4 问题分析

研究问题领域：了解当前系统；项目经理领导，资深系统分析师主持。

上下文图（环境图/系统图）绘制五步骤：

  1. 确定系统边界
  2. 识别外部实体
  3. 识别过程
  4. 绘制上下文图
  5. 验证上下文图

因果分析要点：先分析原因和结果，再陈述问题；避免直接说“我们需要……”而把方案当问题。

系统改进目标约束四类：进度、成本、技术、政策。

2.5 业务流程分析

目的：明确职能在各部门如何完成、信息处理细节，为流程改造与数据流程分析提供依据。

分析步骤：调查 → 描述现有流程 → 确认 → 分析 → 提出方案 → 优化流程。

五种分析方法：

方法 核心视角
价值链分析法 基本活动 vs 辅助活动，找核心竞争力
客户关系分析法 CRA 以客户与企业的关系、客户行为为依据
供应链分析法 SCM 内外部供应链，找核心环节
基于 ERP 的分析法 供应链一体化、资源集成优化
业务流程重组 BPR 以顾客满意为出发点，价值链分解整合

三、业务流程图 TFD（重点）

3.1 基本符号（6种）

符号 含义
圆圈 业务处理单位
矩形框 对业务处理的描述
报表符号 输出信息（报表、报告、文件、图形）
不封口方框 存储文件
卡片符号 收集资料
矢量连线 业务过程联系（物流或信息流）

3.2 TFD 特点

  • 按实际处理步骤绘制，“流水账”式
  • 符号简单，易读；对专业细节表现力弱
  • 适用于事务处理型业务
  • 内部实体参与信息处理；外部实体仅传递/接收信息（如供货单位、有关部门）

3.3 BAM 业务活动图

  • 行为符号：圆圈表示工作步骤；达到职能分解层时圆圈外加方框
  • 决策符号：圆圈边上加菱形
  • 编号：分层编号（如 1.0、1.1、1.2）
  • 应用：流程识别、描述新流程、实施优化

3.4 BPM 与建模语言（了解）

BPM 三要素：实体、对象、活动。建模语言分文本类（BPEL/XPDL，可执行）和图元类（BPMN/UML 活动图，直观；BPMN 可生成 BPEL）。

四、数据流图 DFD（超高频考点）

数据流图 DFD（答卷·定义）：数据流图是用外部实体、加工、数据流、数据存储四种基本元素描述系统中数据流动与处理过程的图形化模型。

数据流图 DFD（答卷·作用）：主要用于在系统分析阶段表达系统的逻辑功能与数据加工路径，为分层分解、需求确认与后续设计提供依据。

上下文图 / 0 层图（答卷·定义）：上下文图（即 0 层图）是数据流图的最顶层，仅含一个代表整个系统的加工及其与外部实体之间的数据流。

上下文图 / 0 层图（答卷·作用）：用于界定系统边界、明确系统与外部环境的信息交换关系，是 DFD 自顶向下分解的起点。

4.1 四种基本符号

符号 图形 含义
外部实体 矩形 系统外人员、设备、其他系统
进程/加工 圆角矩形 功能模块或处理过程
数据存储 开口矩形（长方形） 文件、数据库等
数据流 带箭头实线 数据流动方向与内容

DFD 四要素（答卷·必背）：

要素 定义（是……） 作用（用于……）
外部实体 外部实体是系统边界之外、与系统发生信息交换的人员、设备或其他系统。 用于表示系统与外部环境的交互端点，界定系统范围。
加工（进程） 加工是对输入数据进行处理并产生输出数据的功能模块或处理过程。 用于描述系统的逻辑功能单元及数据变换环节。
数据流 数据流是携带特定含义的数据在加工、外部实体与数据存储之间的有向流动。 用于表达数据的传递方向、来源与去向。
数据存储 数据存储是系统内以文件、数据库等形式持久保存数据的逻辑容器。 用于表示数据的暂存或持久化位置，支撑读/写数据流。

禁止：DFD 中不可夹带控制流（可加入物质流辅助理解）。

4.2 数据流内涵五要素

数据源 → 数据传输 → 数据转换 → 数据存储 → 数据输出

4.3 逻辑数据流与数据流守恒

逻辑数据流：数据在逻辑上的流动路径与处理方式。

守恒原则（考试判断题）：

  1. 输入 = 输出（无增删时）
  2. 输出 = 输入 + 增量（更新/修改）
  3. 处理前 = 处理后 + 丢失量（删除/移除）

4.4 DFD 绘制规则（必背）

  1. 仅 4 种基本元素，每个元素必须有名字
  2. 每个加工至少一个输入、一个输出；保持数据守恒
  3. 按层给加工编号
  4. 子图与上一层一个加工对应，输入输出数据流一致
  5. 每个数据存储必须有读和写的数据流
  6. 可加入物质流，不可夹带控制流

4.5 上下文图与分层

  • 0 层图（上下文图）：系统与外部实体的关系，界定系统范围
  • 自顶向下逐层分解，平衡原则：子图与父图加工对应
  • 物理 DFD：含具体实现细节；逻辑 DFD：抽象功能，不含实现

4.6 SA 方法与 DFD 的关系

  1. 建立当前系统具体模型（现状 DFD）
  2. 抽象出逻辑模型
  3. 建立目标系统逻辑模型（修改后的 DFD）

RTSAD 衔接：实时结构化分析还常问环境模型 / 行为模型（基本模型组成部分）及设计侧的模块内聚 / 耦合。答卷句见 速查/结构化与面向对象分析-体系化学习路径.md §3.8、第13章-系统设计.md §3.1。

五、系统可行性分析

可行性分析（答卷·定义）：可行性分析是对拟建信息系统从必要性与可能性两方面进行论证与评价的工作。

可行性分析（答卷·作用）：主要作用是为项目立项、方案选择与投资决策提供依据，避免盲目建设或技术不可行。

5.1 必要性与可能性

可行性 = 必要性 + 可能性。

5.2 四维评价（GB/T 8567—2006）

维度 别名 考查内容
经济可行性 投资收益/成本效益 建设/运行成本 vs 收益；项目底线
技术可行性 技术风险分析 技术能力、资源、目标是否匹配
法律可行性 社会可行性 政策、法律、道德、制度
用户使用可行性 执行可行性 管理可行性 + 运行可行性

四维可行性（答卷·必背）：

维度 定义（是……） 作用（用于……）
经济可行性 经济可行性是从建设成本、运行成本与预期收益角度评价项目是否值得投资。 用于判断项目的成本效益与财务底线，是可行性评价的项目底线。
技术可行性 技术可行性是评估现有技术能力、资源与手段能否满足系统功能与性能目标。 用于识别技术风险，判断方案在技术上是否可实现、可支撑。
法律可行性 法律可行性是审查项目建设与运行是否符合国家政策、法律法规及道德规范（教程亦称社会可行性）。 用于规避合规风险，确保项目合法、可落地。
用户使用可行性 用户使用可行性是评估组织管理条件与人员运行能力能否保障系统顺利实施与持续使用（含管理可行性与运行可行性）。 用于判断系统能否被用户接受、有效运行并产生预期效益。

管理可行性：领导支持、管理制度、改革时机。

运行可行性：人员 IT 技能、数据采集质量、对组织/流程/地点/经费的影响。

补充：进度可行性——能否在期限内完成。

5.3 可行性研究八步骤

  1. 复查系统目标和规模
  2. 分析现有系统（高层流程图、接口）
  3. 导出新系统高层逻辑模型（上下文图、E-R、用例、领域模型、IPO）
  4. 用户复核（前 4 步循环直至确认）
  5. 提出并评价解决方案（候选方案矩阵、可行性分析矩阵）
  6. 确定最终推荐方案（完善成本效益分析）
  7. 草拟开发计划
  8. 编制并提交可行性研究报告 → 可行性论证会

六、成本效益分析（计算题重点）

6.1 成本分类

按投资时间 按成本性态
基础建设投资、其他一次性投资、非一次性投资 固定成本、变动成本、混合成本

6.2 收益分类

  • 有形/无形；一次性/非一次性；可定量/不可定量
  • 有形收益可用 NPV、回收期、投资回收率度量

6.3 盈亏临界分析

利润 = (销售单价 - 单位变动成本) × 销售量 - 总固定成本

盈亏临界点销售量 = 总固定成本 / (销售单价 - 单位变动成本)

盈亏临界点销售额 = 总固定成本 / (1 - 总变动成本/销售收入)

含义：预期销售额接近盈亏临界点 → 项目几乎无利润；临界点越低 → 抗风险能力越强。

6.4 货币时间价值

单利：F = P(1 + i×n)

复利：F = P(1 + i)ⁿ

折现（现值）：P = F / (1 + i)ⁿ
折现系数 = 1 / (1 + i)ⁿ

6.5 净现值 NPV

NPV = Σ(CI - CO)ₜ / (1 + i)ᵗ
NPV 值 含义
= 0 达到基准收益率
> 0 可行，有超额收益
< 0 不可行

多方案比较：投资额、时间相同 → NPV 越大越好。

内部报酬率 IRR：使 NPV = 0 的折现率 i。

折现率影响：i 越高 → NPV 越小 → 越难通过评价。

6.6 净现值率 NPVR

NPVR = NPV / 投资现值 P
  • 效率型指标：单位投资带来的净现值
  • 资金有限时，不能只看 NPV 绝对值，需结合 NPVR
  • NPV ≥ 0 ⟺ NPVR ≥ 0（单一方案）

6.7 投资回收期

静态回收期：不考虑货币时间价值
使 Σ(CI - CO)ₜ = 0 的 T

动态回收期：考虑折现
使 Σ(CI - CO)ₜ / (1 + i)ᵗ = 0 的 T

实用公式（累计净现金流由负转正）：
回收期 = (T - 1) + |第 T-1 年累计| / 第 T 年净现金流

投资回收率（ROI 近似）：

投资回收率 = 1 / 动态投资回收期 × 100%

原则：回收期越短越好，风险越低。

七、第10章易混对比表

对比项 A B
TFD vs DFD 业务“流水账”，6种符号 系统功能，4种符号，分层分解
逻辑 DFD vs 物理 DFD 逻辑 DFD 是描述系统应做什么的抽象功能模型，不含具体实现细节。 物理 DFD 是描述系统如何实现的模型，含具体技术、设备与存储等实现细节；前者用于需求分析，后者用于设计与实现衔接。
0 层图（上下文图）vs 1 层图 0 层图即上下文图：仅含一个代表整系统的加工及与外部实体的数据流，用于界定系统边界。 1 层图将系统分解为若干主要加工并展开数据流，用于描述系统内部功能结构；二者是上下层关系，不是对立概念。
内部实体 vs 外部实体（TFD） 参与处理 仅传递/接收信息
经济 vs 技术可行性 成本效益，底线 功能性能、技术资源
管理 vs 运行可行性 组织、制度、领导 人员技能、操作、业务影响
静态 vs 动态回收期 不考虑时间价值 折现后计算
NPV vs NPVR 绝对收益 投资效率

应试钩子

案例可能怎么问：TFD/DFD 符号识别与分层改错（守恒、外部实体、数据存储）；四维可行性缺项补全；NPV/回收期/盈亏平衡计算与方案比选结论。

论文怎么用：可行性分析、业务流程、成本效益（23上/24下/25下）——用「现状痛点→候选方案→经济/技术/管理可行性→NPV 或 ROI 结论」结构；BPR/流程再造可写 AS-IS/TO-BE 与 KPI 改进。
