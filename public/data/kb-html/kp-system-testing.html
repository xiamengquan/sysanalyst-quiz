定义

  • 验证 Verification：验证是检验软件实现是否正确地满足规格说明与设计文档的 V&V 活动（「是否正确地构建了产品」）。作用：主要用于对照需求规格、设计文档检验各阶段产出是否「做对了实现」——如代码审查、单元测试、集成测试中的规格符合性检查。
  • 确认 Validation：确认是判定软件是否满足用户真实需求与使用场景的 V&V 活动（「是否构建了正确的产品」）。作用：主要用于对照用户期望与业务目标检验系统是否「做了正确的事」——如用户验收测试、Beta 测试、原型确认。

步骤与流程

测试层次顺序（V 模型对应）

单元测试 → 集成测试 → 系统测试 → 验收测试。

典型测试流程

  1. 依据需求/设计编写测试计划与用例。
  2. 执行测试并记录缺陷。
  3. 回归测试验证修复。
  4. 出具测试报告，作为发布/验收依据。

要点

3.3 验证与确认 V&V（答卷·必背）

V&V 与测试阶段对应（助记，不当答卷正文）：验证偏开发侧各阶段；确认偏用户侧验收；系统测试偏验证，验收测试偏确认。

易混辨析

对比 区别
系统 vs 验收 系统测试由测试方依据需求规格做技术验证；验收测试由用户或第三方依据合同做交付前接受确认

应试

案例可能怎么问：按阶段（单元/集成/系统/验收）匹配方法、依据与执行者；白盒覆盖标准由弱到强选型或计算；性能题区分负载/压力/并发；Alpha/Beta 验收场景判断；变更后应安排回归测试；V&V 题区分「对照规格」与「对照用户需求」。

论文怎么用：测试为近五年最高频带——写「测试策略（静态+动态）→阶段分工→自动化/CI 嵌入→缺陷与质量度量→改进闭环」；性能测试、DevOps 流水线中的质量门禁、回归测试策略可直接套用本章分层；V&V 可嵌入「需求→设计→实现→验收」各阶段质量保障叙述。
