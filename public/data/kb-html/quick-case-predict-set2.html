试题一（必答 · 25 分）· 居家养老 · OO 建模

场景关键词：老人 / 家属 / 服务人员；健康档案；服务订单与明细；智能手环；派单。

问题 1（8 分）· 类图

  • (1)(2) 判 组合：部分随整体生命周期销毁（档案随老人注销；明细不能脱离订单）。
  • (3) 判 关联：订单明细 ↔ 服务项目，各自独立存在。
  • (4) 判 聚合：手环可收回再分配给另一位老人。
  • (5)(6) 多重性 1..*（家属↔老人：至少 1 名家属；一名家属可关注多位老人）——写在对方端，勿写反。
  • (7) 老人—订单 0..*；（8）明细—服务项目 1。

回链考点：UML 指南 · 类图关系 · 考点 API kp-面向对象技术 · kp-7-4（类图）

问题 2（8 分）· 活动图

  • 填空：分支 = 审核是否完整；分叉 / 汇合 = 并发粗横线；后续 评价服务。
  • 口述区别：分叉/汇合 = 同时做；分支/合并 = 选一个做（菱形）。
  • 泳道：按角色/对象划分活动，看清职责与跨角色交接。

回链考点：kp-7-5（活动图）· kp-7-6（状态图/活动对比时一并复习）

问题 3（9 分）· 设计原则

  • ① 开闭 · ② 单一职责 · ③ 依赖倒置 · ④ 接口隔离 · ⑤ 违反里氏替换 · ⑥ 迪米特 · ⑦ 合成复用。
  • ⑤ 改法：子类不能削弱父类行为；计费改为 策略对象 或调整继承体系，避免 VIP 重写后抛异常导致替换失败。

回链考点：kp-7-7 · UML 指南 · 设计原则小节

试题一 · 30 分钟练笔步骤

  1. 读说明 6 条业务规则 → 在草稿上画关系与多重性（2 min）。
  2. 看活动图（PDF 原图）填空 + 写分叉/泳道区别（8 min）。
  3. 原则题 先写原则名再写一句依据；⑤ 必须写 修改方案（15 min）。
  4. 对照下方「易错」扫一遍（5 min）。

易错：组合 vs 聚合只看 生命周期；开闭（怎么扩展）≠ 依赖倒置（依赖抽象）。

试题二（选答 · 25 分）· 一网通办 · 规划与 BPR

问题 1（6 分）· 可行性分类

  • ① 经济 · ② 技术 · ③ 法律/社会 · ④ 操作/用户使用 · ⑤ 组织与政策（仍归社会/法律层面，非技术）· ⑥ 技术（团队能力与工期）。

问题 2（10 分）· 成本效益

  • 静态回收期：累计净现金流由负转正年 = 3 + 30/150 = 3.2 年（写清公式）。
  • 动态回收期：用现值累计，约 3.93 年（应 ≥ 静态）。
  • NPV（10%）：≈ 100.62 万 > 0 → 经济可行。

问题 3（9 分）· BPR

  • 流程填空：一窗受理 → 数据共享交换平台 → 统一出件 → 电子监察（以 PDF 图 3 为准）。
  • BPR 关键词：根本性、彻底性、以顾客/申请人为中心；本案例：并联、一次采集、串改并、信息推送。

回链考点：kp-系统计划和分析 · kp-4-2（BSP/CSF/SST）· 案例分析答题教程 § 规划类

站内加练：案例库 规划/需求 领域限时 1 套；综合知识 NPV/回收期 计算题速刷。

试题三（选答 · 25 分）· 健身预约 · 数据库

问题 1（9 分）· 规范化

  • 候选键 (会员号, 课程号)；最高 1NF（有部分依赖 → 非 2NF）。
  • 各举 插入 / 删除 / 修改 异常一例（教练姓名不一致 = 修改异常）。
  • 分解 3NF：会员、教练、课程、预约 四表 + 主键/外键标清。

问题 2（7 分）· SQL

  • DDL：(a) CHECK · (b) PRIMARY KEY · (c) REFERENCES。
  • 统计：(d) JOIN · (e) GROUP BY · (f) HAVING（筛签到率）· (g) ORDER BY。

问题 3（9 分）· 性能

  • 反规范化：冗余列 / 派生列 / 汇总表 等；列表建议 教练姓名冗余 + 已预约人数派生。
  • 一致性：同一事务更新、触发器、定期对账（缺一不可，否则扣分）。
  • 索引：(会员号, 预约时间)；(课程号, 签到状态) + 最左前缀（仅查签到状态无法用后者）。

回链考点：第 5 章考点群 kp-3-* · kp-数据管理-分析-建模-管理-应用

试题四（选答 · 25 分）· 预约挂号 · 高并发 Web

问题 1（7 分）· 架构填空

  • CDN（静态）· LB · API 网关 · Redis · MQ · 分库分表 · 注册中心（动态服务）。
  • 勿把动态号源放 CDN。

问题 2（8 分）· 负载均衡

  • ① 加权轮询 · ② 最少连接 · ③ 源地址哈希（会话粘滞）· ④ 一致性哈希（扩缩容少迁移）。
  • 四层（IP/端口）vs 七层（HTTP 内容）；常见 LVS + Nginx 组合。

问题 3（10 分）· 业务一致性

  • 防超卖：Redis 原子扣减（Lua/DECR）+ DB 剩余>0 条件更新；MQ 异步落库削峰。
  • 防重复：前端防连点 + 幂等令牌 / SETNX / 唯一索引（至少写两种）。
  • 15 分钟释放：延迟队列或 Redis ZSet + 到期检查；支付与取消 条件更新；对账兜底。

回链考点：kp-cloud-computing · kp-microservices · kp-app-service-integration · Web+Agent 卡（LB/中间件表述可对齐）

试题五（选答 · 25 分）· 燃气管网 · 云边端

问题 1（8 分）· OS 选型

  • 四维对比：硬实时 / 资源 / 生态 / 认证。
  • 终端 RTOS（电池、1 秒告警、功能单一）· 网关嵌入式 Linux（多容器、协议转换、市电）。

问题 2（9 分）· 架构与 MQTT

  • 终端 RTOS · 网关 Linux · 边缘规则 · MQTT Broker · 时序库（非数仓）· NB-IoT/LoRa · OTA。
  • 告警 QoS 1（至少一次，可去重）；QoS 0 可能丢；QoS 2 开销大。

问题 3（8 分）· 低功耗与 OTA

  • 低功耗 ≥4：深度休眠、事件驱动上报、PSM/eDRX、本地预处理、DVFS、低功耗器件 等。
  • OTA ≥4：签名验签、TLS、差分、断点续传、A/B 回滚、安全启动、灰度、电量检查。

回链考点：kp-CPS-物联网 · kp-6-1-2 · kp-实时系统开发
