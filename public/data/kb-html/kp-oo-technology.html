面向对象技术

大纲：第7章 UML、第11/13章 · 教程：第7章 · 分组：科目3 · 1. 信息系统开发及应用 · 状态：工坊精修 v1.3.4 · 审计通过

概述

面向对象技术 属本科目大纲考点，侧重概念辨析与案例/论文回扣。

速懂

  • 一句话：面向对象技术：是以对象为基本单元组织软件，通过类、封装、继承与多态表达问题域的分析、设计与实现方法。作用：用于提高软件的复用性、可维护性与对变化的适应能力。
  • 考什么：开发模型选型、UML、过程改进（教程第 7 章）。
  • 具体理解：
    • 依赖 Dependency：客户端元素依赖供应者元素，供应者变更可能影响客户端；非结构性、较弱，常用于使用、创建、调用、导入等。作用：表示较弱使用语义；虚线开放箭头：客户端 → 供应者。
    • 聚合 Aggregation：共享整—部分语义的关联；弱拥有，整体不负责部分生命周期，部分可独立存在、可被多整体共享。作用：可分离包含；实线空心菱在整体端。
    • 组合 Composition：组合整—部分语义的关联；整体负责部分存在与存储，部分生命周期与整体绑定。作用：强拥有与构成；实线实心菱在整体端。
    • 详解 → 速查/UML-体系化学习指南.md · §2.2.1
  • 别搞混：与同章相邻考点区分；题干锚词：面向对象技术。

定义

  • 面向对象技术：是以对象为基本单元组织软件，通过类、封装、继承与多态表达问题域的分析、设计与实现方法。作用：用于提高软件的复用性、可维护性与对变化的适应能力。
  • 对象与类：对象是状态（属性）与行为（操作）的封装体；类是具有相同属性与操作的对象集合的抽象。作用：用于建立问题域概念与程序结构的直接映射。
  • 封装、继承、多态：是封装隐藏内部实现；继承表达一般—特殊关系并复用特征；多态使同一消息在不同对象上呈现不同行为。作用：用于降低耦合、支持扩展与替换。

步骤与流程

建立面向对象分析模型（案例高频步骤）

  1. 识别参与者与用例，建立用例模型。
  2. 细化用例事件流，识别分析类（边界/控制/实体 BCE）。
  3. 建立类图（概念类及关系）。
  4. 对关键场景绘制序列图/通信图。
  5. 对状态复杂对象补充状态机图；业务流程用活动图。
  6. 迭代精化并追踪到系统需求。

要点

由简入深完整指南：速查/UML-体系化学习指南.md（对齐 OMG UML 2.5.1；含五图读法、易混对比、案例填空套路）。下文仅作考前速记。

  • UML（答卷）：是用标准图形符号描述软件静态结构与动态行为的可视化建模语言（非编程语言、非过程）。作用：用于统一表达与沟通系统模型，支撑分析设计。
  • 结构图 / 行为图：结构图描述静态构成与连接，作用是说明系统由何组成、如何组织部署；行为图描述动态运作与交互，作用是说明系统如何响应与协作。
  • 关系（答卷·定义 / 作用）：
    • 关联 Association：表示分类器之间的结构关系，实例通过链接相连；可标角色名、多重性、导航性、可见性、限定符、约束与关联类；实线，单向导航用开放箭头指向目标端；聚合与组合是关联的两种特殊形式。作用：表达实例间结构连接及端点语义。
    • 依赖 Dependency：客户端元素依赖供应者元素，供应者变更可能影响客户端；非结构性、较弱，常用于使用、创建、调用、导入等。作用：表示较弱使用语义；虚线开放箭头：客户端 → 供应者。
    • 泛化 Generalization：一般与特殊分类器之间的 is-a；特殊端继承并可增加、覆盖或特化行为，支持子类型可替换父类型。作用：建立类型层次与多态；实线空心三角在一般分类器端。
    • 实现 Realization：实现元素兑现规约元素契约（典型：类实现接口）。作用：实现与规约对应；虚线空心三角在规约端。
    • 聚合 Aggregation：共享整—部分语义的关联；弱拥有，整体不负责部分生命周期，部分可独立存在、可被多整体共享。作用：可分离包含；实线空心菱在整体端。
    • 组合 Composition：组合整—部分语义的关联；整体负责部分存在与存储，部分生命周期与整体绑定。作用：强拥有与构成；实线实心菱在整体端。
    • 强度与选型：依赖弱于关联，关联弱于聚合，聚合弱于组合；泛化/实现不参与菱形强弱序；选型看生命周期是否从属整体与语义强弱。
    • 详解 → 速查/UML-体系化学习指南.md · §2.2.1
  • 必考五图（定义 / 作用速记）：
    • 用例图：描述参与者与用例。作用：界定功能范围与交互目标。
    • 类图：描述类及静态关系。作用：展示概念/设计结构。
    • 序列图：按时间描述消息交互。作用：说明场景中对象如何依次协作。核心元素：选择三大（对象、生命线、消息，2014 上）；案例四大（参与者、对象、生命线、消息，2026 上）。泳道属活动图。
    • 通信图（UML 1.x 称协作图）：按对象链接结构描述消息交互，消息旁标序号。作用：说明谁与谁相连、链路上交换了哪些消息；与序列图语义等价、视角不同（时间 vs 链接）。
    • 状态机图：描述单对象状态迁移。作用：说明事件如何改变对象状态。
    • 活动图：描述流程分支与并行。作用：说明业务如何推进与分工。
    • 详解 → 速查/UML-体系化学习指南.md · §2.3 / §3（通信图见 §3.3b）
  • 必考优先级：用例 → 类 → 序列 / 通信（协作）→ 状态 → 活动 → 组件/部署。
  • 分析类三角色 BCE（答卷完整句）：
    • 边界类：是系统与参与者（或其他外部系统、设备）之间的交互接口类。作用：用于接收外部输入、返回结果并适配交互，隔离系统内外。
    • 控制类：是协调完成某一用例（或其中控制流程）的编排类。作用：用于按规定顺序调用相关对象、处理分支，实现用例流程；不长期保存业务数据。
    • 实体类：是问题域中具有持久业务意义的信息及其规则的载体类。作用：用于表达并保存业务状态与约束，供控制类读写。
    • 采用 BCE 的作用：按职责分离界面交互、流程编排与业务数据，避免职责混杂。
    • 详解 → 速查/结构化与面向对象分析-体系化学习路径.md · §4.4（定义/作用须可直接答卷，见该文 §0.1）
  • 易混：include（必含，基→被含）vs extend（可选，扩展→基）；状态图（单对象生命周期）vs 活动图（流程/并行）；序列图（时间轴）vs 通信图/协作图（对象链接+序号）；聚合 vs 组合（生命周期）；泛化 vs 实现（实线/虚线）；边界类 vs 参与者（内 vs 外）。
