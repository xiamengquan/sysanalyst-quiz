概述

微服务概述与特征：微服务（答卷·定义）：微服务是将大型应用拆分为多个小型、自治、可独立部署的服务，每个服务围绕特定业务能力，通过 HTTP/REST、gRPC 或消息等轻量通信协作的架构风格。

速懂

  • 一句话：微服务：微服务是将大型应用拆分为多个小型、自治、可独立部署的服务，每个服务围绕特定业务能力，通过 HTTP/REST、gRPC 或消息等轻量通信协作的架构风格。作用：主要用于应对单体应用在扩展性、部署频率与技术异构方面的瓶颈，使各服务可独立演化、弹性伸缩并按域隔离故障。
  • 考什么：微服务治理、熔断限流、最终一致（教程第 20 章）。
  • 具体理解：
    • 与 SOA 关系：微服务是 SOA 的细粒度实现；强调去 ESB 中心化、去共享 DB、智能端点+简单消息。作用：用于题干场景下的概念识别、对比选型与案例/论文回扣。
    • 单一职责原则（答卷）：单一职责原则是指每个微服务只围绕一项明确的业务能力构建；用于控制服务边界，避免「大而全」服务带来的耦合与发布风险。
    • 隔离性原则（答卷）：隔离性原则是指各服务以独立进程运行并拥有自己的数据存储，常用容器封装；用于故障隔离，防止单服务异常拖垮整个系统。
    • 自治性原则（答卷）：自治性原则是指每个服务拥有独立的生命周期，可独立开发、测试、部署与演化；用于提升团队并行效率与发布频率。

  • 自治性原则（答卷）：自治性原则是指每个服务拥有独立的生命周期，可独立开发、测试、部署与演化；用于提升团队并行效率与发布频率。
  • 弹性原则（答卷）：弹性原则是指系统具备自动扩缩容与故障转移能力；用于应对流量波动，保障高可用。
  • 可观察性原则（答卷）：可观察性原则是指通过日志、指标与分布式链路追踪等手段掌握系统运行状态；用于快速定位分布式环境下的故障与性能瓶颈。
  • 可测试性原则（答卷）：可测试性原则是指各服务须支持单元测试、集成测试与契约测试，并纳入 CI/CD 流水线；用于在频繁独立发布下仍保障质量。
  • 可维护性原则（答卷）：可维护性原则是指服务对外暴露标准 API（如 REST/OpenAPI）并实施版本控制；用于降低服务间协作成本，支持平滑升级。

第20章 微服务系统分析与设计

一、场景特征

定义：将大型应用拆分为小型、自治、独立部署的服务，每个服务围绕特定业务能力，通过轻量通信（HTTP/REST、gRPC、消息）协作。

典型场景：电商、金融、流媒体（Netflix）、大型互联网后台

核心特征：

  1. 服务粒度小、职责单一
  2. 独立部署与演化
  3. 松耦合
  4. 分布式部署（跨数据中心）
  5. 技术异构（Java/Python/Go 混用）
  6. 弹性伸缩
  7. 独立演化和部署

与 SOA 关系：微服务是 SOA 的细粒度实现；强调去 ESB 中心化、去共享 DB、智能端点+简单消息

微服务 vs SOA vs 单体（答卷·易混）

对比维度 单体（Monolithic） SOA 微服务
定义 全部功能集中于单一部署单元 以独立服务为单位、通过标准接口实现跨系统集成的架构思想 SOA 的细粒度实现，强调小服务、独立 DB、去中心化集成
服务粒度 无服务边界，模块级 较粗，常按企业级业务域 较细，常按单一业务能力
集成方式 进程内调用 常经 ESB 集中路由与编排 智能端点 + 简单消息，API 网关/消息队列，去 ESB 中心化
数据存储 通常共享同一数据库 可能共享 DB 或通过 ESB 转换 每服务独立数据库，跨服务用 API 或异步消息
适用场景 简单、低流量、小团队 异构遗留系统集成、企业级复用 高并发、复杂业务、需独立扩展与频繁发布
主要代价 扩展难、小改全量部署 ESB 成为瓶颈与单点 运维复杂、分布式一致性难保障

2.2 六种架构模式（案例对比高频）

模式 机制 优点 注意
聚合器 收集多服务数据聚合返回 减延迟、减依赖、提高可靠 聚合器成为瓶颈
代理 网关转发+治理（LB/熔断/限流） 解耦客户端与后端 不做数据聚合
链式 请求顺序经过多服务 流程清晰 客户端阻塞等待
分支 链式扩展，条件分支 灵活业务路径 复杂度上升
数据共享 共享 DB 或数据代理(Kafka) 数据一致 并发与一致性风险
异步消息 消息队列+EDA 高吞吐、松耦合 最终一致性

三、开发与测试要点

3.1 测试特点

  • 服务多、依赖链长
  • 需契约测试（Consumer-Driven Contract）
  • 需测试替身（Mock/Stub）与测试容器
  • 分布式环境搭建复杂

3.2 测试过程与类型

过程：单元（单服务）→ 集成（服务间）→ 端到端 → 性能 → 容错 → 安全

类型 要点
功能 API 正确性、业务规则
性能 单服务与链路延迟、吞吐
容错 熔断、降级、故障注入
安全 认证授权、传输加密、漏洞扫描
