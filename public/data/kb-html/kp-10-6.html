质量属性

大纲：12.6 · 教程：第12章 · 分组：科目1 · 10. 软件架构设计 · 状态：结构式重写 v2.0 · 审计通过

概述

质量属性 属本科目大纲考点。常考：质量属性与场景 · 架构评估。

速懂

  • 一句话：质量属性（架构）是可观察、可测量的系统非功能特征（性能、可用性、安全等）。
  • 考什么：质量属性场景六要素、ATAM 评估步骤（教程第 12 章）。
  • 别搞混：题干锚词：质量属性。

定义

  • 质量属性（架构）：是可观察、可测量的系统非功能特征（性能、可用性、安全等）。作用：用于架构权衡与 ATAM 评估。
  • 质量属性场景：是用刺激源、刺激、环境、制品、响应、响应度量六要素描述非功能需求的情境。作用：用于把性能/可用性等需求写成可验证场景。
  • ATAM（架构权衡分析法）：是通过质量属性场景、敏感点与权衡点评估架构方案的方法。作用：用于案例写架构选型理由与风险权衡。
  • 可用性：是系统在规定时间内可正常使用的程度。作用：用于冗余、故障转移与 SLA 设计。
  • 性能：是响应时间、吞吐量、资源利用率等指标的集合。作用：用于容量规划与瓶颈分析。
  • 安全性：是抵御未授权访问与破坏的能力。作用：用于威胁建模与安全架构决策。

步骤与流程

质量属性场景（六要素，填空/案例）

  1. 刺激源 → 2. 刺激 → 3. 环境 → 4. 制品 → 5. 响应 → 6. 响应度量（须有可测指标，如 99.9%、200ms）。

SAAM（简单评估，偏可修改性/性能）

  1. 确定场景与评估目的 → 2. 收集架构描述 → 3. 确定场景实现方式 → 4. 分析场景交互 → 5. 汇总敏感点与权衡。

ATAM（四阶段，案例/论文常用）

  1. 场景与需求收集（业务驱动场景）
  2. 架构视图分析（4+1 或逻辑/部署）
  3. 属性模型构造（识别敏感点、权衡点、风险点）
  4. 折中与决策（记录架构决策与残余风险）

与案例答题衔接

先写 1～2 个质量属性场景 → 说明架构风格/战术如何满足 响应度量 → 可选点出 ATAM 权衡（性能 vs 安全等）。

要点

架构概述

定义：构件 + 连接件 + 集成模式及约束；指定组织结构与拓扑，显示需求与构件对应关系。

架构九大意义（常考）：

  1. 干系人交流手段
  2. 早期设计决策体现
  3. 明确实现约束
  4. 决定开发维护组织结构
  5. 制约质量属性
  6. 使推理和控制更改更简单（局部/非局部/架构级变更）
  7. 支持渐进原型
  8. 培训基础
  9. 可传递可复用模型

架构发展史四阶段：无架构 → 萌芽（DFD/控制流图）→ 初级（UML）→ 高级（4+1）。
