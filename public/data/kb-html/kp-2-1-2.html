嵌入式概述（特点、组成、多核、安全攸关）

大纲：17.1 · 教程：第17章 · 分组：科目2 · 2. 嵌入式系统分析与设计 · 状态：结构式重写 v2.0 · 审计通过

概述

嵌入式概述（特点、组成、多核、安全攸关）：定义：以应用为中心、软硬件可配置可裁剪的专用计算机系统，强调功能、可靠性、成本、体积、功耗约束。

速懂

  • 一句话：分区调度（如 ARINC 653）：调度单元是分区；分区无优先级；固定周期重复执行。
  • 考什么：嵌入式实时、调度与资源约束（教程第 17 章）。
  • 别搞混：题干锚词：嵌入式概述。

定义

  • 分区调度（如 ARINC 653）：调度单元是分区；分区无优先级；固定周期重复执行。作用：用于时间与空间隔离，保障关键任务资源。
  • 案例答题模板：实时性指标 → 调度算法选择（RMS/EDF）→ 优先级反转及对策 → EOS/DB 选型 → 低功耗策略 → 测试覆盖与 V&V。
  • 设计验证：测试评估设计是否符合要求。作用：用于确认实现与需求一致、支撑 V&V。

步骤与流程

流程要点

  1. 专用性强：软硬件紧密结合，生命周期长
  2. 实时性强：限时间内响应；分硬实时/软实时
  3. 软硬件依赖强：协同设计
  4. 专用处理器：低功耗、高集成（SoC）
  5. 多技术融合：计算机+半导体+电子+机械
  6. 系统透明性：用户常感知不到嵌入式存在
  7. 资源受限：存储、I/O、处理能力有限
  8. 明确实时性指标
  9. 可调度性分析
  10. 确定任务优先级

要点

一、场景特征

定义：以应用为中心、软硬件可配置可裁剪的专用计算机系统，强调功能、可靠性、成本、体积、功耗约束。

典型领域：航空航天、汽车电子、工业自动化、智能家居、医疗监护、金融终端、通信设备。

七大特点： 3. 软硬件依赖强：协同设计

五核心部件：传感器 → 输入接口 → 处理单元(PE) → 输出接口 → 作动器

软件分层：硬件层 → HAL/BSP → 系统软件层（RTOS、GUI、嵌入式 DB）→ 应用层

多核处理器结构（选型考点）：单核、多处理器、超线程(SMT)、多核、共享 Cache 多核、超线程多核

安全攸关系统：Safety = 单位时间损失期望值 < 规定概率；TMR（三模冗余）增强可靠性

二、架构原则与模式

嵌入式数据库

分类：内存型、文件型、关系型、对象型、同步型

移动环境特点：设备移动、网络断接、条件多样、通信不对称

典型组成：嵌入式 DB + 同步服务器 + DB 服务器 + 连接网络（如「小金灵」移动 DBMS）

嵌入式操作系统（EOS）

类型：硬实时 RTOS vs 软实时

EOS 特征：代码质量高、实时性强、可裁剪可配置

抽象层：系统结构抽象、处理器变种抽象、平台抽象

内核类型：单内核、微内核、混合内核

实时性指标：任务切换时间、中断处理时间、系统响应时间

多任务调度（案例计算/对比高频）

分类维度：

维度 类型
时限 软时限 / 硬时限
周期 周期性 / 非周期性
抢占 可抢占 / 非抢占
优先级 静态（设计时固定）/ 动态
处理器 单处理器 / 多处理器
时机 在线 / 离线

RMS（速率单调调度）假设：

  • 任务均周期性
  • 无共享资源、无同步
  • 抢占式，最高优先级就绪任务执行
  • 时限 = 下一周期开始
  • 定常执行时间
  • 同等关键性

优先级反转：低优先级任务占资源执行，高优先级任务等待 → 解法：优先级继承/天花板协议

分区调度（如 ARINC 653）：调度单元是分区；分区无优先级；固定周期重复执行

开发与协同设计

开发平台三要素：

  • 宿主机/目标机交叉开发工具（以太网、USB、串口、ICE/JTAG）
  • 目标机可裁剪 RTOS
  • 多种通信方式

设计方法：改进结构化、面向对象、基于构件、基于模型(MBD)

软硬件协同设计流程：

  1. 明确实时性指标
  2. 可调度性分析
  3. 确定任务优先级

EOS 选型：功能、工具、可移植性、内存、附加包、实时性、灵活性

低功耗设计：

  • 硬件：低功耗处理器、总线、接口驱动、分区分时供电
  • 软件：编译优化、软硬件协同、算法优化

三、开发与测试要点

验证与确认（V&V）

  • 设计确认：确认产品满足用户需求

软件测试

常见问题：测试滞后于编码、理解不足漏测、文档差、缺自动化、修一处引新错

语句覆盖：每条语句至少执行一次

未覆盖代码处理：

  • 有需求无用例 → 增用例
  • 无需求 → 增需求+用例
  • 死代码 → 问题报告

基于系统的构件测试：集成级验证，关注接口与实时约束

功能安全（如 ISO 26262）：ASIL 等级、FTTI、失效模式、确认前提条件
