定义

  • 微服务架构：是将应用拆分为可独立部署、围绕业务能力组织的小服务。作用：用于云原生、弹性伸缩与团队自治。

  • 容器编排：是Kubernetes 等负责调度、伸缩与自愈。作用：用于 DevOps 与 5.3 开发运维一体化。

  • 「说明从单体迁移微服务的理由与拆分原则」→ 写单体痛点 + 单一职责/隔离性/有界上下文等原则答卷句。

  • 「跨服务下单如何保证一致性？」→ Saga + 最终一致性，说明补偿机制；避免简单写 2PC。
  • 「如何保障微服务可观测与容错？」→ 日志/指标/链路追踪 + 熔断/限流/降级。
  • 背景：电商/金融后台单体瓶颈（发布慢、扩展难、技术栈锁定）。
  • 方案：按业务能力拆分 + 容器编排 + API 网关 + 注册发现 + 消息队列；一致性写 Saga。
  • 成效：独立发布频率、故障隔离、弹性伸缩、团队并行度等可量化指标。
