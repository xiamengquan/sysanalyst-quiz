## 定义

- **REST**：是一种 Web 架构风格，用 URI 标识资源、HTTP 标准方法表达操作语义、服务器无状态。**作用**：用于构建可缓存、易横向扩展的 Web API（2016/2018 案例高频）。
- **SOAP / RPC 风格**：是基于 XML 信封的过程或对象调用，可承载 WS-Security 等规范。**作用**：用于企业级集成与强规范安全场景，与 REST 对比选型。
- **HTTP 方法与幂等**：是GET 用于查询（安全、幂等）；POST 用于创建（通常不幂等）；PUT 全量更新、DELETE 删除（幂等）。**作用**：用于接口设计与 REST 约束题。
- **架构约束**：是含客户端-服务器、无状态、可缓存、统一接口、分层系统等 REST 约束。**作用**：用于辨析 REST 与 RPC/SOAP 的差异。

## 要点

**架构约束（选择高频）**：客户端-服务器、**无状态**、可缓存、**统一接口**（URI + 动词）、分层系统、按需代码（可选）。

**HTTP 方法**：GET 查（安全、幂等）；POST 建（通常不幂等）；PUT 全量更、DELETE 删（幂等）。

**URI 惯例**：名词复数集合 `/surveys`；实例 `/surveys/{id}`；编辑/视图可建模为子资源或查询参数。

**REST vs SOAP**：REST 用 URI 标识资源、HTTP 动词与无状态；SOAP 偏 XML 信封、RPC 与企业 WS-Security。案例常考 REST 选型理由（2016 上）与资源抽象（2018 上）。
