**看完这一集你能做到**：根据场景选出架构风格，并写清**构件、连接件和代价**。

**本讲核心结论**：**选风格，就是选构件和连接件**——只报一个风格名，一分也拿不到。因为教材对风格的定义就是这么下的：**一个词汇表加一组约束**——词汇表里写的是构件和连接件，约束写的是它们怎么组合。

**对比两种答法**：

- ❌ 常见答法：「本系统采用分层架构比较合适。」——没有依据。
- ✅ 能拿分的答法：「**构件**是层，**连接件**是层间协议，**代价**是性能与灵活性。」

**本讲四件事**：

1. 风格到底是什么——先把定义钉死
2. 六类风格逐个过一遍
3. 每种风格要付出什么代价（选型题的第二问）
4. 四句模板写完一问

## 一、风格的定义与价值（01:45）

> **体系结构风格**是描述某一特定应用领域中、系统组织方式的**惯用模式**。它定义一个**系统家族**：**一个词汇表（包含一些构件和连接件类型）＋ 一组约束（指出系统如何把这些构件和连接件组合起来）**。

这正是答题时要写的两句话：词汇表那句回答**构件和连接件是什么**；约束那句回答**它们怎么组合**。

**为什么要有风格**：教材说得很直接——体系结构风格的研究和实践**促进对设计的重用**，一些经过实践证实的解决方案可以可靠地用于解决新的问题。

教材的例子：如果某人把系统描述为「客户机/服务器模式」，那么不必给出设计细节，我们立刻就会明白系统是如何组织和工作的。这就是风格的价值——**说一个名字，对方就懂了**。

## 二、教材把风格分成六类（02:50）

| 类别 | 包含的风格 |
| --- | --- |
| 1. 数据流风格 | 批处理、管道与过滤器 |
| 2. 调用与返回风格 | 主程序与子程序、面向对象、层次型、客户机/服务器 |
| 3. 以数据为中心的风格（仓库风格） | 仓库风格、黑板风格 |
| 4. 虚拟机风格 | 解释器、规则系统 |
| 5. 独立构件风格 | 进程通信、事件系统 |
| 6. 面向服务的风格 | 服务、服务总线、松散耦合的标准接口 |

这六类就是教材第十二章第三节的完整目录，**考试超不出这个范围**。

### 1. 数据流风格（03:37）

- **批处理**：每个处理步骤是一个单独的程序，每一步都要在前一步完成之后才能开始，数据以**整体**的方式在步骤之间传递。
- **管道与过滤器**：每个处理步骤由一个**过滤器**实现，步骤之间的数据传输由**管道**负责。
  - 答题必写：「**构件是过滤器，连接件是管道**」——不能只写「用管道过滤器比较好」。
- **题干信号**：出现「顺序处理、数据转换、每一步的输出是下一步的输入」，基本就是这一类。
- 教材加分原话：数据流体系结构**没有概念上的程序计数器**，指令的可执行性和执行**由指令输入参数的可用性来确定**。

### 2. 调用与返回风格（04:36）——最庞大的一类，四种

- **主程序与子程序**：一般采用**单线程控制**，把问题划分为若干处理步骤；构件是主程序和子程序，**过程调用**充当连接件。
- **面向对象**：建立在数据抽象和面向对象的基础上，数据的表示方法和相应操作封装在抽象数据类型或对象中；**构件是对象**。
- **层次型**：每一层为上层提供服务并作为下层的客户；**连接件由决定层间如何交互的协议来定义**。
  - 最常考，教材两个优点**一定要背**：①每一层**最多只影响两层**；②只要给相邻层提供相同的接口，**允许每层用不同的方法实现**——这两条直接支撑**软件重用**。
  - 答层次架构题时别只说「分层清晰」，要说清**构件是层，连接件是层间交互的协议**。
- **客户机/服务器**：基于**资源不对等**、且为实现**共享**而提出来的，是「胖客户机/瘦服务器」架构。

### 3. 以数据为中心的风格——仓库风格（05:49）

- **仓库**是存储和维护数据的**中心场所**，有两种不同的构件：**中央数据结构**＋**一组对中央数据进行操作的独立构件**。
- **黑板风格**：适用于解决复杂的**非结构化问题**，能在求解过程中综合运用**多种不同的知识源**。
- 教材原话（可直接引用）：黑板风格的传统应用是**信号处理领域**，比如**语音识别和模式识别**。

### 4. 虚拟机风格（06:53）

- **共同思想**：人为构建一个运行环境，在这环境之上可以**解析与运行自定义的语言**，以此增加架构的灵活性。
- **解释器**：含有一个虚拟机，可以仿真硬件的执行过程和一些关键应用；**缺点是执行效率较低**。
- **规则系统**（典型例子是**专家系统**）：包括**规则集、规则解释器、规则/数据选择器、工作内存**四部分。

### 5. 独立构件风格（06:53）

- **核心**：系统中的每个构件都是**相对独立的个体**，它们之间**不直接通信**，以**降低耦合度、提升灵活性**。
- **进程通信**：构件是独立的过程，连接件是**消息传递**；传递方式可以是点到点、异步或同步方式，以及**远程过程调用**。
- **事件系统**：构件不直接调用一个过程，而是**触发或广播一个或多个事件**；系统中其他构件中的过程在事件中**注册**，事件被触发时系统自动调用。
  - 最关键的一句（教材原话）：**事件的触发者并不知道哪些构件会被这些事件影响**。

### 6. 面向服务的架构风格（07:39）

教材给了三个定义来源，其中最常被引用的一条：面向服务架构是一种**客户机/服务器架构**的软件设计方法，着重强调**构件的松散耦合**并使用**独立的标准接口**。

- 所有功能都定义成**独立的服务**，服务之间通过**交互和协调**完成业务的整体逻辑。
- 所有服务通过**服务总线或流程管理器**来连接。

## 三、六类风格一张表答完（08:10）

三列：**风格 → 构件与连接件 → 要付出的代价**。第三列才是拉开差距的地方——**只答优点不答代价，这一问通常只能拿一半分**。

| 风格 | 构件 / 连接件 | 代价（缺点） |
| --- | --- | --- |
| 管道与过滤器 | 过滤器 / 管道 | 不适合交互式应用；各步骤的**数据格式必须统一** |
| 层次型 | 层 / 层间协议 | 层数多了**性能下降**；跨层调用会**破坏约束** |
| 仓库与黑板 | 中央数据结构＋独立构件 / 独立构件对中央数据的操作 | 中央数据结构成为**瓶颈与单点** |
| 事件系统 | 独立构件 / 事件广播与注册 | **不能假定构件的处理顺序**，甚至不知道哪些过程会被调用 |
| 面向服务 | 服务 / 服务总线 | 服务**划分与治理成本**高；接口一旦设计错了很难改 |

> 说明：代价一列是 UP 主依据教材对各类风格缺点的描述整理的**建议性归纳**，答题时请落回教材的原话更稳妥。

## 四、选型判定：五问定风格（09:08）

考场上怎么快速定位？按顺序问五个问题：

1. **数据是整批走，还是逐步转换？**——整批走是**批处理**；逐步转换、每步输出接下一步输入是**管道与过滤器**。
2. **是不是要分层、要共享资源？**——要分层可控是**层次型**；资源不对等、为共享而建是**客户机/服务器**。
3. **是不是围绕一份共享数据转？**——是**仓库风格**；如果还要综合多种知识源求解非结构化问题，那就是**黑板**。
4. **要不要解析自定义的语言或规则？**——要就是**虚拟机风格**（解释器或规则系统），代价是执行效率。
5. **构件之间要不要解耦？**——靠消息传递是**进程通信**；靠广播事件是**事件系统**；跨系统集成是**面向服务**。

## 五、仿真题走一遍（10:02）

> 说明：按教材考点自造的仿真题，非真题，用于演示答题路径。

**场景**：某公司要建一套数据处理平台——每天夜里把当天的交易数据做清洗、汇总，生成报表；同时要求在业务高峰期能对异常交易实施告警。

1. **第一问：批量处理部分适合采用哪种架构风格？说明理由。**——先答风格名，再答构件与连接件，最后说为什么适合。
2. **第二问：实施告警部分与批量部分，是否需要不同的风格？**——需要。两处需求不同，风格也可以不同：夜里那一段是**顺序的批处理**；高峰期的告警要**及时响应**，硬套一种就说不通了。
3. **第三问：采用该风格会带来什么问题？**——这就是问**代价**，照那张表的第三列展开。

## 六、答题模板：四句写完一问（11:01）

把第一问抽象成模板，四句写完：

1. **第一句给结论**：「批量处理部分采用**管道与过滤器**风格」——先把风格名说出来。
2. **第二句给结构**：「**构件**是过滤器，**连接件**是传输数据流的管道。」
3. **第三句给理由**：「清洗、汇总、报表正好表示成顺序的三步，每步的输出接下一步的输入，与场景正好匹配。」
4. **第四句给代价**：「不适合交互式应用；各步骤的数据格式必须统一。」

**注意事项**：

- 四句写完，一条一分，**分条编号写**，别写成一大段。
- **第二句和第三句是绝大多数人漏掉的两句。**

## 七、五个常见失分（11:42）

1. **只报风格名，不写构件与连接件**——本专题第一号丢分点，加一句就能补回来。
2. **理由写成通用的好话**：「扩展性好」谁都能写；要写**题干里的具体场景为什么匹配**。
3. **漏掉代价这一问**：题目问「带来什么问题」，整问都在这儿，漏了就是整问丢。
4. **风格名记混、自造术语**：只用教材里的名字——自己编的名字，阅卷人找不到对应。
5. **混合需求只给一种风格**：题目里出现两种处理特征，就要**分开说**。

## 八、一页纸带走（12:25）

| 内容 | 速记 |
| --- | --- |
| **一个定义** | 风格 = 一个**词汇表**＋一组**约束**，定义一个系统家族 |
| **六类风格** | 数据流、调用与返回、以数据为中心、虚拟机、独立构件、面向服务 |
| **五问定风格** | 整批还是逐步？分层还是共享？是否围绕数据？要不要解析？要不要解耦？ |
| **四句模板** | 选什么、**构件与连接件**、为什么、**代价是什么** |

架构风格讲的是**系统怎么组织**；下一集往下沉一层，讲**数据怎么组织**——数据库设计的五个阶段、实体联系图的三要素，以及范式到底怎么判（教材第五章）。还是同一套结构：教材抓手 → 错误清单 → 仿真题 → 答题模板。
