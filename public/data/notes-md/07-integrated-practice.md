**看完这一集你能做到**：把综合题的每一问**认领**到需求、建模、架构或数据的模板上，并排好时间顺序。

**本讲核心判断**：综合题**不是四道题拼在一起，而是一条主线走四步**——出题人给一个业务场景，然后沿着**需求 → 建模 → 架构 → 数据**这条线一步一步往下问。真正难的地方往往不是某一块你不会，而是**你没看出来这一问到底在考哪一块**——认领错了考点，写得再满也拿不到分。这是综合题最典型的失分方式。

教材主线：**第十一章**讲需求，**第十一章第五节**讲建模，**第十二章**讲架构，**第五章**讲数据。

**本讲四件事**（最值钱的是第二件——审题走对了，后面三件都是顺水推舟）：

1. 综合题长什么样：一段背景、三到四问、每一问考一章
2. 审题三步：圈动词、认领考点、判断题型
3. 四个专题的抓手怎么复用
4. 时间怎么分配、答题顺序怎么排

## 一、综合题的结构（02:09）

题干由两部分组成：

1. **业务背景**：交代系统是干什么的、规模多大、现在遇到了什么问题。**这部分不是废话**，它是后面每一问的共同前提。
2. **三到四问**：每一问各自指向一个专题，而且**彼此之间有前后依赖**。

典型的分工：

| 问 | 落点 | 常见形式 |
| --- | --- | --- |
| 第一问 | **需求** | 补图、补项，或指出需求过程里漏了什么 |
| 第二问 | **建模** | 补参与者与用例，或判定类之间的关系 |
| 第三问 | **架构** | 选风格、说质量属性，或判断要不要拆 |
| 第四问 | **数据** | 判范式给分解，或说明设计阶段该做什么 |

**要盯住的一条线索**：问与问之间有依赖——**前面那一问补出来的实体，往往就是后面那一问要用到的对象**。答题时别各答各的，要把这条线接住。

## 二、审题三步（03:17）——本集最值钱的部分

### 第一步：先圈出动词（03:17）

**动词决定这一问要你交出什么东西**：

| 动词 | 要你交什么 | 打法 |
| --- | --- | --- |
| **指出** | 找出对象：参与者、实体、依赖、遗漏项 | **列清单**，一条一条写清楚 |
| **说明** | 解释概念或给出理由 | **给定义，再加一句为什么**是这样 |
| **设计** | 给出产出物：图表、关系模式 | **给结构，再加说明** |
| **判断并给出** | 两步：先判定，再给结果 | **判定和结果两步都要写**，缺一步就扣一步的分（如「判范式并给拆法」） |

为什么先圈动词？因为把「说明」当成「指出」来答，写得再多也不对路——这是一眼就能避开的坑。

### 第二步：认领考点（04:11）

四个专题各有自己的**关键词**，看到关键词就能定位：

| 专题 | 关键词 | 教材位置 |
| --- | --- | --- |
| **需求** | 需求获取、数据字典、数据流图、需求变更、需求跟踪 | 第十一章 |
| **建模** | 参与者、用例、包含与扩展、类与关系 | 第十一章第五节 |
| **架构** | 架构风格、质量属性、选型拆分 | 第十二章（另有第十六、二十章支撑） |
| **数据** | 实体联系图、候选键、范式分解、反规范化 | 第五章 |

**认领不了时的笨办法**：看题目问的是「怎么组织**数据**」还是「怎么组织**系统**」——前者归**数据**，后者归**架构**，这一句能救回不少分。

### 第三步：判断题型（05:07）

套对应的模板——综合题里每一问都属于四种题型之一：

| 题型 | 模板 |
| --- | --- |
| **概念说明题** | 给定义＋一句它解决什么问题，两句话就够，不要铺开 |
| **分析补全题** | 补出对象＋说明补它的理由——「补什么」和「为什么」一起写 |
| **设计产出题** | 先给结构＋说明关键元素，结构要能看出层次 |
| **判定题** | 先定基准 → 再指出问题 → 最后给结果 |

**认领题型比认领章节更快**：你甚至可以先不定它在哪一章，只要看清它是**判定**还是**补全**，就已经知道该写什么形态了。

## 三、需求这一块的教材抓手（05:53）

教材第十一章按「**获取 → 分析 → 定义 → 验证 → 管理**」五段展开：

| 阶段 | 要点 |
| --- | --- |
| **获取** | 常用方法：**用户访谈、问卷调查、采样、情节串联板、联合需求计划（JRP）**，并配合需求记录技术 |
| **分析** | 把用户的要求分析、整理、确认后形成描述；主要方法：**结构化分析**与**面向对象分析** |
| **定义** | 形成**需求规格说明书**的过程；通常有**严格定义**与**原型方法**两条路 |
| **验证与变更** | 验证靠**需求评审与需求测试**；变更要**受控**；**需求跟踪**负责建立联系文档 |

**答题要领**：不需要背全五段，只需要**找出题目缺的那一段**，把它点出来，再补一句「为什么缺了它会有问题」。

## 四、时间怎么分，顺序怎么排（06:56）

看着是技巧，实际是分数。

1. **第一步：先扫全卷**——案例是五道题里选做三道，**第一题必答**，其余四道选两道。先把最有把握的那两道定下来，**不要边答边选**。
2. **第二步：按问给时间**——每道大题控制在 **20～25 分钟**；某一问写不完就先放下回头补，远比卡在那里强。
3. **第三步：留尾巴检查**——最后留 5 分钟，检查每一问是不是都给了**结论、依据和结果**这三样。

**实用顺序**：先答必答题（稳住基本盘）→ 再答最有把握的选做题 → 最后啃最硬的那道。

> 补充说明：案例科目的总时长是按「综合知识与案例连考共 **240 分钟**」来折算的，你实际能用多久取决于综合知识那一场用了多久——考场上的时间感要自己练出来。

## 五、四专题速查对照表（07:58）

建议考前抄一遍，进考场前看一眼，认领考点的速度会明显变快：

| 专题 | 教材位置 | 常见问法 | 模板 |
| --- | --- | --- | --- |
| **需求** | 第十一章 | 补数据流图、补数据字典 | 补对象＋理由 |
| **建模** | 第十一章第五节 | 补参与者与用例、判定关系 | 判定＋理由 |
| **架构** | 第十二、十六、二十章 | 选风格、说质量属性、判断要不要拆 | 定性＋选型＋代价 |
| **数据** | 第五章 | 判范式、给分解 | 定性＋依赖＋拆法 |

### 判定清单：一问答到什么程度算到位（08:48）

四样齐全，这一问才算答完：

1. **有结论**——先把判断说清楚（属于第几范式、选哪种架构），别让阅卷者猜你的立场；
2. **有依据**——说清依据来自哪条规则，而不是凭印象，**教材那句话就是你最好的依据**；
3. **有结果**——给出可执行的产物：拆法、图的结构、补出来的清单；
4. **有分寸**——该说代价的就说代价，该说限制的就说限制，别把话说满。

> 缺结论显得含糊，缺依据显得无据，缺结果显得空泛，缺分寸显得不专业。

## 六、仿真题走一遍（09:36）

> 说明：按教材考点自造的仿真题，非真题，用于演示答题路径。

**场景**：某企业要建设一套设备巡检系统——业务人员提出的需求零散、而且反复变更；系统要支持巡检员上报、班长审核、管理员统计三类角色；随着接入设备增长，查询压力明显上升。

1. **第一问：需求过程里哪些环节被忽略了？请说明理由。**——这是**补全题**：沿着「获取、分析、定义、验证」这条链找缺口，每一段各说一句为什么。需求零散说明**获取阶段**没走完整的方法；反复变更说明**变更控制和需求跟踪**没有建立起来。
2. **第二问：请补充系统的参与者与核心用例，并说明用例之间的关系。**——这是**判定题**：先列参与者（巡检员、班长、管理员），再列核心用例（上报巡检结果、审核巡检单、统计巡检数据），最后判定关系——**如果一个用例必须调用另一个用「包含」，如果只是偶尔发生用「扩展」**。
3. **第三问：随着设备规模增长，架构上应如何调整？代价是什么？**——这是**选型题**：先给场景定性（规模增长、查询压力上升）→ 再落选型（从整体式走向分布式的微服务）→ 最后说清代价（部署与运维复杂性上升、多库之间要保证一致性、故障会沿调用链传播，并用**隔离、自治、弹性和可观察性**去应对）。

三问走下来，用的全是前面几集给过的模板。

## 七、答题模板四步（11:27）

把刚才的路径收成一个模板四步：

1. **第一步：认领**——看清这一问属于需求、建模、架构还是数据。**认领错了，后面全白写。**
2. **第二步：回忆**——调出这一专题的教材抓手：定义、规则、步骤，写依据的时候就用它。
3. **第三步：落模板**——按题型选模板：补全、判定、设计还是说明，**模板决定产出形态**。
4. **第四步：收口检查**——对照判定清单过一遍：结论、依据、结果、分寸，缺一样补一样，再进下一问。

这四步每一步都只有一句话要做。练熟之后综合题会变得很**机械**——而机械正是考场上最可靠的状态。

## 八、五个常见失分（12:16）

1. **认领错考点**：把架构题当数据题答，写得再满也不对路。
2. **只写结论不给依据**：判定题缺了依据，说服力就没有了。
3. **跨问的依赖没接住**：前一问补出来的实体，后面那一问要用上——别各答各的。
4. **时间卡在一道硬题上**：后面会答的题没时间写，是最亏的失分。
5. **分条编号没做**：一大段文字里，采分点会被阅卷者漏看——分条编号这件事**成本极低、收益极高**。
