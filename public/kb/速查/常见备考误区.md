# 速查 · 常见备考误区

> 每个误区配**辨析要点**与**案例/选择回链**；v0.9.57 起覆盖设计层次，v0.9.63 补案例/论文**扣题**类失分点。

| 误区 | 辨析要点 | 回链 |
|------|---------|------|
| **可行性研究 vs 需求分析** | 可行性回答「建不建、选哪方案、投不投」→ 可行性研究报告；需求分析回答「系统逻辑上做什么」→ SRS/模型。**不要把 SRS 功能列表写进可行性章。** | `kp-8-7` |
| **概要设计 vs 详细设计** | 概要：模块**之间**结构与接口（**结构图/SC**）；详细：模块**内部**算法、数据结构、**流程/伪代码**。**伪代码属于详细设计，不是系统分析。** | `kp-11-1` · `kp-software-lifecycle` |
| **系统分析 vs 系统设计** | 系统分析产出逻辑模型（DFD、数据字典）；设计产出物理/实现方案。分析阶段不写实现级伪代码。 | `kp-8-6` · `kp-system-planning-analysis` |
| **用例 vs 功能** | 用例 = 参与者为达成目标与系统的交互；功能 = 系统提供的能力清单。勿把按钮级操作直接当用例。 | `kp-9-3` · `kp-requirements-engineering` |
| **模块四要素** | **输入、输出、处理逻辑、内部数据**（针对单模块）——勿与 **SC 图模块间调用**、勿与 **实现类/表** 混为一谈。 | `kp-11-1` |
| **固定成本 vs 可变成本** | 盈亏平衡题：固定不随产量变（折旧、租金）；可变随产量变（原材料、按量云资源）。混用会导致盈亏平衡点算错。 | `kp-8-8` |
| **答案与题干脱节** | 案例/论文只写「加强沟通、完善文档」等**通用管理原则**，不引用题干中的**系统名、约束、指标、角色** → 难拿过程分。 | [案例分析答题教程](../案例分析答题教程.md) |
| **只写结论不写依据** | 如「应加强需求管理」却未写**依据哪条原则、谁执行、做什么动作、如何验收** → 按点给分时会丢分。 | [需求侧论文框架](./需求侧论文写作框架.md) |

### 辨析示例（一句话）

- **可行性 vs 需求**：可行性写「三年 ROI 18%」；需求写「订单状态机 7 态及转换条件」。  
- **概要 vs 详细**：概要「模块 A 调用 B 的接口」；详细「A 内排序算法步骤」。  
- **模块四要素**：写清**本模块** I/O 与内部数据；SC 图只画**模块间**关系。  
- **扣题**：案例写措施时带题干词，如「**大促峰值 5000 TPS** 下采用 **Redis 集群 + 网关限流**」。

## 案例/论文自检

1. **层次**：立项 / 逻辑需求 / 概要结构 / 详细实现 — 我答的是哪一层？  
2. **扣题**：每问至少 **2 个题干关键词**？  
3. **依据**：结论后是否有 **因为题干××**？
