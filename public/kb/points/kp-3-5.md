# 分布式数据库（概述、分片）

> **大纲**：5.5 · **教程**：第5章 · **分组**：科目1 · 3. 数据库系统基础知识 · **状态**：工坊精修 v1.2.9 · 审计通过

## 概述

**分布式数据库（概述、分片）**：- 分片：水平(行)、垂直(列)；完备性、重构性、不相交性（见下「分片正确性」）。 - 复制：提高可用性和性能。 - 透明性：分片、位置、局部、重复、事务。

## 定义

- 数据均衡性原则（答卷·定义）
- **作用 / 答卷展开**：用于避免出现热点节点（某节点数据量或访问量过大导致瓶颈）与空闲节点（资源浪费），保证整体吞吐与响应稳定。
- 业务相关性原则（答卷·定义）
- **作用 / 答卷展开**：用于使高频关联查询、跨表访问尽量落在同一分片内完成，减少跨分片查询与聚合，从而降低延迟（如实时排队 ≤1 秒类约束）。
- 可扩展性原则（答卷·定义）
- **作用 / 答卷展开**：用于在分厅增多、历史记录累积等情况下扩容，且扩展过程尽量无需大规模重构数据或长时间中断服务。
- **数据均衡性原则**：数据均衡性原则是指分片后各节点的数据量与访问压力应尽可能均匀。  
**作用 / 答卷展开**：用于避免出现热点节点（某节点数据量或访问量过大导致瓶颈）与空闲节点（资源浪费），保证整体吞吐与响应稳定。
- **业务相关性原则**：业务相关性原则是指分片键与分片边界应紧贴核心业务场景与高频访问路径来设计。  
**作用 / 答卷展开**：用于使高频关联查询、跨表访问尽量落在同一分片内完成，减少跨分片查询与聚合，从而降低延迟（如实时排队 ≤1 秒类约束）。
- **可扩展性原则**：可扩展性原则是指分片方案应支持业务增长时通过新增节点实现横向扩展。  
**作用 / 答卷展开**：用于在分厅增多、历史记录累积等情况下扩容，且扩展过程尽量无需大规模重构数据或长时间中断服务。

## 要点

### 分布式数据库

- **分片**：水平(行)、垂直(列)；完备性、重构性、不相交性（见下「分片正确性」）。
- **复制**：提高可用性和性能。
- **透明性**：分片、位置、局部、重复、事务。

### 分布式数据库分片设计的核心原则（答卷·必背）

> 案例常问「说明分片设计的核心原则（至少 2 个）」——优先答下面三条**设计原则**；勿与「完备性 / 重构性 / 不相交性」混淆（后者是分片结果正确性准则）。

| 原则（答卷写全名） | 一句话抓手 |
|-------------------|------------|
| 数据均衡性原则 | 量与压均匀，防热点/空闲 |
| 业务相关性原则 | 键贴业务与主查询，少跨片 |
| 可扩展性原则 | 能加节点横向扩，少重构少停机 |

**分片正确性准则（易混·教程原文，非上述三条的替身）**

| 准则 | 含义 |
|------|------|
| **完备性** | 全局关系的每个数据项必属于某个分片 |
| **重构性** | 各分片可重构回原全局关系 |
| **不相交性** | 水平分片时各片数据一般不重叠（复制策略除外） |

## 应试

**案例可能怎么问**：给定业务表与函数依赖，要求判断范式级别并分解至 3NF/BCNF；或给出并发/死锁场景，选隔离级别与加锁策略；备份恢复题常考「完全+增量/差异」组合与 RPO 对应关系；**分布式库案例**常考「分片设计核心原则（至少 2 个）」——答**数据均衡性、业务相关性、可扩展性**并稍作展开；再问分片键选型，回扣「跨厅/跨站点共享」与「长期持久化/审计保存」。

**论文怎么用**：数据迁移/多源集成类（23上、24上）可写「源库→中间层→目标库」割接步骤、一致性校验与回滚；OLTP/OLAP 分离、读写分离、缓存与索引优化可作为性能段落素材；多网点政务/连锁类可写分片键与故障隔离。

**常考结论**

- 授权粒度：**库→表→行→列**（4级，由大到小）。
- 审计=**事后**；标识鉴别=**事前**。
- ACID：**原一隔持**。
- 范式递进：**1→2→3→BCNF→4NF**。
- 备份口诀：**物逻分，冷热全增异**。
- 增量备份基于"上次任意备份"，差异备份基于"上次完全备份"（易混！）。
- 分片**设计**原则口诀：**均衡、相关、可扩展**（写全名：数据均衡性 / 业务相关性 / 可扩展性）。
- 分片**正确性**准则：**完备、重构、不相交**（勿与上条混答）。
