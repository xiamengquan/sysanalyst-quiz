## 定义

- **需求基线**：评审批准后的需求约定，是开发与管理的桥梁。**作用**：用于题干场景下的概念识别、对比选型与案例/论文回扣。
- **软件需求**：软件需求是用户（及干系人）对新系统在功能、行为、性能、设计约束等方面的期望与约定。**作用**：用于指导后续分析、设计、实现、测试与验收，并作为变更与跟踪的基准。
- **需求获取**：需求获取是通过调查、交流与观测等手段，从干系人处收集并初步整理业务目标、用户任务与约束条件，形成原始需求素材的过程。**作用**：用于把隐含的业务与用户期望显性化，为后续需求分析、建模与规格说明提供输入。
- **需求广度**：需求广度是一次获取活动所能覆盖的干系人范围、业务领域或需求条目面的宽窄程度。**作用**：用于衡量「能覆盖多少人/多少面」——面越宽，越利于发现共性问题与统计分布，但单点深入往往不足。
- **需求深度**：需求深度是对某一角色、任务或业务规则所能挖掘到的细节、动机与异常场景的充分程度。**作用**：用于衡量「挖得够不够细」——深度高利于澄清复杂流程与例外，但覆盖面通常较窄、成本较高。
- **信息集成度**：信息集成度是多方信息能否在同一场合被对照、冲突被当场暴露并初步收敛为一致认识的程度。**作用**：用于衡量「信息是否拼得拢」——集成度高利于消解矛盾、形成共识；集成度低则信息分散，需事后综合。
- **用户参与度**：用户参与度是最终用户（或业务代表）在获取过程中直接投入时间、表达意见并影响结论的程度。**作用**：用于衡量「用户是否真的进来了」——参与度高利于验收对齐与减少误解；参与度低则易出现「文档有、现场不对」。
- **业务需求**：业务需求是组织或投资方希望通过系统建设达成的高层业务目标、收益与项目范围描述。**作用**：用于界定「为什么做、做到什么程度、不做什么」，为项目立项、范围控制与优先级提供依据。
- **用户需求**：用户需求是最终用户（或角色）为完成其工作任务而对系统提出的目标、任务与交互期望。**作用**：用于说明「谁要用系统做什么」，是连接业务目标与系统规格的桥梁，常以用例、场景、用户故事表达。
- **系统需求**：系统需求是为实现业务与用户需求，对系统必须具备的功能、非功能属性及设计约束所作的、可验证的规格说明。**作用**：用于作为开发、测试与验收的直接依据，把「用户要做什么」落实为「系统必须怎样表现」。
- **用户访谈**：用户访谈是分析人员与干系人进行一对一（或小范围）交流，通过结构化/非结构化提问收集需求的技术。**作用**：用于深入了解特定角色的目标、任务与痛点，澄清模糊表述。
- **联合需求计划 JRP / 联合应用设计 JAD**：JRP/JAD 是在引导人主持下，于短时间内召集关键干系人共同研讨需求（或设计）并当场达成一致的工作坊式获取技术。**作用**：用于快速收敛多方观点、暴露并处理冲突，缩短需求确认周期。
- **问卷调查**：问卷调查是向较大范围对象发放统一题项并回收统计结果，以批量收集需求或态度的技术。**作用**：用于在短时间内扩大样本面、获取可量化的共性倾向。
- **文档分析**：文档分析是通过研读现有制度、报表、接口说明、遗留系统文档等，提取业务规则与数据需求的技术。**作用**：用于低成本复用已有知识、发现书面规则与现状差距。

## 步骤与流程

### 需求工程流程（教程第 11 章）

**两大工作**：**需求开发** + **需求管理**（管理贯穿全生命周期）。

**需求开发四阶段**：
1. **需求获取**——通过交流、观察、分析任务等捕获与修订需求。
2. **需求分析**——对获取信息分类、建模、排优先级与冲突处理。
3. **需求定义（规格说明）**——形成用户需求说明与**软件需求规格说明（SRS）**。
4. **需求验证**——评审、走查、原型或仿真，确认完整、正确、一致、可测试、可行。

**需求工程五活动**（选择/流程题常考）：获取 → 分析 → 规格 → **确认与验证** → **管理**。

**需求管理**：评审批准后建立**需求基线**；**变更控制**（影响分析、审批）；**需求跟踪**（需求—设计—实现—测试追溯矩阵）。

## 要点

### 2.5 需求工程

**两大工作**：需求开发 + 需求管理。

**需求开发四阶段**：
1. 需求获取
2. 需求分析
3. 需求定义（文档化）→ 用户原始需求说明书 + 软件需求规格说明
4. 需求验证

**需求管理**：需求基线、变更控制、**需求跟踪**。

**需求工程五活动**（含管理）：获取 → 分析 → 规格 → 确认验证 → 管理。

**需求基线**：评审批准后的需求约定，是开发与管理的桥梁。

## 应试

**案例可能怎么问**：给出干系人多、工期紧、说法冲突等约束，要求用四维比较访谈 / JRP(JAD) / 问卷 / 文档分析 / 观察（及**采样**、**情节串联板**若题干涉及大样本成本或界面流程确认），并说明应优先采用哪一种及理由。

**论文怎么用**：需求获取段落可写「先问卷（+采样）扩面 → 访谈/观察加深 → 情节串联板或原型对齐界面 → JAD 收敛冲突」，并回扣四维与题干约束。
