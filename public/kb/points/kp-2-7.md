# Web 服务（REST 架构风格）

> **大纲**：4.7 · **教程**：第4章 · **分组**：科目1 · 2. 计算机网络与分布式系统 · **状态**：手工精编 · 审计通过

## 概述

Web 服务考点集中在 **REST 与 SOAP/RPC 的差异**、HTTP 动词与 **无状态**、**幂等** 及资源 URI 设计；案例常考 REST 选型理由（2016 上）与资源抽象（2018 上在线调查）。

## 定义

**REST（Representational State Transfer，表述性状态转移）** 是一种 **Web 架构风格**（不是单一产品协议）：用 **URI 标识资源**，用 **HTTP 标准方法** 表达操作语义，服务器 **无状态**，每个请求应自包含完成操作所需信息。**用于**构建轻量、可缓存、易横向扩展的 Web API 与 SOA 集成。

**SOAP / RPC 风格** 则偏 **过程/对象调用 + 消息信封**，可支持有状态多步流程与企业级 WS-Security 规范。

## 要点

**架构约束（选择高频）**：客户端-服务器、**无状态**、可缓存、**统一接口**（URI + 动词）、分层系统、按需代码（可选）。

**HTTP 方法**：GET 查（安全、幂等）；POST 建（通常不幂等）；PUT 全量更、DELETE 删（幂等）。

**URI 惯例**：名词复数集合 `/surveys`；实例 `/surveys/{id}`；编辑/视图可建模为子资源或查询参数。

## 易混辨析

| 维度 | REST | SOAP / RPC |
|------|------|------------|
| 抽象 | 资源 + HTTP 动词 | 过程名 + 信封 |
| 状态 | 强调无状态 | 可有会话上下文 |
| 扩展 | HTTP 负载均衡、横向扩展易 | WS-Security 等规范成熟 |
| 安全 | HTTPS + OAuth/JWT 等应用层补 | 规范层能力更直接 |

**无状态 vs 统一接口**：无状态 = 服务端不记会话；统一接口 = URI 标识资源 + 标准 HTTP 动词。

## 应试

- 选择题：「不在请求之间保存客户端会话」→ **无状态**；URI + GET/POST/PUT/DELETE → **REST**。
- 2016 上案例：REST 映射 CRUD、利于 HTTP 负载均衡合理；缺开箱即用 WS-Security 需额外设计合理。
- 2018 上案例：问卷/问题/评论/统计拆 **资源** 与 URI。
- 相关练习：综合知识搜「REST」「REST无状态」「REST幂等」。
