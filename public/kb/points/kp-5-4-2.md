## 概述

**测试**：过程：单元（单服务）→ 集成（服务间）→ 端到端 → 性能 → 容错 → 安全。

## 定义

- **自治性原则（答卷）**：自治性原则是指每个服务拥有独立的生命周期，可独立开发、测试、部署与演化；**用于**提升团队并行效率与发布频率。
- **可测试性原则（答卷）**：可测试性原则是指各服务须支持单元测试、集成测试与契约测试，并纳入 CI/CD 流水线；**用于**在频繁独立发布下仍保障质量。
- 契约测试（答卷·定义）：契约测试（Consumer-Driven Contract）是由消费方定义期望的 API 契约、由提供方验证是否满足的测试方式；用于在微服务独立发布时保障接口兼容性，减少集成阶段才发现的接口不匹配。

## 要点

### 3.2 测试过程与类型

**过程**：单元（单服务）→ 集成（服务间）→ 端到端 → 性能 → 容错 → 安全

| 类型 | 要点 |
|------|------|
| 功能 | API 正确性、业务规则 |
| 性能 | 单服务与链路延迟、吞吐 |
| 容错 | 熔断、降级、故障注入 |
| 安全 | 认证授权、传输加密、漏洞扫描 |
