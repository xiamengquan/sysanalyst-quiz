## 一、场景特征

**定义**：高效、综合的数据处理平台，处理和分析**海量、多样、高速**数据。

**大数据特征（常考）**：Volume、Velocity、Variety、Veracity（不同教材表述略有差异，考试以教程为准）

**数据类型**：
- 结构化：关系数据库
- 半结构化：JSON、XML、日志
- 非结构化：图片、视频、文本、语音

**处理方式**：
- ****：有界数据，HDFS + MapReduce + Hive
- ****：无界数据，Flume/Kafka + Storm/Spark Streaming + HBase/Redis
- **混合架构**：Lambda（批+流）/ Kappa / 数据湖

## 二、架构原则与模式

### 2.1 架构原则

| 原则 | 内容 |
|------|------|
| 分布式环境 | 水平扩展 |
| 模块化设计 | 组件可替换 |
| 安全性 | 加密、访问控制、备份、审计、持续监控 |
| 性能 | 分区、分布式计算、并行、内存计算 |
| 可靠性 | 冗余、自动故障转移、负载均衡 |
| 可运维 | 监控预警、性能调优、故障排除、升级维护 |

### 2.2 架构类型与模式

**Lambda 架构三层**：
- 批处理层（Batch Layer）：全量历史视图
- 速度层（Speed/Stream Layer）：实时增量
- 服务层（Serving Layer）：查询合并结果

**数据湖模式组件**：通用数据模型、边缘 SDK、实时缓存、历史沉浸区、Dumper、Query Engine、模型反馈

**特点**：去 ETL 化、即时查询、边缘计算

### 2.3 存储选型

| 方式 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **行存储** | 写入完整、事务友好 | 读冗余、分析慢 | OLTP、MySQL |
| **列存储** | 批量列访问快、压缩比高 | 写入复杂、完整性弱 | OLAP、HBase |
| **文档** | 灵活 schema | — | MongoDB |
| **搜索** | 全文/复杂检索 | — | Elasticsearch |

**HBase**：列族，平衡 OLTP/OLAP，水平扩展

## 三、开发与测试要点

### 3.1 数据生命周期

**存储** → **管理** → **处理** → **分析** → **部署**

**数据管理四块**：
1. **元数据管理**：技术元数据 + 业务元数据（数据源、ETL 规则、仓库、报表、接口、商业、日志）
2. **数据关系图谱**：血缘（归属性、多源性、可追溯性、层次性）+ 关联分析
3. **数据安全**：认证 + 授权（Kerberos、RBAC、Sentry/Ranger）；产生→存储→使用→传输→展示→销毁全链路；S1—S4 表安全等级
4. **资源监控**：机房网络、组件存活、Metrics、Runtime 探活、集群指标、任务状态、趋势预测

**数据处理**：
- 实时：数据不断到来、不能积压、TB/PB 级、结果快速展现
- 离线：数据量巨大、批量复杂运算、数据预先到位不变、方便查询结果
- 图计算：顶点/边、路径搜索、中心性、社群发现（GraphX/Spark）

**数据分析**：
- 机器学习：监督/非监督/强化学习
- 搜索推荐：ElasticSearch、Solr
- 可视化：Tableau、Datawrapper

**ETL/数据转换六步**：发现 → 映射 → 提取 → 代码生成 → 执行 → 审查

**数据清洗**：缺失值、异常值、重复记录、标准化、干净数据回流

### 3.2 系统部署

**隔离原则**：生产/测试、集群、在线/离线、应用、数据

**部署检查**：集群规划、网络、安全、时间同步、SSH

**变更管理**：版本控制、内容一致、变更跟踪、版本对应、快速回滚、历史记录

### 3.3 测试特点与过程

**特点**：数据量大、类型多样、实时+批处理、高性能可扩展、逻辑复杂

**过程**：测试需求分析 → 计划方案 → 用例设计 → 执行 → 报告

| 测试类型 | 要点 |
|----------|------|
| 功能 | 查询过滤、分区分片、聚合统计、排序分组、多表关联、清洗转换 |
| 性能 | 存储容量、扩展性、吞吐、延迟 |
| 可靠性/容错 | 节点故障、数据副本、故障转移 |
| 安全 | 认证授权、加密、审计 |
| 兼容性 | 多组件、多版本、多数据源 |
