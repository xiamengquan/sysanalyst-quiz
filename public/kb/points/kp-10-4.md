# 架构标准

> **大纲**：12.4 · **教程**：第12章 · **分组**：科目1 · 10. 软件架构设计 · **状态**：工坊精修 v1.2.8 · 审计通过

## 概述

**架构标准**：二层 C/S 缺点：开发成本高、客户端复杂、界面不一、移植难、维护升级难、扩展性差、安全性难保证。

## 定义

- C/S、B/S、三层架构（答卷·必背）：
- **面向对象**：对象 + 方法调用
- **层次结构**：层间调用，上层依赖下层
- **C/S**：资源不对等、共享；二层或三层
- **B/S**：三层 C/S 的实现，浏览器客户端

## 要点

### 返回风格

| 风格 | 特点 |
|-----|------|
| **主程序/子程序** | 单线程控制 |
| **面向对象** | 对象 + 方法调用 |
| **层次结构** | 层间调用，上层依赖下层 |
| **C/S** | 资源不对等、共享；二层或三层 |
| **B/S** | 三层 C/S 的实现，浏览器客户端 |

| 架构 | 定义（是……） | 作用 / 适用（用于……） |
|-----|-------------|---------------------|
| **C/S 架构** | C/S 架构是客户端与服务器资源不对等、通过网络共享数据的调用/返回式架构，常见二层或三层划分。 | 适用于需丰富客户端交互、局部高性能处理的场景；主要作用是集中管理核心数据与业务逻辑。 |
| **B/S 架构** | B/S 架构是以浏览器为客户端的三层 C/S 实现，表示层由 Web 浏览器承担。 | 适用于广域网部署、免客户端安装与易维护升级的场景；主要作用是降低客户端部署与维护成本。 |
| **三层架构** | 三层架构是将系统划分为表示层、功能（业务逻辑）层与数据层的 C/S 组织方式。 | 适用于需逻辑独立、并行开发与跨平台选型的中大型系统；主要作用是隔离界面、业务与数据，提升可维护性与可扩展性。 |

**二层 C/S 缺点**：开发成本高、客户端复杂、界面不一、移植难、维护升级难、扩展性差、安全性难保证。

**三层 C/S 优点**：
- 逻辑相对独立
- 灵活选平台
- 并行开发、多语言
- 功能层隔离表示与数据

**B/S 不足**：动态页面支持弱、安全性较 C/S 低、交互性不强。
