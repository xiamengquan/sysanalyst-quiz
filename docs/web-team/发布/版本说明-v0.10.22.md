## 背景

用户在 `/recall` 连续上报两起判定违和：

1. **UML 关系强弱卡**（fc-k-uml-xx）：答「组合强于聚合强于关联强于依赖，泛化与实现基于契约，不参与排序」被判 2/4 部分命中。复现：失分点①「不参与此序」vs「不参与排序」——纯字面差一个「此」字，语义全等；②「实现属类型契约」vs「实现基于契约」——漏「类型」二字，属合理失分。
2. **RUP 卡**（fc-k-t05-02）：答「初始、细化、构建、移动」被判 1/4。复现：卡面问「RUP 四阶段？」但卡背是「初细构移 + 三特点（用例驱动/架构中心/迭代增量）」，4 个关键点中 3 个是三特点——问咖范围错位；口诀「初细构移」经 acronym 匹配命中（用户答的四个词首字恰好覆盖），故 1/4。另：用户写「移动」系术语错误（正确为「移交」Transition），该失分应保留。

## 变更清单

### 判定纠偏（answer-match.ts）

- `normalizeAnswer` 新增等义改写：「此序」→「排序」（语义全等，不应字面失分）。
- RecallApp：判定「正确」时也显示命中数——全中显示「关键点全命中」，过线未全中显示「（关键点 x/y）· 达标通过，缺失词见下方 ✗」，便于对照补全。
- 回归验证（judgeAnswer 直测）：用户原案 → correct 3/4（缺失词只剩「实现属类型契约」）；卡面原文 → 4/4；顺序写反 → partial 2/4（seq 顺序敏感点保底，不放水）；无关卡（需求管理）→ 4/4 无副作用。

### 卡面纠偏（build-flashcards 源数据）

- 记忆卡组 T05 #24：「RUP 四阶段：初细构移 + 三特点（…）」→「RUP 四阶段与三特点：初始→细化→构建→移交（初细构移）；用例驱动、架构中心、迭代增量」——卡面自动变为「RUP 四阶段与三特点？」，问咖与卡背一致；卡背补四阶段全名。单行改写，卡 id 不变（fc-k-t05-02 等），进度不受影响。
- 总册 D1 必会卡 3（fc-m-d1-003）：「四阶段「初细构移」＋三特点「…」」→ 补全名「（初始→细化→构建→移交）」。
- 「移动 ≠ 移交」保留判失分：术语错误不迁就，✗ chip 显示卡面原话「初始→细化→构建→移交」帮助纠错。
