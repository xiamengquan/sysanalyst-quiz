# 版本说明 v0.10.3

- **版本号**：0.10.2 → 0.10.3
- **日期**：2026-10-11
- **类型**：缺陷修复（缓存策略）
- **背景**：用户反馈 v0.10.2 的 CMMI 口诀勘误在线上站点仍显示旧内容（`/kb/quick-four-tier-7d/#d1`）。排查确认：服务端数据（`/data/kb-html/quick-four-tier-7d.html`、`/data/kb-md/...md`）均已为新内容（last-modified 09:50），但客户端仍显示旧版。

## 根因

`src/lib/kb-fetch.ts` 的正文拉取使用 `fetch(url, { cache: "force-cache" })`：

- force-cache 语义 = **只要本地有缓存副本就直接使用，即使已过期也不回源验证**
- 服务端虽有 `cache-control: public,max-age=0,must-revalidate` + etag，但请求侧 force-cache 优先级更高，普通刷新（F5）仍命中陈旧副本
- 只有硬刷新（Ctrl+Shift+R）才绕开——对用户表现为「部署后内容永远不更新」

## 修复

- `force-cache` → **`no-cache`**：本地缓存必须回源验证；服务端按 etag 协商，内容未变 304 秒回（零成本），内容更新即拿最新
- 影响面：知识点阅读页、抽屉预览（KbPreviewDrawer）、刷题/案例的知识点关联面板——均走 `fetchKbBody` 单点，一处修复全局生效
- release-notes 原本已用 `no-store`（更新弹窗不受影响）
