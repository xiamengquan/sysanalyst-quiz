# 版本说明 v0.10.12（2026-10-11）

## 主题

修复知识点正文内「中文路径站内链接」点击报「未找到知识点」的问题，并按「路由树」方案重构全部 KB 引用解析。

## 用户上报与根因

- **现象**：在《考前 14 天冲刺计划》等页面点击「UML 指南」链接，提示「未找到知识点」；链接被原样渲染为 `<a href="./UML-…%E4%BD%93….md">`。
- **根因**：`renderKbMarkdown` 中 marked 解析阶段会把 `<a href>` 里的非 ASCII 字符百分号编码（`体系化` → `%E4%BD%93%E7%B3%BB…`），后续 `linkifyMarkdownFileAnchors` 未先 `decodeURIComponent` 就拿编码串去 kb-index 查表 → 精确 path / 文件名 / 标题全部匹配失败 → 原始 markdown 链接原样输出 → 点击 404。
- **影响面**：全站所有含中文路径的 `[](*.md)` 站内链接（共 19 处），不止 UML 指南。

## 修复与重构

1. **KB 路由树**（`src/lib/kb-resolve.ts`）
   - 新增 `buildKbRouteTree` / `getKbRouteTree`：按 items 数组引用缓存（WeakMap）建树，索引 byId / byPath / byFile / byPathStem / byTitle。
   - `resolveKbRef`、`findKbItemByRouteId` 统一走树查询；入口统一 `decodeKbRefQuery`（剥书名号壳 + 递归 percent-decode，最多 3 层）。
   - 查找优先级保持不变：id → 精确 path → 文件名（唯一 / endsWith 消歧）→ 文件 stem / 标题包含 → 书名省略「速查 ·」前缀。
2. **链接改写解码**（`src/lib/kb-md.ts`）
   - `linkifyMarkdownFileAnchors` 对 `<a href>` 先 `decodeURIComponent`（容错）再判定 `isKbMarkdownHref` 与相对路径解析。
