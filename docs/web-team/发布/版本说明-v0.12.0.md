## 变更要点

### A4 · 追溯矩阵发版门禁（内容断链 CI 拦截）

- **问题（G1）**：考点 ↔ 题 ↔ 卡 ↔ 案例此前只有单向映射，断链内容（如卡组缺日、锚点缺域）要等用户刷到才暴露。
- **修复**：新增 `scripts/check-traceability.mjs`，挂入 `check:release` / `check:release:strict`，每个考点配置项四向可追溯：
  - **考点 → 题组**：点内题组非空（复核汇总，逐点细则由 `check-tracks` 把关）；
  - **考点 → 卡组**：课程日次（`course.day`）在 `flashcards.json` 有 ≥1 张卡，且含 ≥1 张 M 必会卡；
  - **考点 → 总册**：域 id 在重学锚点表有落点（脚本内 `KB_ANCHOR` 与 `src/lib/se-system.ts` 同步维护，已注明双向同步要求）；
  - **反向孤儿筛查**：`flashcards` 中 `day` 值必须落在 d1–d7 或 null，防「/recall/?day= 深链筛不到的孤儿卡」。
- **效果**：任何断链在发版阶段非零退出拦截，知识点与题、卡、速查永远对得上。

### A5 · 案例微卡自动生成（做题产出即记忆资产）

- **问题（G3 延伸）**：案例三部曲「做→批→卡」中「卡」依赖人工摘录，做题产出与记忆资产之间无自动通道。
- **修复**：`RecallApp` 载入时新增 `mergeCaseDraftCards()` 合成器：
  - 扫描 `/case` 作答草稿（`sysanalyst_case_v1`），有小问实质作答（≥8 字）即合成「案例微卡」；
  - 卡面 = `案例微卡 · 案例标题 第N问：题干摘要`，卡底 = 官方参考要点（`rubric.sample`，缺省退化为 `must_hit` 清单，均做轻量去 markdown）；
  - 卡 id 稳定（`CASE-<caseId>-<qnum>`），出处深链「回看原题」直达 `/case/?id=`；
  - **仅在确有草稿时才拉取 `cases.json`**（1.1 MB），无草稿零流量；复用既有莱特纳 1-2-4-7-15 排程，`day=null` 仅进「全部」池。
- **涉及文件**：`src/components/RecallApp.tsx`、`scripts/check-traceability.mjs`（新增）、`package.json`（门禁接线）。
