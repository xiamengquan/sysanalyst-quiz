# 版本说明 v0.10.10（2026-10-11）

> **主题**：修复随机问答自动比对的三类误判——列举切分、中文标点阻断、口诀展开答法；阈值微调。

## 用户上报

「UML 常考十图？（默写要点）」用户作答「静态五图：类图、对象图、包图、组件图、部署图。动态五图：用例图、活动图、状态机图、序列图、通信图。」（内容完全正确）被判「未通过（0/5）」。

## 根因（复现确认）

1. **`/` 不是切分符**：标准答案「静态五种（类/对象/包/组件〔旧称构件〕/部署）…」规范化后「类/对象/包/组件旧称构件/部署」整段成为**一个**关键点；用户按顿号列举的写法（类图、对象图…）以子串匹配永远无法命中 → 必然 0 命中。
2. **中文标点阻断**：匹配仅剔除 `/+=-`，用户答案里的冒号/顿号/句号留在串中，跨标点的子串不可达。
3. **修饰词计入关键点**：「静态五种/动态五种」用户写「五图」即 miss，且权重与实体词相同。

## 修复（`src/lib/answer-match.ts`）

- `TOKEN_SPLIT` 增加 `/` 与空白：列举式答案逐词成点；「类/对象/包/组件」→ 类、对象、包、组件四个关键点。
- 匹配前**双方**剔除分隔符与弱符号（`stripAll`）：标点差异不再阻断（「类型/契约」vs「类型契约」）。
- **口诀展开匹配**（`acronymHit`）：3–8 字纯中文口诀压缩串（初重定管优 / 业数过应测），当用户答案按分隔符切成 ≥3 词时，口诀逐字按序在词序列中定位（每词消耗一次，字可在词中任意位置——「定」落在「已定义」）即命中；旧口诀（初可已定优）在展开词序列中定位失败仍判 wrong。
- 「旧称…」括注剔除升级为 token 内部清洗（〔旧称构件〕黏连在 token 尾部时同样剔除）。
- 修饰性计数词 COUNT_RE 放宽（「静态五种」类前缀+数字+量词结构不计入关键点）。
- U+2212 数学负号归一为半角 `-`。
- 判定阈值：正确 ≥65%（原 75%）、部分 ≥45%——核心语义全中、仅漏括注细节（如「实线/虚线」）时不再卡在 partial。
