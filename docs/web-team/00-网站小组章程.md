# 题库网站小组章程

## 目的

负责系统分析师**本地/可部署题库站点**的产品、体验与界面、架构与实现、质量验收，将正式题库与（审计通过后的）知识点精炼接入可刷题、可导航的 Web 界面；**移动端体验与桌面同等优先**。

## 成员（7 名）

| 席位 | 代号 | 职责 | Skill（`.cursor/skills/`） |
|------|------|------|---------------------------|
| 产品 | 站点产品 | 用户场景、验收标准、Backlog 优先级建议、移动体验目标 | `sysanalyst-web-product` |
| 体验设计 | UX | 信息架构、用户路径、页面目标与空态、触控/安全区体验标准 | `sysanalyst-web-ux` |
| 界面设计 | UI | 视觉令牌、组件外观、主题与排版、可落地的视觉规范 | `sysanalyst-web-ui` |
| 架构设计 | 架构 | 模块边界、数据/同步链路、静态导出与依赖选型、技术债 | `sysanalyst-web-arch` |
| 功能实现 | 实现 | 页面与交互编码、sync 脚本落地、缺陷修复与适配 | `sysanalyst-web-impl` |
| 测试 | 质量验收 | 冒烟/回归清单、移动端窄视口验收、发版门禁签字 | `sysanalyst-web-qa` |
| 协调 | 站点经理 | 跨工坊对齐、发布检查、看板维护、冲突升级 | `sysanalyst-web-pm` |

协作顺序（常规）：

**产品定目标与验收 → 体验设计定路径/IA → 界面设计定视觉 → 架构设计定方案 → 功能实现编码 → 测试按清单验收 → 协调发版**。

体验与界面可并行初稿，但体验路径冻结前界面不锁终稿；架构方案评审通过前实现不铺开大改。

## 工作原则

1. **内容与实现分离**：不直接改知识点对错、不擅自出题；内容问题提工单给对应委员会  
2. **本地优先**：`npm run dev` 或静态导出即可运行；账号/云同步为可选增强  
3. **隐私**：默认 IndexedDB；云同步须用户显式开启  
4. **发布门禁**：正式知识点须有审计发布记录；**测试席位对移动清单签字**后方可标「可发版」  
5. **移动优先验收**：新 UI 须在 ≤390px 宽与底栏安全区下可完成主路径，不得仅桌面验收  
6. **设计双席 / 程序双席**：体验不替代界面视觉终稿；架构不替代功能编码与联调  
7. **变更必登日志（更新全记录）**：任何一点的更新（含 UI/交互微调、功能增强、知识点增补/修正、题库维护、架构重构、依赖变动），都必须被明确记录并写入更新日志（`public/data/release-notes.json` 与 `docs/web-team/发布/版本说明-*.md`），杜绝“静默更新”，确保用户端与站点迭代全链路透明可溯。  

## 现行重点

1. 维持刷题 / 案例 / 知识点 / 更新 / 关于一体体验  
2. 加强移动端顶栏密度、触控热区、搜索/抽屉与底栏避让（见看板 **B-5**）  
3. 产品、测试与拆分后的设计/程序席位常态化参与排期与发版
