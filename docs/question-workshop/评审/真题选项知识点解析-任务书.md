# 跨委员会任务书 · 综合知识真题「选项级知识点解答」

> 状态：进行中 · 2026-09-15  
> 发起：站点需求（刷题反馈需清楚说明**为何对 / 为何错**）  
> 联席：知识点编制委员会 + 出题工坊（出题者 / 提示信息官）

## 1. 目标

为 `content/banks/real/综合知识/all.jsonl` **每一道题的每一个选项**配备知识点口径解答：

| 选项角色 | 必须写清 |
|----------|----------|
| 正确项 | **为什么对**（定义/关系/适用条件，对齐 `content/kb/`） |
| 错误项 | **为什么错**（混淆点、适用边界，勿只写「不正确」） |

展示优先：刷题页揭示答案后，逐项列出 A–D 解析；并保留汇总字段 `exp` 供兼容。

## 2. 角色分工

| 席位 | 职责 |
|------|------|
| **编制乙**（考点） | 核对概念口径；易混对比（include/extend、ACID…） |
| **编制丙**（应试） | 补「答卷钩子」短句，控制篇幅可读 |
| **出题者** | 按场次起草 `opt_exp` / `exp`，不改题干选项答案 |
| **提示信息官** | 质检：简洁 · 合理 · 通俗（≥35 字汇总；禁空壳套话） |
| **审计乙**（抽查） | 抽检知识对错；重大误导 → 打回重写 |
| **网站程序** | 合并补丁、`npm run sync:data`、答题页展示 |

**禁止**：改 `ans` / 选项原文；臆造与精炼明显冲突的说法（不确定标「待核」）。

## 3. 数据字段

补丁 JSONL（每行一题），目录：`content/banks/real/综合知识/exp-patches/`

```json
{
  "id": "ZT-2014上-001-…",
  "opt_exp": {
    "A": "对：……",
    "B": "错：……",
    "C": "错：……",
    "D": "错：……"
  },
  "exp": "【正解】……【易错】B……；C……；D……"
}
```

- `opt_exp`：每项 **15–60 字**为宜；正确项以「对：」起句，错项以「错：」起句  
- `exp`：汇总 **35–120 字**，答对/答错两种场景都能读
