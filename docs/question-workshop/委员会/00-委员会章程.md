# 细则审计委员会章程

## 1. 设立目的

对《出题细则报告》进行**多视角独立审计**，避免单分析师偏见。  
**仅当三名分析师全员表决「通过」后，细则方可正式发布**，作为出题者与评审员的唯一生效依据。

## 2. 成员

| 席位 | 代号 | 视角 | Skill |
|------|------|------|-------|
| 分析师甲 | 结构与分级官 | 目录层级、§ 编号、科目/难度分层 | `sysanalyst-committee-a` |
| 分析师乙 | 规律与证据官 | 数据可复核、样本边界、合规 | `sysanalyst-committee-b` |
| 分析师丙 | 可执行与评审官 | checklist、机审可行性、规则无冲突 | `sysanalyst-committee-c` |
| 主席（编排） | 汇总发布 | 计票、改稿编排、正式落盘 | `sysanalyst-committee-chair` |

三人**平行审计同一稿件**，互不代写对方意见。

## 3. 表决规则

| 结论 | 含义 |
|------|------|
| **通过** | 无阻塞项，同意按当前结构正式发布（可附不阻塞建议） |
| **有条件通过** | 存在阻塞项，改完后可不必大翻；**计票视为未通过** |
| **驳回** | 结构或证据或可执行性不合格，需重大修订 |

**正式发布 ⇔ 甲∧乙∧丙 均为「通过」。**

## 4. 流水线（生效后）

```text
起草分析师 → 细则草稿
    → 委员会甲∥乙∥丙 并行审计
    → 主席汇总
         ├─ 未全员通过 → 修订任务单 → 改稿 → 再审
         └─ 全员通过 → 正式发布/
                → 出题者按正式细则调整题库
                → 评审员按正式细则审计题库
                → 不合规打回出题者重编
```

## 5. 目录

```text
委员会/
  00-委员会章程.md
  细则结构模板.md
  意见/          # 三人表决与修订任务单
  正式发布/      # 仅全员通过后写入
```

## 6. 与旧三角色关系

- 原「分析师」负责**起草**细则，不单独具备发布权  
- 「出题者」「评审员」**只认** `正式发布/` 下盖章版本（或 reports 中标注「正式发布」的同步稿）  
- 草稿阶段不得启动全库合规打回（可预审）
